# 第十二章 图形数据结构（Data Structures for Graphics）

> **来源**：《Fundamentals of Computer Graphics》第 4 版 · Ch.12 · PDF 第 296–336 页
> **定位**：图形学中反复出现的数据结构——它们解决曲面、空间和场景结构等底层问题。本章四大部分：三角网格存储、场景图、空间数据结构（BVH / 均匀网格 / BSP 树）、平铺多维数组。
> **关联**：依赖第 4 章（光线追踪求交）、第 6 章（变换矩阵）、第 8 章（光栅化 z-buffer）、第 2 章（隐式平面方程）

## 1. 三角网格（§12.1）

### 1.1 网格拓扑（§12.1.1）

三角网格不是无关三角形的集合，而是通过共享顶点和边连接成**连续曲面**的网络。这种共享是效率的关键。

**流形（Manifold）**——最严格的拓扑约束：

一个 2-流形是指：表面上任意点的小邻域都可以被平滑成一块平坦表面。用反例理解最清晰：

- **非流形边**：一条边连接了 3 个或更多三角形——邻域多出一块"鳍"，无法展平。流形要求每条边恰好被 2 个三角形共享。
- **非流形顶点**：一个顶点周围有两组不连通的三角形环——邻域像两块表面在中心粘合，无法展平。流形要求每个顶点周围只有单一、完整的三角形环。

**带边界的流形**——放宽条件，允许有边界（缺口）：

| 条件 | 流形 | 带边界的流形 |
|---|---|---|
| 每条边被几个三角形共享 | 恰好 2 个 | 1 个或 2 个 |
| 每个顶点周围 | 单一完整三角形环 | 单一边连通三角形集合 |

**定向（Orientation）**：单个三角形的正面由顶点排列顺序定义（逆时针为正面）。连通网格**一致定向**的条件是：每对相邻三角形中，共享顶点在两个三角形的顶点列表中以**相反顺序**出现。

> [!warning] 不可定向曲面
> 即使是合法流形，也可能无法一致定向——如莫比乌斯带。任何有非流形边的网格都无法一致定向。不过这在实践中很少出现。

### 1.2 索引网格存储（§12.1.2）

最直观但浪费的存储：每个三角形独立存 3 个顶点坐标：

```
Triangle {
    vector3 vertexPosition[3]    // 3 个顶点位置
}
```

3 个三角形共 4 个顶点 → 存了 9 个点（顶点 b 存 3 次，其余各 2 次）。

**共享顶点方案——索引网格**：顶点单独存一次，三角形通过索引引用顶点：

```
IndexedMesh {
    int    tInd[nt][3]    // 三角形的顶点索引
    vector3 verts[nv]     // 顶点位置数组
}
```

**存储量对比**（假设 float、pointer、int 等宽）：

| 方案 | 存储量 | 大网格（$n_t \approx 2n_v$） |
|---|---|---|
| 独立三角形 | $9n_t$ | $18n_v$ |
| 索引网格 | $3n_v + 3n_t$ | $9n_v$ |

大网格中每个顶点大约连接 6 个三角形（每个三角形 3 个顶点），故 $n_t \approx 2n_v$。共享顶点约**节省一半存储**，且加上顶点属性后优势更大。

### 1.3 三角网格的数据结构（§12.1.3–12.1.5）

索引网格适合**静态网格**的存储和传输，但不支持高效的邻接查询（"这个顶点的相邻三角形有哪些？"）。对于需要网格编辑、细分、简化等操作的应用，需要更丰富的连通性数据结构。

#### 1.3.1 三角形邻接结构（Triangle-Neighbor Structure）

在索引网格基础上增加两个数组：

```
Mesh {
    int tInd[nt][3]    // 每个三角形的 3 个顶点索引
    int tNbr[nt][3]    // 每个三角形的 3 个邻居三角形索引
    int vTri[nv]       // 每个顶点的任意一个相邻三角形索引
}
```

`tNbr[i][k]` 指向与三角形 $i$ 的第 $k$ 和第 $k+1$ 个顶点共享边的邻居三角形。从任意三角形出发，可以 $O(1)$ 跳到相邻三角形。

**遍历顶点 $v$ 的所有相邻三角形**：

```
TrianglesOfVertex(v) {
    t = vTri[v]
    do {
        find i such that (tInd[t][i] == v)    // 找到 v 在 t 中的位置
        t = tNbr[t][i]                          // 跳到顺时针下一个三角形
    } while (t != vTri[v])
}
```

问题：每次跳转后要在新三角形中**搜索**中心顶点的位置——虽然是 $O(1)$（顶点列表只有 3 个元素），但需要分支。

**改进——存储边引用而非三角形引用**：用 `Edge` 替代 `int`，包含三角形索引和边索引 $i$：

```
Edge { Triangle t; int i; }    // 三角形 t 的第 i 条边
```

不变量：`t.nbr[j].t.nbr[t.nbr[j].i].t == t`——从任何边出发走过去再走回来，回到原三角形。

改进后的遍历无需搜索：

```
TrianglesOfVertex(v) {
    {t, i} = v.e
    do {
        {t, i} = t.nbr[i]    // 跳到邻居
        i = (i + 1) mod 3     // 直接知道下一步走哪条边
    } while (t != v.e.t)
}
```

**存储量**：每顶点 4 个数值（3 坐标 + 1 边），每三角形 6 个数值（3 顶点索引 + 3 边），合计 $\approx 16n_v$（对比索引网格 $9n_v$）。

> [!note] 仅适用于流形网格
> 遍历依赖"回到起始三角形"来终止。边界顶点没有完整的三角形环，无法回到起点。推广到带边界流形需引入哨兵值（如 $-1$）标记边界。

#### 1.3.2 翼边结构（Winged-Edge Structure）

翼边结构把连通性信息存储在**边**上，使边成为数据结构的"一等公民"。

每条边存储：
- **两个顶点**：头顶点（head）和尾顶点（tail）
- **两个面**：左面（left）和右面（right）
- **四条邻接边**：左面的前驱/后继边（lprev/lnext）、右面的前驱/后继边（rprev/rnext）

每个顶点和面各自存储一个指向任意关联边的指针。

```
Edge {
    Edge lprev, lnext, rprev, rnext
    Vertex head, tail
    Face left, right
}
```

**遍历面 $f$ 的所有边**：

```
EdgesOfFace(f) {
    e = f.e
    do {
        if (e.left == f) e = e.lnext    // 沿左面前进
        else             e = e.rnext    // 沿右面前进
    } while (e != f.e)
}
```

**遍历顶点 $v$ 的所有边**：

```
EdgesOfVertex(v) {
    e = v.e
    do {
        if (e.tail == v) e = e.lprev    // 从尾出发走左前驱
        else             e = e.rprev    // 从头出发走右前驱
    } while (e != v.e)
}
```

翼边结构的关键不便：每次跳转前都要**检查边的朝向**（判断当前顶点是 head 还是 tail），类似三角形邻接结构基本版中的搜索问题。

> [!tip] 适用于任意多边形网格
> 翼边结构不限于三角形——可以处理任意多边形网格。这是基于边结构的重要优势。

**时间/空间权衡**：可以去掉前驱指针（lprev/rprev），需要时沿后继绕一圈回到原位。省空间但某些操作变慢。

#### 1.3.3 半边结构（Half-Edge Structure）

翼边结构的终极改进：不为每条边存储一套数据，而是为**每条半边**存储一套。

一条共享边被**拆成两个半边**，分属两个相邻三角形，朝向相反，各自与所属三角形朝向一致。

每个半边存储：
- **pair**（配对指针）：指向对面的半边
- **next**（后继指针）：指向同一面内的下一条半边
- **v**（顶点）：指向该半边的头顶点
- **f**（面）：指向该半边所属的面

```
HEdge {
    HEdge pair, next
    Vertex v
    Face f
}
```

**遍历面 $f$ 的所有半边**——无需检查朝向：

```
EdgesOfFace(f) {
    h = f.h
    do {
        h = h.next          // 直接走 next，无需判断
    } while (h != f.h)
}
```

**遍历顶点 $v$ 的所有半边**——也无需检查朝向：

```
EdgesOfVertex(v) {
    h = v.h
    do {
        h = h.pair.next     // 跳到对面半边再走 next
    } while (h != v.h)
}
```

> [!tip] 半边结构的优势
> 翼边结构在遍历时每次都要判断"从哪个方向进入"（检查 head/tail），半边结构完全消除了这种判断。代价是边的数量翻倍（每条边变两个半边），但实现更简洁。
>
> **省去 pair 指针**：在基于数组的实现中，可以排列数组使偶数编号边 $i$ 始终与奇数边 $i+1$ 配对——$O(1)$ 索引计算替代指针存储。

#### 三种网格数据结构对比

| | 三角形邻接结构 | 翼边结构 | 半边结构 |
|---|---|---|---|
| 连通性存储位置 | 面（三角形） | 边 | 半边 |
| 遍历时需检查朝向 | 改进版不需要 | 需要（head/tail） | **不需要** |
| 支持任意多边形 | 否（仅三角形） | 是 | 是 |
| 每边存储量 | 3 个边引用 | 4 个边引用 + 2 顶点 + 2 面 | 2 个引用 + 1 顶点 + 1 面 |
| 支持网格手术 | 是 | 是 | 是 |
| 流形要求 | 严格（需哨兵推广） | 无 | 无 |

## 2. 场景图（§12.2）

### 2.1 动机

复杂场景包含大量对象和变换。把每个对象独立放置很笨拙——例如一辆汽车有车身、4 个轮子、方向盘，轮子随车身移动并自转，方向盘随车身旋转。需要一种层次化的变换管理机制。

### 2.2 层次变换

场景图是一棵**有向无环图（DAG）**，节点是对象，边表示"父→子"的变换关系。每个节点存储自己的局部变换矩阵，子节点的世界变换 = 从根到该节点的路径上所有矩阵的**乘积**。

例如一个简化的太阳系：

```
根
├─ 太阳（自转）
├─ 地球轨道节点（绕太阳公转）
│   └─ 地球（自转）
│       └─ 月球轨道节点（绕地球公转）
│           └─ 月球（自转）
```

月球的世界变换 = 根 × 地球轨道公转 × 地球自转 × 月球轨道公转 × 月球自转。月球自动跟随地球，地球自动跟随太阳。

### 2.3 实现要点

```
SceneGraphNode {
    Matrix localTransform       // 相对父节点的局部变换
    Surface *object             // 该节点关联的几何体（可为 NULL）
    list<SceneGraphNode*> children
}

// 递归计算世界变换并绘制
function traverse(node, parentWorldMatrix):
    worldMatrix = parentWorldMatrix * node.localTransform
    if (node.object != NULL):
        node.object.draw(worldMatrix)
    for (child in node.children):
        traverse(child, worldMatrix)
```

**关键点**：
- 变换沿树向下累积，子节点自动继承父节点的变换
- 修改一个父节点的变换，所有后代自动更新——无需逐个调整
- 同一个网格可以被多个节点引用（实例化），用不同变换绘制多次
- 场景图是 DAG 而非树——一个节点可以有多个父节点（共享几何体），但不能有环

## 3. 空间数据结构（§12.3）

### 3.1 动机与分类

光线追踪中暴力遍历所有对象求交是 $O(N)$ 的。通过预处理建立空间数据结构，可以用"分治法"在**亚线性时间**内完成求交。

三大类：

| 类别 | 划分对象 | 空间重叠 | 例子 |
|---|---|---|---|
| 对象划分 | 对象分组到层次结构 | 兄弟节点的包围盒可能空间重叠 | BVH |
| 规则空间划分 | 空间分成均匀网格 | 每点属于唯一单元格 | 均匀空间细分 |
| 不规则空间划分 | 空间自适应递归划分 | 每点属于唯一区域 | BSP 树 |

**对象划分 vs 空间划分的本质区别**：
- 对象划分：每个对象属于**唯一**节点，但空间中一个点可能在多个节点的包围盒内
- 空间划分：空间中每个点属于**唯一**分区，但一个对象可能横跨多个分区

### 3.2 包围盒（§12.3.1）

所有加速结构的基础操作：**光线与轴对齐包围盒（AABB）的求交测试**。

#### 基本算法（2D，正向光线）

包围盒由 $x_{\min}, x_{\max}, y_{\min}, y_{\max}$ 定义。分别计算光线在 $x$ 和 $y$ 方向进入/离开平面的参数 $t$：

$$t_{x\min} = \frac{x_{\min} - x_e}{x_d},\quad t_{x\max} = \frac{x_{\max} - x_e}{x_d}$$

$$t_{y\min} = \frac{y_{\min} - y_e}{y_d},\quad t_{y\max} = \frac{y_{\max} - y_e}{y_d}$$

光线命中包围盒当且仅当两个 $t$ 区间 **重叠**（交集非空）：

```
if (txmin > tymax) or (tymin > txmax) then
    return false     // 两区间不重叠 → 未命中
else
    return true      // 重叠 → 命中
```

#### 处理负方向分量

若 $x_d < 0$，光线先命中 $x_{\max}$ 再命中 $x_{\min}$，需交换：

```
if (xd >= 0) then
    txmin = (xmin - xe) / xd
    txmax = (xmax - xe) / xd
else
    txmin = (xmax - xe) / xd
    txmax = (xmin - xe) / xd
```

#### 除以零问题

水平/垂直光线 $x_d=0$ 或 $y_d=0$ 导致除零。检查 IEEE 浮点数是否优雅处理：

- $x_e \le x_{\min}$（在盒子左侧，未命中）→ $t_{x\min} = t_{x\max} = +\infty$，区间 $(\infty, \infty)$ 不与任何区间重叠 → 正确
- $x_{\min} < x_e < x_{\max}$（在盒子内部，命中）→ $t_{x\min} = -\infty, t_{x\max} = +\infty$，区间 $(-\infty, \infty)$ 与所有区间重叠 → 正确
- $x_e \ge x_{\max}$（在盒子右侧，未命中）→ $t_{x\min} = t_{x\max} = -\infty$，不重叠 → 正确

IEEE 浮点约定自动处理了除零，无需特殊检查。

> [!warning] $-0$ 问题
> 当 $x_d = -0$ 时，`xd >= 0` 判断为真（因为 $-0 = +0$），但实际方向为负，导致进入/离开面搞反。解决方法：测试 $x_d$ 的**倒数** $a = 1/x_d$ 的符号——$-0$ 的倒数是 $-\infty$，符号正确反映为负方向。

#### 3D 推广

对 3D 包围盒，计算 $x, y, z$ 三个方向的 $t$ 区间 $[t_{\min}^{(i)}, t_{\max}^{(i)}]$，三个区间都有交集则命中。等价于：

$$\max(t_{x\min}, t_{y\min}, t_{z\min}) \le \min(t_{x\max}, t_{y\max}, t_{z\max})$$

### 3.3 层次包围盒 / BVH（§12.3.2）

#### 基本思想

在所有对象外放一个大包围盒。命中大盒的光线再递归检查子包围盒，未命中的直接跳过。层次化：把对象分成两组，各自加包围盒，形成树。

**关键性质**：一个节点的包围盒保证包含其所有子节点的对象，但**不保证**不包含其他节点的对象——兄弟节点的包围盒可能空间重叠。

#### 树节点结构

```
class bvh-node subclass of surface:
    surface-pointer left, right
    box bbox

    bool hit(ray, t0, t1, rec):
        if (bbox.hitbox(ray, t0, t1)):
            left-hit  = (left  != NULL) and (left.hit(ray, t0, t1, lrec))
            right-hit = (right != NULL) and (right.hit(ray, t0, t1, rrec))
            if (left-hit and right-hit):
                rec = (lrec.t < rrec.t) ? lrec : rrec    // 取更近的
                return true
            else if (left-hit):  rec = lrec; return true
            else if (right-hit): rec = rrec; return true
            else: return false
        else:
            return false
```

虚函数自动处理内部节点和叶节点的区别——叶节点直接对图元做求交，内部节点递归。

#### 构建策略

**方法一——按对象数量均分**：沿某个轴排序后对半切。

```
function create(A, axis):
    N = A.length
    if (N == 1): left = A[0]; right = NULL
    else if (N == 2): left = A[0]; right = A[1]
    else:
        sort A by object center along axis
        left  = new bvh-node(A[0..N/2-1], (axis+1) mod 3)
        right = new bvh-node(A[N/2..N-1], (axis+1) mod 3)
    bbox = combine(left.bbox, right.bbox)
```

轴的选择可以轮流轮换（$x\to y\to z\to x$），或每次选择使两个子树包围盒体积之和最小的轴。

**方法二——按空间均分**：找到包围盒沿当前轴的中点，按中点划分对象。

```
find midpoint m of bounding box of A along axis
partition A into lists surrounding m
```

虽然产生不平衡树，但便于遍历空空间，且构建更快（划分比排序便宜）。

### 3.4 均匀空间细分（§12.3.3）

与 BVH 的**本质区别**：
- BVH 划分**对象**——每个对象属于唯一节点，空间点可能在多个节点中
- 空间细分划分**空间**——每个空间点属于唯一单元格，对象可能跨多个单元格

**结构**：将场景分成大小相同的轴对齐 3D 网格。每个单元格存储一个指向该格子内对象的指针（空格子为 NULL，多对象格子可指向列表或嵌套结构）。

**光线遍历**：光线逐步穿越单元格，只检查光线经过的单元格中的对象。关键操作是决定每步沿哪个轴前进——跟踪光线与下一个垂直/水平边界的交点参数 $t$，取较小的那个。

> [!note] 限制 $t$ 范围
> 检查单元格内对象时，将 $t$ 限制在当前单元格范围内。否则可能错误报告穿过多个单元格后的命中，而非最近的命中。

### 3.5 轴对齐 BSP 树（§12.3.4）

空间细分的层次版本：用轴对齐平面递归划分空间，形成二叉树。

```
class bsp-node:
    surface-pointer left, right
    real D          // 切割平面位置（如 x = D）
    int axis        // 0=x, 1=y, 2=z
```

**与 BVH 的区别**：穿过切割平面的对象**同时存储在两侧子树**中——因此一个对象可能在多个节点中出现。节点更多、内存更大，但单个节点的处理更快（无需包围盒测试）。

**遍历的四种情况**（以 $x = D$ 切割平面为例，光线起点 $\mathbf{p} = \mathbf{a} + t_0 \mathbf{b}$）：

| 情况 | 条件 | 处理 |
|---|---|---|
| 1 | $p_x < D$ 且 $b_x < 0$ | 光线只走左子树 |
| 2 | $p_x < D$ 且 $b_x > 0$ | 先查左子树，无命中再查右子树 |
| 3 | $p_x > D$ 且 $b_x > 0$ | 光线只走右子树 |
| 4 | $p_x > D$ 且 $b_x < 0$ | 先查右子树，无命中再查左子树 |

情况 2 和 4 需要计算光线到达切割平面的参数 $t = (D - x_a) / x_b$，用 $t$ 限制子树的搜索范围。

### 3.6 三种空间数据结构对比

| | BVH | 均匀空间细分 | 轴对齐 BSP 树 |
|---|---|---|---|
| 划分对象 | 对象 | 空间 | 空间 |
| 层次性 | 是 | 否（均匀） | 是（自适应） |
| 对象复制 | 无 | 无（用指针） | 有（跨平面对象存两侧） |
| 内存 | 紧凑 | 取决于网格密度 | 比BVH大 |
| 适合场景 | 对象分布不均 | 均匀分布 | 通用 |
| 构建成本 | 排序/划分 | 简单 | 递归划分 |

## 4. 用于可见性排序的 BSP 树（§12.4）

### 4.1 画家算法与 BSP 树（§12.4.1）

画家算法从后到前绘制每个对象，后面的覆盖前面的，自动消除隐藏面。问题是：多个对象的全局排序不一定存在（遮挡循环）。

**BSP 树的核心思想**：用一个三角形所在平面将空间分成两侧。如果视点 $e$ 和三角形 $T_2$ 在 $T_1$ 平面的**同一侧**，则 $T_1$ 不可能遮挡 $T_2$——先画 $T_1$ 再画 $T_2$。如果在**异侧**，则先画 $T_2$ 再画 $T_1$。

```
function draw(tree, e):
    if (tree.empty) return
    if (f_tree.root(e) < 0):        // e 在负侧
        draw(tree.plus, e)          // 先画远侧（正侧）
        rasterize tree.triangle     // 画当前三角形
        draw(tree.minus, e)         // 再画近侧（负侧）
    else:                           // e 在正侧
        draw(tree.minus, e)         // 先画远侧（负侧）
        rasterize tree.triangle     # 画当前三角形
        draw(tree.plus, e)          # 再画近侧（正侧）
```

**关键优势**：树可以**预计算**，对任意视点都有效。视点变化时只需重新遍历，无需重建树。

### 4.2 构建树（§12.4.2）

```
tree-root = node(T1)
for i in {2, ..., N}:
    tree-root.add(Ti)
```

`add` 操作将三角形按其顶点在当前节点平面上的符号分到正/负子树：

```
function add(T):
    fa, fb, fc = f(a), f(b), f(c)
    if (all <= 0): add to negative subtree
    else if (all >= 0): add to positive subtree
    else: cut triangle and add pieces to both sides
```

### 4.3 三角形切割（§12.4.3）

当一个三角形跨越切割平面时（2 个顶点在一侧，1 个在另一侧），用平面将其切割成 3 个新三角形：

设 $a, b$ 在正侧，$c$ 在负侧。求边 $ac$ 和 $bc$ 与平面的交点 $A$ 和 $B$：

$$t_A = \frac{-\mathbf{n} \cdot \mathbf{a} + D}{\mathbf{n} \cdot (\mathbf{c} - \mathbf{a})},\qquad A = \mathbf{a} + t_A(\mathbf{c} - \mathbf{a})$$

三个新三角形（顶点顺序保持与原三角形一致的绕向）：

$$T_1 = (a, b, A),\quad T_2 = (b, B, A),\quad T_3 = (A, B, c)$$

$T_1, T_2$ 在正侧子树，$T_3$ 在负侧子树。

> [!warning] 精度问题
> 顶点非常接近切割平面时（$|f| < \epsilon$），切割会产生近乎零面积的退化三角形。解决方法：将 $|f| < \epsilon$ 的顶点 $f$ 值直接设为 $0$，避免不必要切割。这在共享顶点的模型中频繁出现，必须处理。

### 4.4 优化树（§12.4.4）

遍历时间与节点数成正比（与平衡度无关）。节点数取决于三角形添加顺序——不同顺序可能产生不同数量的切割。

- 最优顺序：$N$ 个三角形可能不切割，节点数 $= N$
- 最差顺序：大量切割，节点数远超 $N$
- 实际做法：从 $N!$ 种排列中随机采样若干，选最好的

## 5. 平铺多维数组（§12.5）

### 5.1 动机

传统 2D 数组按行优先存储：`index = x + Nx * y`。同行相邻元素在内存中相邻，但同列相邻元素隔了 $N_x$ 个元素——大数组时**缓存局部性差**。

平铺（tiling / bricking）把数组分成小块，使行和列方向的局部性都好。

### 5.2 二维单层平铺（§12.5.1）

将 $N_x \times N_y$ 数组分成 $n \times n$ 的小块。分块数 $B_x = N_x / n$，$B_y = N_y / n$（不整除时填充）。

**索引公式**：

$$\text{index} = n^2(B_x \cdot b_y + b_x) + y' \cdot n + x'$$

其中：
- 块索引：$b_x = x \div n$，$b_y = y \div n$
- 块内偏移：$x' = x \bmod n$，$y' = y \bmod n$

**优化——查表**：索引表达式可分解为 `index = Fx(x) + Fy(y)`，预计算两个查找表 $F_x$ 和 $F_y$（各 $N_x$ 和 $N_y$ 个元素），查表替代除法/取模。表大小可放入 L1 缓存。

### 5.3 三维两级平铺（§12.5.2）

3D 数组需要两级平铺以同时优化缓存行和 TLB 命中率：$m \times m \times m$ 个宏砖，每个包含 $n \times n \times n$ 个单元格。

索引公式同样可分解为 `index = Fx(x) + Fy(y) + Fz(z)`，预计算三个查找表。

**平铺块尺寸选择**：
- $n$ 应使一个块的数据恰好填满一个缓存行（如 32 位浮点数、128 字节缓存行 → 32 个元素 → $5\times5$ 略小、$6\times6$ 略大）
- $m$ 针对 TLB 优化（经验值：16 位数据集 $m=5$，浮点数据集 $m=6$）

> [!tip] 性能影响
> 某些体渲染应用中，两级平铺策略带来**十倍**性能差异。当数组超出主内存时，还能有效防止页面抖动。

| 问 | 答案要点 |
|---|---|
| 流形网格 | 每条边恰好 2 个三角形；每顶点单一完整三角形环 |
| 带边界流形 | 每条边 1~2 个三角形；每顶点单一边连通三角形集 |
| 一致定向 | 相邻三角形共享顶点在列表中顺序相反 |
| 索引网格 | `tInd[nt][3]` + `verts[nv]`；大网格约省一半存储 |
| 三角形邻接结构 | `tNbr[nt][3]` + `vTri[nv]`；$O(1)$ 遍历相邻三角形 |
| 翼边结构 | 边存 4 邻接边 + 2 顶点 + 2 面；遍历需检查 head/tail |
| 半边结构 | 每边拆两个半边；pair + next；遍历无需检查朝向 |
| 场景图 | DAG，变换沿树向下累积；子节点自动继承父变换 |
| 光线-AABB 求交 | 各轴算 $t$ 区间，区间重叠则命中 |
| IEEE 除零处理 | $+\infty/-\infty$ 自动处理；$-0$ 用倒数修复 |
| BVH | 对象划分；兄弟包围盒可能重叠；递归 hit |
| BVH 构建 | 按对象数均分（排序）或按空间均分（中点划分） |
| 均匀空间细分 | 空间划分；每点属唯一单元格；增量遍历 |
| 轴对齐 BSP 树 | 空间划分；跨平面对象存两侧；四种情况遍历 |
| 可见性 BSP 树 | 非轴对齐平面（与多边形重合）；预计算后任意视点可用 |
| 三角形切割 | 跨平面三角形切成 3 个，顶点顺序保持绕向 |
| 精度处理 | $|f|<\epsilon$ 设为 0，避免退化切割 |
| 平铺数组 | `index = Fx(x) + Fy(y)`，查表替代除法取模 |
| 平铺块尺寸 | 块数据 $\approx$ 一个缓存行；$n$ 对应缓存行，$m$ 对应 TLB |
