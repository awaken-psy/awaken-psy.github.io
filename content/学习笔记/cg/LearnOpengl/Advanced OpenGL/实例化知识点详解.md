# 实例化知识点详解

原教程：[LearnOpenGL-CN · 实例化](https://learnopengl-cn.github.io/04%20Advanced%20OpenGL/10%20Instancing/)

## 1 同一块岩石，摆到一万个位置

一圈小行星看起来各不相同，但可以共用一个岩石模型，只给每块岩石不同的位置、旋转和缩放。

普通做法是 CPU 反复“设置这块岩石的矩阵 → Draw”。**实例化则准备一组矩阵，一次 Draw 告诉 GPU：用这份几何画 N 个实例。**

| 共用的内容 | 每个实例自己的内容 |
|---|---|
| 岩石顶点、索引、Shader 等 | 偏移量，或完整的变换矩阵 |

因此不必复制 N 份顶点。几何照旧，变化的是每次实例使用哪一条参数。

## 2 一份几何，配 N 条偏移或矩阵

先回忆教程里的 100 个小四边形：每个四边形都是相同的 6 个顶点，只是各自加上不同的二维偏移。

**当前顶点的位置 + 当前实例的偏移 → 这个实例的顶点位置。**

实例数据有两种常见取法：

| 方法 | 怎样取出当前实例的数据 |
|---|---|
| uniform 数组 | 用 `gl_InstanceID` 作为下标，例如 `offsets[gl_InstanceID]` |
| 实例化属性 | 把偏移或矩阵存进缓冲，让 GPU 按实例读取下一条记录 |

`gl_InstanceID` 从 0 开始编号。教程先用 uniform 数组解释思路，再换实例化属性，避免把大量数据都塞进有限的 uniform 空间；本地 `10.1` 用的是后者。

岩石把二维偏移升级为完整矩阵即可：顶点最终使用 **projection × view × 当前实例矩阵 × 原始位置**。

## 3 divisor 决定什么时候换数据

同一块岩石内，顶点位置要逐个变化，但所有顶点应使用同一份实例矩阵。

| `divisor` | 属性怎样选取 |
|---|---|
| `0`，默认值 | 按当前顶点选取，适合位置、UV |
| `1` | 每个实例换一条，适合偏移、矩阵 |
| `2` | 每两个实例换一条 |

下面省略缓冲上传和属性格式配置，假设四边形 VAO 已配置好 location 2 的偏移属性：

```cpp
glBindVertexArray(quadVAO);
glVertexAttribDivisor(2, 1); // location 2 按实例读取
shader.use();
glDrawArraysInstanced(GL_TRIANGLES, 0, 6, 100);
```

最后两个数字表示：每个实例使用 6 个顶点，一共画 100 个实例。不是只画 100 个顶点，也不是画 100 个三角形。

> [!important] divisor 改的是读取频率，不是上传频率
> CPU 先把实例数据放进 GPU 缓冲，Draw 时按规则读取。修改 CPU 数组后，仍要更新缓冲；设置 divisor 不会自动同步数据。

## 4 复习时别混淆

- **一次 Draw 不等于 GPU 只算一块岩石。** CPU 少了重复提交，GPU 仍要处理各实例的顶点和片段。
- **多个 Mesh 仍要分别画。** 本例若岩石有 M 个 Mesh，N 个实例可从约 N×M 次提交变为 M 次实例化提交，其他物体另算。
- **只换 Draw 函数，不会自动产生不同位置。** Shader 必须使用实例偏移或矩阵，否则这些实例会重叠。
- **不是任意物体都能挤进同一批。** 通常要能共用几何、Shader 和渲染状态；不同材质可能需要分批。

> [!note]- 对照本地小行星示例
> 10.2 普通绘制 循环设置 `model`；10.3 实例化绘制 改用矩阵属性。一个 `mat4` 占四个属性位置，本例是 3～6，四列都设置 `divisor = 1`。

> [!summary] 一句话回忆
> **一份几何配 N 条实例数据，divisor 控制怎么读，一次实例化 Draw 提交这一批。**
