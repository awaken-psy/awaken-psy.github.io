# 射线的六级查询

采样块发出 64 条射线，每条都在回答同一个问题：这个方向上，什么表面会把光反弹给我？系统里有六级查询可以回答，成本与能力差别很大：

| 级   | 方式     | 能回答什么                    | 成本   |
| --- | ------ | ------------------------ | ---- |
| ①   | 屏幕空间查询 | 当前画面里有什么（深度 + 上一帧颜色）     | 极低   |
| ②   | 局部精场查询 | 起点附近一小段内有什么（索引表里几个模型的精场） | 低    |
| ③   | 粗场步进   | 整个世界（相机级联粗场，接近处逐格转精场）    | 中等   |
| ④   | 内联光追   | 真实三角形（硬件加速，逐条即时）         | 高    |
| ⑤   | 完整光追   | 真实三角形（硬件加速，完整命中流程）       | 最高   |
| ⑥   | 天空回退   | 天光环境                     | 几乎为零 |

规则只有一条：**能用便宜的就不上贵的**
1. 每条射线先查屏幕——有结果就结束。‘
2. 答不了的交给距离场：短程问题（比如面片朝灯发的遮挡检测线）用 ②，长程问题（GI 射线）用 ③。
3. 有硬件光追的机器上，②③整体换成 ④⑤。全部落空的，取天光 ⑥。

## 1. 流压缩：逐级筛选

"没找到才升级"的工程实现叫**流压缩**（stream compaction）：一级查询对全体射线执行，有结果的当场记录，没结果的**紧密排成一队**，只把这一队交给下一级。

效果有两点：
1. **贵的级别只在少数射线上执行**：便宜级别处理掉大部分射线（屏幕命中占大头），每一级接手的名单都比上一级短，最贵的光追只服务极少数"前面全答不了"的射线。
2. **GPU 并行度充分利用**：没有压缩时，一个线程组里大部分线程早已出结果，整组的硬件时间被少数仍在计算的射线占用；压缩把"还没结果"的射线重新排满一队，每级内部一个线程组恰好处理一队。

## 2. 屏幕空间查询：最便宜也最有价值

屏幕空间查询不是简单读一次深度图，它本身就是一次小型步进：

1. 射线投到屏幕坐标上，沿画面推进；
2. 推进用 **Hi-Z 深度金字塔**跳大步——远处用粗档、接近命中自动换细档，和球体步进"按安全距离前进"是同一个思路，只是安全距离来自深度金字塔；
3. 射线深度超过画面深度处出现**命中候选**——射线走入了某个已画表面的"背后"；
4. 候选不能直接采信：按**运动矢量**把候选点带回上一帧**核对深度**，对上了才接受——防止相机或物体运动时采信错位的表面（拖影）；
5. 接受后**取色读的是上一帧的最终画面**——那里面已经是直接光加全部间接光都画完的结果色：

$$
\text{屏幕命中} \approx \text{直接光} + \text{上一帧已算好的反弹光} \approx \text{接近两反弹的信息}
$$

限制有两条：
1. 读的是**上一帧**：灯光突变的瞬间旧颜色带着滞后，靠深度校验和后续的重投影压制。
2. 屏幕外的方向、没画到的表面、这一帧没出现在画面里的东西，一律答不了。

## 3. 中间两级：距离场查询的短程版与全程版

② 和 ③ 用的是同一套两级距离场（[分层距离场](学习笔记/cg/tuanjie引擎/GI原理/02-世界表示/02-分层距离场.md)），区别只在查多远：

**② 局部精场查询——短程版**。距离预算只有约一个粗场格：查起点所在格（和预算终点所在格）的模型索引表，每格最多 4 个模型，逐个进它们的精场求交，距离最近的胜出。适合"问题本身很短"的查询——面片朝灯发的**遮挡检测线**走的就是这一级。

**③ 粗场步进——全程版**。回答"整个世界里撞到什么"：

1. 从**包含射线起点的层**开始步进——近层格子细；
2. 走出这一层的包围盒就**换到外层**继续，每层只走自己罩住的那段路径，直到走出最外层；
3. 读数变小、接近某处表面时，在**步进点前方一点**（提前量约等于命中阈值）查该格的模型索引表，转入登记模型的精场精确判定，多个候选里距离最近的胜出；
4. 每段步进有**步数上限**（128 步）——掠射时步长会越来越小，上限保证射线一定给出结论，而不是在切线处无限小步推进。

命中后拿命中点去面片取色——带深度校验的双线性取色，多个候选按可信度加权平均，足够可信就提前结束（校验细节见[面片与表面光场](学习笔记/cg/tuanjie引擎/GI原理/02-世界表示/01-面片与表面光场.md)）。

## 4. 硬件光追：换命中方式，不换流程

带硬件光追的平台上，④⑤启用——**一启用就替换掉 ②③**：④是内联的逐条即时查询，⑤是完整命中流程，两者合起来接手距离场的全部工作。同一条射线没必要既查距离场又跑光追，两套几何引擎只跑一套。

语义变化只有一处：命中从"距离场近似"变成"真三角形精确"——距离场存不下的小螺丝、铁丝网、薄墙，光追都能给准确命中。而**取色依然读面片**——光追负责把"撞在哪、朝向哪"定得更准，"那里发多少光"仍由面片数据决定。

于是面片数据有了另一重身份：它让"软几何"（距离场）与"硬光追"共享同一套光照结果——**换几何后端，不用换光照数据**。

## 5. 天空回退

全部落空的射线射向天空——这不是查询失败，而是正确答案：逃出场景的光就该收集环境光。结果取天光环境按方向、按粗糙度档的颜色，命中标记"无限远"距离，不再对它做遮挡和混合。

至此 64 条射线全部有了结果。收回来的 64 份"方向 → 亮度"数据，接下来要汇总成 9 个球谐系数、再摊回像素——先转到世界层看面片数据怎么更新，然后是[从采样块到像素](学习笔记/cg/tuanjie引擎/GI原理/03-核心算法/04-从采样块到像素.md)。
