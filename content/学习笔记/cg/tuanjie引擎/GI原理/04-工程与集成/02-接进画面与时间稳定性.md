# 接进画面与时间稳定性

GI 不是孤立系统，它插在渲染管线中间。这篇讲两件事：它从管线拿什么、交回什么；以及相机运动时间接光为什么不糊。

## 1. 七样输入，三张输出

URP/HDRP 每帧要先把这几样递给 GI：

| 输入 | 用途 |
|---|---|
| 深度图（带 Hi-Z 金字塔） | 屏幕空间查询的大步跳跃；采样块采样点定位 |
| 法线图 | 采样点朝向；三判据滤波的朝向判据 |
| 运动矢量图 | 时间稳定性的关键（下节） |
| 上一帧的最终画面 | 屏幕空间查询的取色来源——"多一反弹信息"的原料 |
| 材质缓冲（颜色/粗糙度） | 摊回时按材质调制 |
| 灯表 | 世界层计算直接光照 |
| 天空环境查询接口 | 射线全空时的回退、天光总开关 |

读懂这张表的额外收获：你能自己判断"一个管线能不能接这套 GI"——只要凑得齐七样就能接。这就是为什么同一套算法既能进 URP 又能进 HDRP：两个管线都有能力备齐，差异只是"谁去备、怎么备"，各写一个适配层，算法本身零修改。

GI 交回三张图：**间接漫反射**（在着色器里与 Lightmap、Light probe 占同一位置——《总览》第 10 章的环境光汇合点多了个实时来源）、**粗糙镜面**（与反射 probe 按粗糙度分工）、**bent normal**。着色时的事很直接：间接漫反射按表面颜色一乘、粗糙镜面按材质混合——GI 负责"把环境给的光算清楚"，材质决定"怎么用"。

## 2. 像素层重投影

[核心算法](学习笔记/cg/tuanjie引擎/GI原理/03-核心算法/04-从采样块到像素.md)讲过块层的帧数混合——它决定结果质量，越静越准。但它管不了一件事：**相机一动，采样块网格整体重排**，上一帧这里还是墙角的结果、这一帧变成桌面，旧结果直接沿用会对不上位置。

解决思路一句话：**不按网格找历史，按像素找历史。**每个像素在上一帧都有明确的前身（运动矢量给出位置）：

1. 拿本帧 GI 新算的结果；
2. 按运动矢量找到上一帧同一点的三张旧图；
3. 新旧按"这张像素已稳定了多少帧"加权（上限约 8 帧），与块层同一套帧数算法；
4. 写出结果，同时保存本帧深度/法线/帧数，供下一帧用。

旧图不盲信，三重校验：前身移出屏幕外——弃；前身深度与本帧推算对不上（有东西切换了前后）——弃或降权；前后身朝向差太大（位于不同表面）——弃或降权。稳妥的做法是取 4 个邻近历史像素、按各自可信度加权平均。

两层时间的分工至此清晰：**块层帧数混合管结果质量（下限 2 上限 16），像素层重投影管运动连续（上限 8）**。只有块层，相机一动旧结果错位、画面跳变；只有像素层，单帧结果太噪。缺一不可。

## 3. 几个收尾细节

**曝光的衔接**。GI 输出存成"预曝光"形态：写出时乘当前曝光，读历史时把上一帧的曝光除掉——曝光怎么变，历史图都能正确续用。这是与后处理链（HDR → 曝光 → Tone mapping）的一次干净衔接。

**透明的特殊处理**。玻璃后面的墙也该有间接光，但透明物不写深度缓冲，GI 的采样和追踪都会失真。处理方式是专用通道：透明相关的屏幕追踪在"不透明画完、透明未画"的窗口期单独再跑一遍，范围缩小到屏幕空间能答的部分，有限但成本可控。

**平台**。当前支持：桌面全平台、主机、移动中高端。网页和微信小游戏暂不可用——3D 纹理与 compute 的门槛，加上距离场和图集的显存占用。移动端靠三个开关运行：交错更新（射线 ÷16）、快速积分（摊回从邻域加权降为就近取）、较低的面片密度——同一套系统，用保守参数运行。
