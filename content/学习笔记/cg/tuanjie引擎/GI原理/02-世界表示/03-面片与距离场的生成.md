一个模型标记为"参与实时 GI"，编辑器立即为它生成两份随模型永久保存的资产：**SDF**（模型形状的 3D 距离表示）和**facet布局**（贴满表面的贴片集合——位置、朝向、大小）。

注意预制的边界——**预制的是几何表示，不是光照**。改模型的形状，两份资产要重新生成；面片数据每帧自己更新。

对比 Lightmap 那种"预制光照结果"的烘焙：那边灯一动全部作废，这边灯随便动。**TuanjieGI 把预计算用在几何上，把自由留给光照。**

## 1. 距离场：离线测量

距离场不是解析算出来的（模型千奇百怪，没有公式可循），而是**测量**出来的。编辑器在离线阶段逐点测量：

1. 模型包围盒切成体素格网（就是距离场未来的格子）；
2. 从每个格点向四面八方发射测量线，撞到表面为止——最近一次碰撞的距离就是该格读数；
3. 内外判定（穿越计数）定正负；开放网格（树叶、栅栏）测不出内外，自动退化为 UDF；
4. 按距离远近生成几个粗细档位（LOD）。

整套测量走的是成熟的离线光线求交（BVH 加速）。

## 2. 面片：六向投影

面片的生成：模型分别沿六个方向投影，每次投影得到一批"该由这个朝向面片覆盖"的表面区域，然后对齐到轴向摆贴片，直到表面被覆盖住。面片数量有预算上限——太复杂的模型自动降密度。

此刻生成的是**布局**。面片上的像素内容（颜色、法线、深度）**运行时采样**：面片第一次驻留显存时，系统用普通光栅化把原模型对着面片格子画一遍，读回像素。

为什么运行时采样而不是导入时预先烘焙？因为采样走的是引擎的普通渲染管线——无论模型用什么材质、贴图、特效，光栅化结果天然正确。不用写任何"材质翻译器"，永不过时。

## 3. 运行时：按需驻留

资产生成后存放在硬盘里；进游戏后，显存预算成了新约束。管理原则是"用到才驻留"：

- **按距离换档**：模型离相机远，距离场自动用粗档；
- **按使用续期**：每帧统计哪些档位实际被射线查过（GPU 统计、异步回传 CPU）——被使用的常驻显存，没被使用的让出；
- **新模型进入范围**：按统计流式加载它的精场，开放式大世界可行；
- **移动的模型**：粗场本来每帧跟着相机重建，顺带完成更新；面片数据按新位置重采样迁移，随后逐帧重新清晰。

## 4. 从模型到画面

```
美术建模
  → 编辑器预制: 距离场(离线测量+LOD+UDF) + 面片布局(六向投影)
  → 运行时: 按距离选档、按使用驻留、粗场每帧合成
  → 每帧: 面片采样基本数据 → 计算直射+间接 → 写回出射光
  → 每帧: 屏幕射线 → 粗场推进→查索引表→精场命中→面片取色
  → 画面的间接光
```
