# 03 - 投影：从 3D 到 2D

> 阅读时间：约 30 分钟
> 关键词：FOV、视锥体、针孔相机、深度精度、Reverse-Z

---

## 你将学到什么

- 透视投影的物理原型：针孔相机
- FOV、宽高比、近平面、远平面如何决定你"看到的世界"
- 深度缓冲的精度陷阱：为什么远处物体闪 flicker
- Reverse-Z：现代引擎（含团结/Unity）解决深度精度的主流方案

## 1. 透视的原型：针孔相机

一切 3D 投影的原型是**针孔相机（pinhole camera）**：一个密封盒子，前面扎一个小孔，光线穿过小孔，在盒子背面的底片上**倒立成像**。

```
        世界点 P(x, z)
            ●
             \|
              \
               \        （光线穿过针孔）
                \
                 〇 小孔（相机原点）
                /|
               / |
              /  |  ← 成像距离 f（焦距）
             ●   |
        底片上的像 p(x', -z')     （倒立、缩小）
```

几何上，底片上的像与世界点之间是**相似三角形**关系：

$$
\frac{x'}{f} = \frac{x}{z} \quad \Rightarrow \quad x' = f \frac{x}{z}
$$

$$
\frac{y'}{f} = \frac{y}{z} \quad \Rightarrow \quad y' = f \frac{y}{z}
$$

看到了吗？**除以 $z$**——上一节"透视除法除以 $w=z$"的物理原型就是这里。针孔相机就是大自然写的投影矩阵。

> 💡 **关键直觉**：透视的全部秘密是"**位置除以深度**"。离得越远（$z$ 越大），同一个偏移量 $x$ 在画面上占的比例越小。

现代图形管线把这个过程倒过来用（不需要真的"倒立像"，屏幕坐标系再翻回来即可），但几何关系一字不差。

## 2. 相机参数与视野：你到底"看到"多少

引擎里 Camera 的几个参数，每一个都精确对应投影矩阵里的一个数：

| 参数 | 几何含义 | 对投影矩阵的影响 |
|---|---|---|
| **FOV**（视场角） | 上下方向能看到多大范围（垂直张角） | 控制垂直缩放 $\frac{1}{\tan(\text{fov}/2)}$ |
| **Aspect**（宽高比） | 视口宽/高 | 控制水平缩放 $\frac{1}{a\tan(\text{fov}/2)}$ |
| **Near**（近平面） | 距相机多近的东西开始可见 | 影响 $z$ 压缩曲线与深度精度 |
| **Far**（远平面） | 最远可见距离 | 同上 |

### 2.1 FOV 直觉

FOV 是**垂直方向**的视场角。为什么游戏里第一人称视角常用 60°~90°，而电影感镜头约 40°？FOV 越大：

- 视野越广（战术射击游戏喜欢大 FOV）；
- 但**透视变形越强**（物体边缘拉伸、速度感夸张）；
- 同时同样的物体在屏幕上**更小**。

$$
\text{fov} \uparrow \;\Rightarrow\; \tan(\text{fov}/2) \uparrow \;\Rightarrow\; \frac{1}{\tan(\text{fov}/2)} \downarrow \;\Rightarrow\; \text{画面中的物体} \downarrow
$$

### 2.2 视锥体：你看到的是一块"棱台"

近/远平面与四条侧棱围出一个**平截头体（Frustum，视锥体）**——这才是相机的真实可见区域。第04章的视锥体剔除，就是拿它的 6 个平面逐个检查物体包围盒。

$$
\text{可见} \iff -w \le x \le w,\; -w \le y \le w,\; 0 \le z \le w \quad (\text{D3D约定})
$$

为什么近平面不能设成 0？两个原因：一是 $x/z$ 在 $z=0$ 处除零爆炸；二是深度精度（下一节）。

## 3. 深度：投影矩阵里最微妙的部分

$x,y$ 经过投影后是"屏幕在哪"，$z$ 则被改造成"**深度**"存进深度缓冲，用于判断遮挡（近的挡住远的，第02章展开）。

### 3.1 深度不是线性的

新手最常踩的坑：**NDC 深度 $z_{ndc}$ 与世界深度 $z$ 不是线性关系**。

透视投影对深度的改造是**有理函数**（非线性）：

$$
z_{ndc} = \frac{A \cdot z + B}{z} = A + \frac{B}{z}
$$

其中 $A=\frac{f+n}{f-n}$，$B=-\frac{2fn}{f-n}$（D3D 约定下）。这是个**双曲线**形状：

```
深度精度分布（近平面 0.1，远平面 100，示意）：

z_ndc
 1 ┤                          ●●●●●●●●●  ← 远平面挤在一起
   │                    ●●●●
   │               ●●●
   │           ●●
   │       ●●
   │    ●●
 0 ┤●●●●                            ← 近平面附近精度极高
   └──────┴──────┴──────┴──────→ 相机距离 z
         25%    50%    75%
```

**读图**：距离相机越近，深度值分辨率越高；越远越挤。近平面处一丁点距离就占掉深度区间的一大段，远处则成片物体挤在几个深度值之间。

### 3.2 为什么这会出事：Z-Fighting

深度缓冲一般只有 24 位（1670 万个离散值）。远处两个间距 0.5 米的物体，深度值可能**四舍五入到同一个数**——GPU 无法判断谁在前，两帧之间交替胜利，表现就是**远处物体表面闪烁/穿插，称为 Z-Fighting（深度冲突）**。

实用结论（引擎实践中的经验法则）：

1. **近平面在安全前提下尽量拉远**：near 从 0.01 改到 0.1，远处精度可提升约一个数量级（$B=-\frac{2fn}{f-n}$ 中 $n$ 的影响巨大）；
2. 远平面不要盲目放大：near=0.1, far=1000 时远处已经糊成一片；能收窄就收窄；
3. 检查远处地面共面闪烁的物体：错开几何或用 polygon offset。

### 3.3 Reverse-Z：现代引擎的解法

问题的根源是双曲线把精度全堆在近平面。但 GPU 只要求深度缓冲能**比较大小**，并不在乎大=远还是大=近。于是现代引擎（团结/Unity 的 D3D11/D3D12/Vulkan/Metal 后端，URP/HDRP 默认开启）反转约定：

> **Reverse-Z：近平面映射到深度 1.0，远平面映射到 0.0。**

双曲线形状没有变，但**浮点深度缓冲（32 位 float）的精度分布恰好与它互补**——浮点数在接近 1.0 的地方也有最高的表示密度，两个曲线"嵌合"后全程精度都够用。

$$
\text{普通: } z_{ndc} \in [0 \text{（近）}, 1 \text{（远）}] \qquad
\text{Reverse-Z: } z_{ndc} \in [1 \text{（近）}, 0 \text{（远）}]
$$

> ⚠️ 抄 shader 时如果看到别人比较深度写的 `depth < z`，在 Reverse-Z 引擎里方向要反过来。引擎内置管线 API 已帮你隐藏了大部分差异，但自己动深度缓冲时（水面深度、雾效）必须知道当前约定。
>
> 📁 **源码指引**：`Runtime/GfxDevice/GfxDeviceTypes.h`（深度写入与比较枚举 `kCompareOp` 等）；URP 中创建深度时反转 clear 值的代码在 `Packages/com.unity.render-pipelines.universal/Runtime/UniversalRenderer.cs` 附近。

## 4. 屏幕之外：FOV 之外的宽高比

垂直 FOV 固定、屏幕变宽（16:9 → 21:9 带鱼屏），垂直视野不变但水平视野变大。这就是为什么同一款游戏在超宽屏上"看得更多"——**水平 FOV 是被 aspect 推导出来的**：

$$
\tan(\text{fov}_h / 2) = a \cdot \tan(\text{fov}_v / 2)
$$

游戏的"FOV 滑条"改的就是垂直 FOV，水平自动联动。而电影感与游戏感的差异之一，正是电影镜头的垂直 FOV 远小于游戏默认值。

## 5. 在引擎中

- 相机参数 → 投影矩阵：`Runtime/Graphics/Display/` 与相机模块；URP 在 `Packages/com.unity.render-pipelines.universal/Runtime/` 的 `CameraData`；
- 引擎每帧把 VP 矩阵与相机位置塞进"内置着色器参数"：`Runtime/GfxDevice/BuiltinShaderParams.cpp`；
- 视锥体平面提取（剔除用）：`Runtime/Graphics/ScriptableRenderLoop/ScriptableCulling.cpp`——从组合矩阵 $VP$ 中直接"抠"出 6 个平面，第04章详解。

---

## 小结

- 透视的原型是针孔相机：屏幕位置 = 坐标 ÷ 深度；
- FOV/Aspect/Near/Far 每个都精确对应投影矩阵的一项；
- 深度经投影后**非线性**，精度集中于近处 → 远处 Z-Fighting；
- 工程解法：near 别太近、far 别太远、用 Reverse-Z + 浮点深度；
- 超宽屏"看更多"来自 aspect 拉大水平 FOV。
