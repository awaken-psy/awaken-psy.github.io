## 1. 第一性问题：帧时间去哪了

帧时间公式（把全书串起来）：

$$
T_{frame} = \max\big( \underbrace{T_{CPU:logic} + T_{CPU:cull/batch/submit}}_{\text{CPU 主线程 + 渲染线程}},\ \underbrace{T_{GPU}}_{\text{几何/光栅/着色/带宽/后处理}} \big)
$$

性能优化第一铁律：**先测量，再动刀**。瓶颈判错方向，白干三周。诊断的第一刀切在 **CPU vs GPU**：

| 观察 | 判定 | 用什么证据 |
|---|---|---|
| 主线程或渲染线程 100%，GPU <90% | **CPU bound** | Profiler 线程图 |
| GPU 主峰值 >100%，CPU 闲 | **GPU bound** | GPU Profiler/RenderDoc |
| 都不满但帧率低 | 同步/等待（VSync、Swap 等待、读回） | Profiler 的等待段 |

## 2. 工具链总表：什么工具看什么

| 工具 | 强项 | 看什么 | 别用它看 |
|---|---|---|---|
| **Profiler（CPU）** | 线程时间轴 | 主线程/渲染线程/Job 哪段爆 | 单个 DrawCall 细节 |
| **Profiler（GPU 模块）** | Pass 级 GPU 耗时 | 每个管线 Pass 的时间分布（依赖厂商驱动支持） | 硬件内部细节 |
| **Frame Debugger** | **命令序列** | DrawCall 顺序、每批内容、SRP Batcher 兼容性、Pass 图像逐步验证 | 时间信息（它不看耗时） |
| **RenderDoc** | **单帧 GPU 封尸** | 单 DrawCall 的状态/资源/PS 反汇编/像素历史（哪个像素被哪些 pass 写过） | 实时性能趋势 |
| **Profile GPU 厂商工具**（Snapdragon/Perfetto/Xcode GPU/Metal System Trace/PIX） | 硬件级真机数据 | 真机带宽/占用率/温度节流 | 编辑器里的跑分 |
| **Memory Profiler** | 内存快照 | 纹理/缓冲/Lightmap 的内存大头 | 时间性能 |
| **Rendering Debugger（HDRP）** | 管线内部可视化 | 逐 Pass 开关验证贡献、成本热图 | — |

**工作流搭配口诀**：**Profiler 找方向 → Frame Debugger 找结构 → RenderDoc 找元凶 → 厂商工具上真机复核**。

## 3. CPU Bound 的细分诊断（渲染侧）

渲染线程的常见大户与药方（全书索引回收）：

| 症状段 | 原因 | 药方（对应章节） |
|---|---|---|
| Submit/`SetPass Calls` 高 | DrawCall 多/状态切换多 | 合批四流派（第04章）、SRP Batcher（第05章） |
| 剔除耗时长 | 物体数大/遮挡烘焙差 | 视锥+遮挡剔除（第04章）、LOD |
| 排序耗时长 | 透明多 | 透明预算（第02章） |
| shader 编译卡顿 | 运行时首编变体 | 预暖+变体剔除（第05章） |
| Job/主线程爆 | 蒙皮/动画逻辑 | GPU 蒙皮、Job 化 |
| Camera 数 ×物体 | 相机栈滥用 | 合并相机/裁剪 mask（第04章） |

**性能第一杠杆**（按收益排序）：剔除范围 > DrawCall 合批 > 变体数 > 相机数。先动结构性问题，再抠细节。

## 4. GPU Bound 的细分诊断

GPU 的四个子瓶颈（RenderDoc/厂商工具判定）：

| 子瓶颈 | 特征 | 药方 |
|---|---|---|
| **几何/顶点** | DrawCall 数大、顶点数大、小三角形多（第02章 quad 浪费） | LOD、合批网格、去细分 |
| **填充率/着色** | 高分辨率×复杂 PS×Overdraw | 降 PS 复杂度/变体、降 Overdraw（第02章）、半分辨率后处理（第11章） |
| **带宽** | 纹理大/RT 读写多/G-Buffer | 纹理压缩+mip（第02章）、减 RT 格式、延迟换前向（第08章，移动端） |
| **ALU** | 复杂数学（多次光照循环、PCF 大核） | 循环上限（第06章灯数）、阴影软化降档（第07章） |

**移动端特有**：带宽墙（第02章）与**温控节流**（真机连跑 15 分钟测，不要只测前 1 分钟的"快乐帧"）。

## 5. 可复用的"降帧排查流程"

**Step 1 —— 定位层**：Profiler 线程图，CPU 还是 GPU？（第1节公式）

**Step 2a —— CPU 路线**：
```
DrawCall 数 > 预算?（桌面>1w/移动>1k）
  → Frame Debugger 看批次结构：谁贡献的？
     → 同材质重复物体多 → Instancing（第12章）
     → 材质数太多 → 材质合并/变体治理（第05章）
     → 状态切换频繁 → SRP Batcher 兼容性检查（第05章）
剔除段长? → 遮挡/LOD/距离剔除（第04章）
```

**Step 2b —— GPU 路线**：
```
降分辨率跑：帧率大幅升? → 填充率/带宽型 → 查 Overdraw 视图与 RT 格式
不变? → 几何/ALU 型 → LOD 与 PS 复杂度
逐 Pass 开关（HDRP Rendering Debugger 或手动改 URP asset）找出"最贵 Pass"
  → 阴影贵 → 距离/级联/软化降档（第07章）
  → 透明贵 → 层数/粒子预算（第02章/第12章）
  → 后处理贵 → 半分辨率/砍邻居类（第11章）
```

**Step 3 —— 上真机复核**：厂商工具看带宽/占用率/温度；记录"优化前后"的同场景数据（无数据的优化=玄学）。

**给读者的最后建议**：
1. **打开引擎做实验**：每个专题配一个最小场景（阴影参数实验、变体审计、Overdraw 视图）——本书的一切概念都可在编辑器里"看见"；

## 小结

- 第一刀切 CPU/GPU，第二刀切子瓶颈（几何/填充/带宽/ALU）；
- 工具口诀：Profiler 找方向 → Frame Debugger 找结构 → RenderDoc 找元凶 → 厂商工具上真机；
- CPU 药方杠杆：剔除 > 合批 > 变体 > 相机；GPU 药方：降 PS/降分辨率/砍 Pass；
- 无数据的优化是玄学——前后同场景数据是底线；
- 全书十三层知识在性能诊断里完成了"总复习"：每个瓶颈都有出处，每个药方都有原理。

## 自测问题（综合大题）

1. 移动项目 45 FPS：主线程 8ms、渲染线程 14ms、GPU 12ms——第一刀切哪？接下来看什么工具？
2. 桌面 3A 帧不稳：GPU 90%+，降分辨率帧率不变——判断子瓶颈并给出两步药方。
3. DrawCall 数 3000（材质 800 个），SRP Batcher 已开但 Profiler 显示 SetPass 巨大——用第05章知识定位最可能原因（材质变体/兼容性）。
4. 设计你自己的"渲染预算表"：以 45 FPS 手机为目标，分配 DrawCall/阴影/后处理/透明的预算。
