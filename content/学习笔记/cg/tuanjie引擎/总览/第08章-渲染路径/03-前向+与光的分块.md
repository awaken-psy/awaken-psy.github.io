# 03 - 前向 + 与光的分块

> 阅读时间：约 35 分钟
> 关键词：Forward+、Tiled、Clustered、光分桶、计算着色器

---

## 你将学到什么

- 前向+的核心思想：给像素配"光名单"，但不存 G-Buffer
- Tiled 与 Clustered 两种分桶维度与各自的病
- URP 的实现现状与团结引擎的选择
- 三种渲染路径的终局对比表

---

## 1. 前向的两个痛、延迟的四个罪，各有解法吗？

复盘：
- 前向之痛：像素被它周围**所有**灯各算一遍（灯列表按"物体"分配，重叠区域重复计算）；
- 延迟之罪：透明、MSAA、带宽、材质单一——全是"G-Buffer 这张解剖图"的锅。

**问题**：能不能**不存解剖图**，但让每个像素只算"真正影响它的灯"？

**答案**：把空间切片分桶，给每桶一个光名单——这就是**前向+（Forward+，含 Tiled/Clustered 两个流派）**。

## 2. Tiled（瓦片）：屏幕切格

**第一步：光剔除分桶（每帧一次，compute）**
把屏幕切成 16×16 像素左右的**瓦片**，对每盏灯把它的范围投影到屏幕，登记进"覆盖到的所有瓦片"：

```
屏幕 (16×16瓦片示意)           灯A(红)影响这几个瓦片:
┌─┬─┬─┬─┬─┐                  ┌─┬─┬─┬─┬─┐
├─┼─┼─┼─┼─┤                  ├─┼─▼─▼─┼─┤
├─┼─┼─┼─┼─┤    → 灯列表:      ├─┼─▼─▼─┼─┤
├─┼─┼─┼─┼─┤      瓦片(2,1): [A]├─┼─┼─┼─┼─┤
└─┴─┴─┴─┴─┘                  └─┴─┴─┴─┴─┘
```

还要按深度做一次 2.5D 剔除：用该瓦片的最小/最大深度，把"深度不达标的灯"剔掉。

**第二步：着色**
前向画物体，PS 里按像素坐标找到自己瓦片的光名单，**只循环这几盏**：

$$
C_{pixel} = C_{material} + \sum_{l \in \text{tile}(p)} C_{BRDF}(l)
$$

**收益**：灯的成本 ∝ "真覆盖该像素的灯数"（前向是"物体周围所有灯"、延迟是"全屏受影响区域"）。瓦片化还特别适合 compute（一个线程组正好处理一个瓦片）。

**Tiled 的病**：
- 2D 分桶对**深度跨度大的场景**失灵（上帝视角俯视全场时一个瓦片里前后 500 米都算"覆盖"——名单爆炸）；
- 名单上仍有"前后的灯"（深度测试粗）。

## 3. Clustered（簇）：切 3D 香肠

**改进**：在瓦片基础上**沿深度再分层**（常按指数分布——第07章级联同款直觉）：

```
空间被切成 (瓦片×深度簇) 的3D格子:

far ┤ █ █ █ █  ← 每个格子独立光名单
     █ █ █ █
     █ █ █ █
near └─┬─┬─┬─┘
      屏幕 xy
```

每帧构建（compute 一次），PS 按像素坐标+深度查簇。**深度剧变场景（俯视/室内分层）名单精准得多**。现代主机/PC 引擎标配：Tiled 用于简单场景、Clustered 是通用解；URP/HDRP 的 Forward+ 均为 Clustered（`LightLoop` 相关，HDRP 最成熟）。

**成本对比总表**（着色 1000 盏灯覆盖的夜场，示意）：

| 路径 | 每像素光照成本 | 附加成本 |
|---|---|---|
| 前向（URP 每物体） | 物体周围全部灯 | 无 |
| 延迟 | 受影响区域全算 | G-Buffer 巨额带宽 |
| 前向+ Clustered | **本簇名单内的灯**（常 <10） | 分桶 compute（一帧一次） |

## 4. 灵魂三问（设计视角）

**Q1：Forward+ 为什么在桌面"取代"延迟？**
透明（前向光照原生）、MSAA（原生）、带宽（无 G-Buffer）、材质（前向自由）——**延迟四个罪全免**，只留"每像素逐灯循环"的成本。compute 普及后分桶不贵 → 现代桌面的默认答案。

**Q2：那移动端呢？**
移动 GLES：compute 支持残缺（3.1 才有 ES 3.1 compute）、带宽与缓存敏感——前向+ 直到近年 Vulkan 安卓才可行；团结引擎的移动主线（含微信小游戏）仍是**前向 + 灯数量预算**。**前向+ 是"桌面新技术 + 移动晚班车"**。

**Q3：URP/HDRP/内置现状？**
- HDRP：Forward+（集群）为主推路径；
- URP：Forward+ 在近版本加入（旧 Deferred 可选）；
- 内置：无 Forward+（架构固定）——**管线选型差异的实感案例**。

> 📁 **源码指引**：HDRP 的 clustered light loop 在 `Packages/com.unity.render-pipelines.high-definition/Runtime/Lighting/LightLoop/`（分桶构建、簇常量、BigTile 预剔除全套）；URP 对应 `Packages/com.unity.render-pipelines.universal/Runtime/`（Forward+ 相关 pass 与 light list）；引擎侧结构化缓冲与 compute 基础设施：`Runtime/Graphics/GraphicsBuffer.cpp`、`ComputeShader.cpp`（第12章主角）。

---

## 小结

- 前向+ = 前向 + **光分桶名单**：不存 G-Buffer，灯成本降到"真影响该像素的灯"；
- Tiled 2D 屏幕切格，深度场景失灵；Clustered 加深度第三维，现代标配；
- 延迟四宗罪全免，代价是一帧一次的分桶 compute；
- 桌面终局：Forward+（HDRP）与延迟并存；移动与前向+相见恨晚，仍是前向天下。
