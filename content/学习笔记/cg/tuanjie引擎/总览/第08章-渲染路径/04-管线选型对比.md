# 04 - 管线选型对比：内置 / URP / HDRP 与团结平台变体

> 阅读时间：约 35 分钟
> 关键词：管线选型、URP vs HDRP、平台矩阵、微信小游戏变体

---

## 你将学到什么

- 三大管线的定位、能力、成本全景对照
- 选型的决策树与常见后悔点
- 团结引擎平台变体（微信小游戏 URP 等）的适配哲学
- 选错管线的"代价表"——为什么选型是第一架构决策

---

## 1. 终极对照表

| 维度 | 内置管线 | URP | HDRP |
|---|---|---|---|
| **本质** | 写死在引擎 C++ | C# 包（可读可改可fork） | C# 包（高端特性堆栈） |
| **渲染路径** | 前向（+老延迟） | 前向为主，可切换 | Forward+ / Deferred |
| **光照** | Blinn-Phong/Standard 混合 | PBR（第06章那套） | PBR + 物理单位（lux/nit） |
| **阴影** | 固定方案 | CSM 精简 | CSM+接触+体积全套 |
| **后处理** | 图像效果组件 | Post-processing Volume | 完整 Volume 体系 |
| **目标平台** | 全部（老平台兜底） | 全部（**移动一等公民**） | PC/主机（**无移动无 GLES**） |
| **定制性** | ✗（只能 CommandBuffer 补丁） | 中（RendererFeature） | 中高（自定义 Pass 较难） |
| **包体/复杂度** | 最小 | 中 | 最大 |
| **团结特化** | Weixin 定制 | **Weixin URP / 小游戏模板** | — |
| **未来** | 维护模式（不推荐新项目） | 主力 | 高端线 |

**一句话画像**：
- **内置**：祖宅——住着没问题，但敲不得墙；
- **URP**：主流公寓——图纸透明（C# 源码），按需改造；
- **HDRP**：摄影棚——设备最全（物理光照、体积、LookDev），但只接"高端电路"（现代 API 与桌面 GPU）。

## 2. 选型决策树

```
目标平台有移动端（含微信小游戏）吗？
├─ 是 → URP（几乎唯一答案）
│       └─ 极低端 GLES 老机占比高？→ URP + 关掉默认的贵特性（后处理精简、阴影缩距离）
└─ 否（纯 PC/主机）
    ├── 追求 3A 画质/物理光照/复杂体积 → HDRP
    ├── 需要深度定制管线（风格化/特殊算法）→ URP（fork 源码最顺手）
    └─ 老项目维护、不新增功能 → 内置（别迁移）
```

**为什么移动=URP 是铁律**：HDRP 物理光照单位与高带宽路径在 GLES 上**不可运行**（非"慢"而是"不支持"）；内置管线的未来投资停在原地；URP 有移动专用简化（每物体光上限、Bloom 简化版、无 MSAA+TAA 可选）与团结的小游戏专属优化（Weixin URP：进一步砍后处理、ASTC 压缩链、首包裁剪）。

## 3. URP vs HDRP 的深层差异（不是"画质高低"）

新手最大误解："HDRP = 更高画质的 URP"。真实差异是**世界观不同**：

| | URP 世界观 | HDRP 世界观 |
|---|---|---|
| 光的单位 | 抽象强度（美术直觉） | 物理单位（lux/nit/lm）+ 物理相机曝光（第11章） |
| "正确"的定义 | "看起来对" | "物理上可测量" |
| 材质调法 | 直接调参数 | 配合曝光与光照环境调 |
| 体积效果 | 基础 | 体积云/雾/光轴的完整体系 |
| 工作流 | 快速出画面 | LookDev/光照调试全流程 |

**后果**：URP↔HDRP **资产不通用**（材质光照单位不同、后处理配置不同），迁移成本高——**选型要按"产品的最终画面目标"定，中途换管线接近重做**。

## 4. 团结引擎的平台管线变体

```
URP（团结维护版）
├── 标准移动版
├── WeixinMiniGame URP ── 微信小游戏定制：
│     · WebGL2 后端 + 首包4MB约束 → 激进变体裁剪与shader精简
│     · 后处理裁剪（Bloom 简化/无TAA）
│     · ASTC 优先的压缩链与 mipmap 策略
│     · 渲染分辨率与 DPR 适配（高 DPR 屏幕动态降分辨率）
├── HMI 车机版 ── 常驻帧率/宽温环境，传统 API 兼容优先
└── OpenHarmony 版 ── 挂在 GLES/Vulkan 后端，复用安卓优化线
```

**适配哲学**：不是"新平台新管线"，而是**同一 URP 管线 + 平台配置资产**——因为管线分层（第00章）保证了底层换后端不换上层。这也是为什么"学一次 URP，到处能用"。

> 📁 **源码指引**：URP 包 `Packages/com.unity.render-pipelines.universal/`（注意有 Platform/ 或各变体的 asmdef 区分）；HDRP `Packages/com.unity.render-pipelines.high-definition/`；小游戏平台装配在 `Platforms/WeixinMiniGame/` 与 `PlatformDependent/WeixinMiniGamePlayer/`——对照第03章后端图鉴，可以看到"平台=后端+配置资产"两层。

## 5. 选错的代价表（提前止损）

| 错误 | 发现时点 | 代价 |
|---|---|---|
| 移动项目用了 HDRP | 立即（不能运行） | 换 URP，资产重调 |
| PC 项目用内置 | 半年后想要定制 | 迁移 URP，shader 重写（内置 CG 语法→HLSL/URP 结构） |
| 用 URP 但靠"内置管线教程"写 shader | 当场 | 二套 API 记忆混乱，写成"混血 shader"报错 |
| 中途 URP→HDRP 追求画质 | 中期 | 光照单位重调+后处理重配+材质重验证 ≈ 重做美术管线 |
| 小游戏项目忽视首包约束 | 发布时 | 减包体 = 砍资产重做优化 |

**第09章将验证**：SRP 的"管线即 C# 包"正是消灭"内置管线不可改"遗憾的架构答案。

---

## 小结

- 内置=祖宅（维护模式）；URP=全平台主力（移动/小游戏一线）；HDRP=PC/主机高端线（物理光照世界观）；
- 移动 → URP 是铁律（HDRP 不可运行而非慢）；
- URP 与 HDRP 是**世界观差异**（抽象 vs 物理单位），资产不通用、选型不可逆；
- 团结平台变体 = 同一 URP + 平台配置（小游戏/车机/鸿蒙），分层架构的胜利；
- 选型是第一架构决策——按最终画面目标定，中途切换≈重做。
