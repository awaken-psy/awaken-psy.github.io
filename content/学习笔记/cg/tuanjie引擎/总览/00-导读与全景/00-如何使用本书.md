## 1. 渲染是什么：一句话的全景

实时渲染的本质可以用一句话概括：

> **每秒钟，CPU 和 GPU 协作 60 次（或更多），把一个由三角形和材质描述的虚拟世界，转成一张发给显示器的二维彩色像素阵列。**

这一句话里藏着本书要讲的全部内容：

- "三角形和材质描述的虚拟世界" → 场景、网格、材质系统（第03、04、05章）
- "CPU 和 GPU 协作" → 引擎架构、剔除、提交、多线程渲染（第03、04章）
- "转成二维像素" → 图形管线、光栅化（第02章）
- "彩色" → 光照、色彩空间、后处理（第06、11章）
- "每秒60次" → 帧率、性能优化（第12章）

## 2. 为什么"重原理、少代码"

图形编程有个特点：**API 会过时，原理不会**。

- Direct3D 11 的 API 和 Vulkan 的 API 长得完全不一样，但它们背后的"三角形 → 像素"原理是一样的；
- 内置管线（Built-in）和 URP 的 C# 代码完全不同，但"前向渲染"的原理是一样的；
- 读懂了原理，换任何引擎、任何 API，你都能在一周内上手；只背 API，换一个版本就要重新学。

所以本书刻意**不贴大段源码**。取而代之的是：

1. 用图和类比建立直觉；
2. 用公式把直觉精确化；
3. 用"源码指引"告诉你这个概念在 Tuanjie 引擎源码的哪个目录，方便你某天想验证时能自己找到。

## 3. 本书结构：四个阶段

```
阶段一：地基（00~02章）
  渲染全景 + 数学 + GPU管线 —— 建立完整的心智模型
  
阶段二：引擎怎么做（03~05章）
```

**强烈建议按顺序读到第03章**。前两章是地基：如果连"视锥体"、"齐次裁剪空间"都不清楚，后面引擎章节会处处卡壳。

## 4. 新手三大误区

### 误区一：把渲染当"黑盒设置学"

> "调一个参数，看看画面变化，记住效果" —— 这是最慢的学习方式。

渲染系统的参数之间是**强耦合**的：改了阴影分辨率会影响性能，改了 HDR 会影响后处理，改了渲染路径会影响所有 Pass。死记参数组合就像背棋谱，而理解原理就像懂棋理。

### 误区二：一上来就读引擎源码

渲染源码是全世界最复杂的软件层之一。Tuanjie 的 GfxDevice 有几十万行 C++，URP 有几百个 Pass 文件。没有概念地图就冲进去，只会迷路。

正确的顺序是：**概念 → 单点验证 → 局部阅读 → 全局阅读**。本书的目标是带你完成前两步，并给你第三步的地图。

### 误区三：跳过数学

渲染 90% 的"魔法"其实是三样数学：**向量点积/叉积、矩阵变换、渲染方程**。它们都不难——向量就是三个数，矩阵变换就是"乘法打包"，渲染方程就是"能量的加法"。第01章会用最平实的方式把它们讲透，请别跳过。

## 5. 阅读工具建议

- **Obsidian**（推荐）：笔记本身就在你的知识库目录下，公式（LaTeX）和流程图（Mermaid）直接渲染；
- **配合引擎**：每章的"源码指引"都指向本地源码仓库 `C:\Users\chang.wei\cw\tj`，读累了理论可以打开目录感受一下真实规模；
- **配合 Frame Debugger**：学完第02章后，建议你打开引擎的 Frame Debugger，对照每个 Pass 观察理论如何落地——这是"单点验证"最有效的手段。
