## 1. 只画直接光的画面为什么"假"

把第06章的像素公式拿回来，砍掉环境项：

$$
L = \sum_i f(\mathbf{l}_i, \mathbf{v})\, E_i \cos\theta_i \qquad \text{（只有直射）}
$$

**缺的东西**：红墙旁边的地面没有那片红色反弹光；室内只有窗光直射的一条，墙角全黑；阴影区漆黑一片（现实中影子是被环境反弹光洗亮的）。

第01章"渲染方程"的积分项 $L_{in}(\mathbf{l})$ 其实包含**别人反射出来的光**——这是**递归**：

$$
L_{in}(P \leftarrow \mathbf{l}) = L_e(Q) + L_{reflected}(Q), \quad Q = \text{沿 } \mathbf{l} \text{ 撞到的表面}
$$

**全局光照（Global Illumination, GI）** 就是解这个递归：光在场景中多次反弹的运输。**离线渲染**（电影/烘焙）可以真的慢慢追踪反弹；**实时**必须用近似与预计算组合。

## 2. 实时 GI 的三路解法光谱

$$
\text{间接光} = \underbrace{\text{漫反弹（低频）}}_{\text{可预计算/低频表达}} + \underbrace{\text{镜面反弹（高频）}}_{\text{只能局部近似}}
$$

按"预计算 vs 运行时"与"静态 vs 动态"，行业三大家：

### 2.1 烘焙GI

**思想**：静态场景的反弹光**离线算好**，存成图/系数，运行时只查询。
- **Lightmap**：静态表面的反弹结果烘成贴图（第02篇）；
- **Light Probe**：动态物体所在位置的反弹光烘成 SH 系数（第04篇）；
- 优点：运行时几乎免费、质量极高（离线可以多反弹）；
- 缺点：只能静态（动一个桌子要重烘）、占内存（第02篇算账）、动态物体插值感。

### 2.2 实时低频 GI（探针/传播/场类）

**思想**：把"反弹光"在**粗粒度体素/探针场**里运输，每帧更新（低频所以可行）。
- LPV/DDGI/VXGI 等学术族谱；主机届流行 DDGI 类探针网格；
- **TuanjieGI（团结自研）**：SDF+光步进的探针式 GI（第05篇主角）；
- 优点：支持动态场景（开关门、移动光源）；
- 缺点：质量受粒度限制、GPU 成本实时花。

### 2.3 屏幕空间补充（SS 系列）

**思想**：从当前画面可见信息"猜"反弹——SSAO/SSR/SSGI。
- 优点：无需烘焙、对动态完美、实现直接；
- 缺点：**只有屏幕里有的信息**（屏幕外的反弹体不存在）；
- 定位：永远是"补丁"，不是主力。

## 3. 产品名字对照表（团结/Unity 生态）

| 技术 | 引擎产品名 | 属于哪路 |
|---|---|---|
| 烘焙光照贴图 | **Progressive Lightmapper**（CPU/GPU） | 烘焙 |
| 环境探针 | Ambient Probe（天空 SH） | 烘焙/实时 |
| 光照探针 | Light Probe Group | 烘焙 |
| 反射探针 | Reflection Probe（Baked/Realtime） | 烘焙/实时 |
| 阴影遮罩 | Shadowmask / Distance Shadowmask（第03篇） | 混合 |
| 实时 GI | **TuanjieGI**（团结新增）/ Enlighten（老技术，已淘汰于新项目） | 实时 |
| 屏幕空间 | SSAO / SSR / SSGI（管线可选） | 屏幕空间补丁 |
| 体积 | Volumetric Fog（含环境散射） | 体积近场 |

**历史小注**：Unity 传统上的实时 GI 是 Enlighten（预计算辐射传输+运行时运输），2020 后从新项目逐步退役；团结引擎的答案是自己写的 **TuanjieGI**（SDF 基础）——这是团结对渲染体系最大的自有贡献，第05篇专门讲。


## 小结

- 递归的 $L_{in}$ 是 GI 本质：反弹光的运输；
- 漫反弹低频可预存，镜面反弹高频只能局部近似；
- 三路：烘焙（免费但静态）、实时低频（动态但粗）、屏幕空间（完美适配但只见屏幕）；
- 团结生态：Progressive Lightmapper + Probe 家族 + **TuanjieGI**（自有实时 GI）。
