# 03 - 抗锯齿：MSAA、FXAA、SMAA、TAA

> 阅读时间：约 40 分钟
> 关键词：锯齿成因、MSAA、FXAA、SMAA、TAA、速度缓冲、Ghosting

---

## 你将学到什么

- 锯齿的三种类型与各自成因
- MSAA：硬件采样抗锯齿的原理与适用面
- 后处理三剑客：FXAA（快而糊）、SMAA（精而贵）、TAA（免费的午餐+暗税）
- TAA 的重投影机制与 Ghosting 之病

---

## 1. 锯齿不是一种病

**类型一：几何锯齿**——三角形边缘的二值覆盖（第02章光栅化："点要么全有要么全无"）。
**类型二：着色锯齿**——高频纹理/法线/材质在像素内的细节超出采样密度（远处棋盘闪、法线噪点、高光火蚁 fireflies）。
**类型三：时域锯齿**——亚像素细节随时间在帧间跳动（远处电线一闪一闪）。

| 技术 | 治什么 |
|---|---|
| MSAA | 仅几何锯齿 |
| FXAA/SMAA | 几何+部分着色（后处理近似） |
| TAA | 全部三类（时域采样累积） |

## 2. MSAA：硬件的"超采样边缘"

第02章埋的问题回收：光栅化每像素 1 个采样点二值覆盖 → 边缘锯齿。**MSAA（Multi-Sample AA）**：每像素 N 个采样点（4×/8×）判定覆盖——**但 PS 只跑一次**（中心），边缘像素按"覆盖比例"混合邻居色：

```
像素中心采样：颜色算一次
4个采样点覆盖：边缘像素 2/4 在三角形内 → 与背景 50% 混合 → 平滑边缘
```

- **治标精准**：边缘是"真混色"（亚像素几何信息），质量上乘；
- **只治几何**：着色锯齿（远处棋盘）纹丝不动——PS 仍是每像素一次；
- **成本**：几何阶段带宽×N（深度/颜色模板多份），PS 不变——**前向管线的天然搭档**（第08章前向四宝之一）；
- **延迟管线的尴尬**：G-Buffer 是"PS 的输出"——每个 MSAA 采样点都要有 G-Buffer = 带宽爆炸（第08章罪二）。

**URP 的 MSAA**：开关即用（移动端 2×/4× 仍是实惠选择——iOS TBDR 架构的 MSAA 近乎免费！第03章平台的补充知识：苹果 GPU 的 tile 内存让 MSAA 几乎白送）。

## 3. FXAA / SMAA：后处理的"猜"

**共同思想**：不增加采样，拿**最终图**做文章。

**FXAA（Fast Approximate AA）**：一 pass 找"局部亮度对比高的走向"（=大概的边），沿边做方向性模糊。**极便宜、极普及**；代价：细纹理、文字被误当边缘糊掉（"糊味"的来源）。

**SMAA**：三步（边缘检测→权重图→混合），有专门的边缘模式库（形状记忆），比 FXAA 准、比 MSAA 便宜（带宽固定）；文字/UI 场景的口碑选择。

**适用**：不能上 MSAA 的场景（延迟管线）、或 MSAA 治不了的着色锯齿。两者都**只是"近似修边"**——治不了时域锯齿。

## 4. TAA：时域的魔法与暗税

**思想**：单帧每像素 1 采样的预算下，**让多帧合起来"每像素 N 采样"**——每帧把采样点在像素内抖动（subpixel jitter，第02章的采样点位置人为偏移），然后**用运动矢量把上一帧的结果"重投影"到当前位置混合**：

$$
c_t(p) = \text{blend}\big( \text{thisFrame}(p),\ \text{history}(\text{proj}_{t-1\to t}(p)) \big)
$$

1. **抖动**：相机投影矩阵加亚像素偏移（第01章投影矩阵的"作弊"：多帧等效超采样）；
2. **速度缓冲**：逐像素存"这像素上一帧在哪"（相机+物体矩阵算出）——URP 的 Motion Vectors（深度+重投影）；
3. **历史混合**：$0.1 \times \text{new} + 0.9 \times \text{history}$（历史占比高=4~16 倍等效采样）。

**收益**：几何、着色、时域三病全治；**成本**：速度缓冲一 pass + 混合一 pass——**3A 与 HDRP 的默认选择，DLSS/FSR/STP 的时域底座**（AI 超分本质是"更聪明的 TAA"）。

### 4.1 TAA 的三宗罪（暗税）

**罪一：Ghosting（拖影）**。速度缓冲不准（新出现的像素没有正确的历史/遮挡关系变化），历史"鬼影"残留——快速移动角色后拖半透明残影。工程解法：**邻域截断**——历史颜色若偏离当前帧的邻域色域则裁剪，以及失败时降混合权重。

**罪二：细细节糊化**。高频细节（电线、栅栏）被历史"平均"掉——远处电线变成半透明。解法：render scale 降采样配合（先模糊后重建的 DLSS 反而更好）、对速度慢的像素加大权重。

**罪三：管线耦合**。需要所有 Pass 与抖动一致（阴影/速度/透明都要知道 jitter）——**这就是内置管线没有好 TAA、SRP 才有**（管线级一致性只有可编程管线管得住）。

> ⚠️ **TAA 与透明**：透明物体通常没有速度缓冲（引擎近似）→ 透明层 TAA 质量差——粒子特效在 TAA 下"果冻感"是常见反馈，特效师要给粒子**调 alpha 与大小**补偿。

## 5. 选型速查表

| 场景 | 推荐 | 理由 |
|---|---|---|
| iOS 移动 | MSAA 4× | TBDR 白送（几乎免费） |
| 安卓中端 | MSAA 2× 或 FXAA | 带宽与兼容 |
| PC 前向 | MSAA 8× / TAA | 精度或全面性 |
| PC 延迟（HDRP） | TAA/DLSS | MSAA 不可行（G-Buffer 带宽） |
| 文字/2D 重 UI | SMAA（或关） | FXAA 糊字 |
| 快节奏竞速/电竞 | **关 TAA** 用 MSAA/FXAA | Ghosting 拖影对竞技致命 |

> 📁 **源码指引**：URP 的 TAA 实现 `Packages/com.unity.render-pipelines.universal/Runtime/Temporal/`（重投影与截断）与 `Shaders/PostProcessing/*.shader` 的 SMAA 族；MSAA 的 GfxDevice 状态：`Runtime/GfxDevice/GfxDeviceTypes.h`（多重采样数）与 RT 创建（`RenderTexture.cpp` 的 msaa 参数）；速度缓冲：URP 的 ObjectVelocity/Depth 相关 pass。

## 小结

- 锯齿三型：几何（覆盖）、着色（采样密度）、时域（帧间跳变）；
- MSAA 硬件治几何：前向好搭档、延迟的天敌、iOS 白送；
- FXAA/SMAA 是后处理近似：便宜、治不了时域；
- TAA 用抖动+速度缓冲+历史混合把三病全治——代价是 ghosting、细节糊、管线强耦合；
- DLSS/FSR/STP 是"更聪明的 TAA"（AI 重建历史）。
