# 02 - 光栅化与重心插值

> 阅读时间：约 30 分钟
> 关键词：光栅化、重心坐标、覆盖率、2x2 像素块、导数

---

## 你将学到什么

- 光栅化在做什么：三角形的"填色算法"
- 重心坐标：插值的数学基础
- GPU 并行模型：2×2 像素块与 quads
- 屏幕导数（ddx/ddy）：光栅化机制带来的意外能力

---

## 1. 光栅化：从几何到像素的"点阵打印机"

光栅化回答一个看似简单的问题：

> **"这个三角形，盖住了屏幕上哪些像素？"**

直觉的答案是把三角形内部所有像素填色。但像素不是一个"点"，而是一个**有面积的小方格**——三角形边缘穿过像素方格时，只盖住半个格子怎么办？

GPU 的主流策略是**采样点规则（point sampling）**：每个像素中心发射一个采样点，在三角形内 → 覆盖；不在 → 不覆盖。边缘锯齿由此而生（点要么全有要么全无），抗锯齿 = 每像素多个采样点（MSAA，第11章）。

```
三角形边缘经过像素网格：

  ┌─┬─┬─┬─┐        ● = 采样点在三角形内（点亮）
  │●│●│●│ │        ○ = 在外（不点亮）
  ├─┼─┼─┼─┼─┐
  │●│●│●│○│ │      边缘出现"锯齿"：
  ├─┼─┼─┼─┼─┤      —— 本质是二值覆盖
  │●│●│○│○│○│       丢失了"半覆盖"信息
  └─┴─┴─┴─┴─┘
```

**硬件的暴力美学**：光栅化单元拿屏幕空间三个顶点，用**增量计算（forward differencing）**沿扫描线推进——每移动一个像素只需加法，无需重复算边函数。配合 2×2 像素块的粗粒度并行，一块顶级 GPU 每秒能测试上百亿个像素×三角形的覆盖关系。GPU 名字里的"Graphics Processing"首先是干这个的。

## 2. 重心坐标：像素在三角形里的"比例尺"

### 2.1 定义

屏幕三角形顶点 $A, B, C$，内部点 $P$。重心坐标 $(\alpha, \beta, \gamma)$：

$$
P = \alpha A + \beta B + \gamma C, \qquad \alpha+\beta+\gamma = 1
$$

几何意义是**面积比**：

$$
\alpha = \frac{\text{Area}(PBC)}{\text{Area}(ABC)}, \quad \beta = \frac{\text{Area}(APC)}{\text{Area}(ABC)}, \quad \gamma = \frac{\text{Area}(ABP)}{\text{Area}(ABC)}
$$

$P$ 越靠近顶点 $A$，$\alpha$ 越接近 1。任何顶点属性（UV、法线、颜色）都按同一组权重混合：

$$
\text{attr}(P) = \alpha\, \text{attr}_A + \beta\, \text{attr}_B + \gamma\, \text{attr}_C
$$

（记得上一篇的透视校正：硬件实际按 $\frac{1}{w}$ 加权做这个混合。）

> 💡 **类比**：重心坐标是三角形的"内部 GPS"——不管什么属性（温度、颜色、UV），只要知道三个角的值，就按"离谁近、占多少"混合。

### 2.2 重心坐标的另两个用途

- **三角形内测试**：$\alpha,\beta,\gamma \ge 0$ 同时成立 ⇔ 点在三角形内。光栅化硬件的覆盖测试本质就是解这个不等式组（用边函数 edge function 三次叉积式判断）；
- **表面参数化**：UV 坐标本质是把三角形"重心比例"映射到纹理的 2D 坐标，光栅化期间逐像素插值 UV → PS 里用来采样纹理。

## 3. GPU 并行模型：一切为了 2×2

一个对理解 GPU 行为极重要、但新手常常不知道的事实：

> **像素着色器永远以 2×2 像素块（quad）为单位调度，哪怕三角形只覆盖其中 1 个像素。**

为什么？因为大量效果需要知道**相邻像素的差异**（导数）——最典型的是**纹理 mip 选择**：物体很远时，屏幕上 1 像素跨越纹理上很多纹素，必须降级采样（下一篇详述）。算"屏幕 1 像素对应纹理多少纹素"，需要 UV 沿屏幕 x/y 的导数：

$$
\frac{\partial u}{\partial x}, \frac{\partial v}{\partial x}, \ldots
$$

GPU 的实现简单粗暴：quad 内 4 个像素各自算完 UV，拿相邻像素的 UV **相减**即得数值导数。

**代价（Overdraw 的隐藏放大器）**：如果 quad 里只有 1 个像素被覆盖，其余 3 个仍然执行 PS——**白干 75%**。细长的三角形（电线、链条、草地草叶）经常出现"1 个 quad 服务 1 个像素"的极端浪费。这解释了一条著名性能法则：

> **三角形越小越细，光栅化/着色效率越低；4 像素以下的三角形，quad 利用率暴跌。**

实践中（第12章）：草和电线能用面片合批、能用顶点通道替代细三角形的，尽量别铺满小三角形。

## 4. 屏幕导数：光栅化送的"外挂"

`ddx` / `ddy`（HLSL；GLSL 为 `dFdx`/`dFdy`）读取上述数值导数。常见用途速览：

| 用途 | 原理 |
|---|---|
| **Mipmap 选择（硬件自动）** | UV 导数 → 远处自动降采样 |
| **屏幕空间边缘检测** | 深度/法线导数突变处 = 几何边缘 → 描边（卡通渲染轮廓线的常用法之一） |
| **程序化抗锯齿** | 用 UV 导数把棋盘/条纹函数按屏幕密度软化（aastep 技巧） |

> ⚠️ **quad 内分支的不一致**：若 quad 的 4 个像素在 shader 里走了不同分支（if/else），导数会拿隔壁像素"另一条分支"的值算差——**分支里用导数会产生垃圾**。同理，辅助像素（helper lanes）的存在也意味着"if 提前 return"并不能真的省时间。这是 shader 优化的知名陷阱。

## 5. 从光栅化到片元

光栅化每个被覆盖像素（含插值好的属性）产生一个**片元（Fragment）**——"候选像素"。为什么叫候选？因为它还不一定是最终画面：

- 可能输给深度测试（被更近的物体挡住）；
- 可能被模板测试拒绝；
- 可能被 scissor/viewport 边界裁掉。

活下来的片元才进入像素着色器染色，最后在输出合并阶段竞争/混合写入帧缓冲。**深度/模板测试发生在 PS 之前还是之后，是一个重要的性能开关（Early-Z）**——下一篇细说。

## 小结

- 光栅化 = 按采样点覆盖规则把三角形"点阵化"，天然锯齿，MSAA 靠多样本缓解；
- 重心坐标 = 三角形内部的比例尺，驱动一切顶点属性插值（硬件做透视校正）；
- PS 以 2×2 quad 调度 → 小三角形利用率低 + 分支破坏导数有效性；
- ddx/ddy = 数值屏幕导数，mip 选择、边缘检测的基础；
- 片元 = 候选像素，要过深度/模板测试才能"转正"。
