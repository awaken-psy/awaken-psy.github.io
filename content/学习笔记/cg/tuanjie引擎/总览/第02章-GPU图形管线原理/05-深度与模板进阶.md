## 1. 深度缓冲：格式与精度

深度缓冲的格式决定精度与带宽：

| 格式 | 位深 | 说明 |
|---|---|---|
| Depth16 | 16 bit | 老移动端/低成本；远处精度差 |
| Depth24 + Stencil8 | 24+8 | **桌面/移动最常见打包格式**（D3D 的 D24S8） |
| Depth32F | 32 位浮点 | 配合 Reverse-Z 的现代高精度方案 |
| Depth32F + Stencil8 | 32F+8 | HDRP/现代管线首选 |

回顾第01章：透视深度天然非线性、精度集中在近平面 → 远处 Z-Fighting；解法 = Reverse-Z + 32F（浮点在 1.0 附近密度最高，恰好嵌合双曲线）。

**两个必记结论**：
1. near/far 比值越大精度越差：`near=0.1, far=1000`（比值 10⁴）在 24 位下远处已相当拥挤。**能拉近 near 就拉近，能压近 far 就压近**；
2. 抄 Depth 相关代码前先确认当前管线是否 Reverse-Z（URP 在 PC/主机默认开）。

## 2. Depth Prepass：先画一遍"看不见的"

某些场景（尤其复杂 GPU 材质 + 复杂着色）会这样安排：

> **第一遍（Depth Prepass）**：全场景只画深度（PS 为空或禁用写入颜色），把深度缓冲"垫"好；
> **第二遍**：再画一遍完整着色——每个片元先过 Early-Z，被遮挡的**直接免 PS**。

适合场景：大量复杂 shader 但互相遮挡严重（植被、粒子重场景）。代价是几何提交两遍（顶点开销 ×2），因此它**不是免费午餐**，URP 里 `Depth Priming` / 内置 `Camera depthTexture` 模式就是这种取舍的开关。

## 3. _CameraDepthTexture：全屏深度"地基图"

现代管线几乎都会产出一张**只含深度的全屏纹理**（URP 的 `_CameraDepthTexture`，HDRP 的 depth buffer），它是一大批屏幕空间效果的地基：

| 效果 | 用深度干什么 |
|---|---|
| **软粒子** | 粒子片元深度 vs 背景深度差 → 边缘自动淡出（粒子插进地里/墙里的硬边消失了） |
| **屏幕空间雾** | 逐像素重建世界距离 → 按距离衰减雾浓度 |
| **水面深度差** | 水下物体离水面多远 → 决定水的折射/吸收 |
| **接触硬化阴影** | 采样深度 mipmap（Hi-Z）估计遮挡距离 → 面包屑式软影 |
| **边缘检测描边** | 深度突变 = 物体轮廓 |
| **SSR 屏幕空间反射** | 沿视线 ray-march 深度图找交点 |

**重建世界坐标**：有了深度 + 逆 VP 矩阵 + 屏幕像素坐标，可反解该像素的世界位置（逆变换回来）——上述所有效果的公共前置步骤：

$$
P_{world} = M_{invVP} \cdot \left( \text{ndc}(x, y, \text{depth}) \right)
$$

> 📁 **源码指引**：URP 的深度图生成 Pass 在 `Packages/com.unity.render-pipelines.universal/Runtime/Passes/`（DepthOnly / CopyDepth）；重建函数 `ComputeWorldSpacePosition`。引擎侧 CopyColor/CopyDepth 的 GfxDevice 支持在 `Runtime/Graphics/CopyTexture.cpp`。

**Hi-Z（Hierarchical Z）**：把深度图逐层取 min/max 建成 mip 链，ray-march 时可大步跳跃（上层 mip 粗查、细层精查），SSR/接触阴影的核心加速结构。也是现代 GPU Occlusion Culling 的硬件基础。

## 4. 模板缓冲：像素级"门票系统"

模板 = 每像素 8 位整数标签 + 一套可编程的测试/操作。它的心智模型：

> **先在像素上"盖章"，再决定哪些像素凭"票"入场。**

模板测试通用形式：

$$
(\text{Ref} \;\&\; \text{Mask}) \quad \text{CompareOp} \quad (\text{StencilBuf} \;\&\; \text{Mask})
$$

通过/失败后可对模板值执行操作（Keep/Replace/Invert/Incr/Decr…）。三个经典套路：

**套路一：物体描边**。Pass1 正常画角色并把可见像素写入模板；Pass2 沿法线膨胀的"外壳"只画**模板外**的像素 → 只留下轮廓。卡通渲染 NPR 的看家本领之一。

**套路二：镜面/传送门限定**。先画镜面框写模板；再画镜中世界，只在模板内可见 → 反射被精确限制在镜框里。

**套路三：延迟光照的 Volume 标记**。延迟渲染（第08章）里点光的影响范围是个球，把"在球内、在表面上"的像素 incr 标记，光照 Pass 只处理有标记像素——避免整屏都做点光积分。

> 📁 **源码指引**：模板状态抽象 `Runtime/GfxDevice/GfxDeviceTypes.h`（`StencilState`/`CompareFunction`）。URP 的 DrawObjects 设置 StencilState → GfxDevice 翻译到各 API。

## 5. 深度清除：别忘每帧重置

深度/模板是**持久缓冲**：帧与帧之间不清空 → 残留上一帧深度 → 一片物体神秘消失。每帧开头（或每个 RenderTarget 切换时）引擎都会 Clear（clearDepth=1 或 Reverse-Z 下 clearDepth=0）。Frame Debugger 里每个 Pass 头部的 Clear 项就是在干这个。自己写管线时（SRP 定制）忘记 clear 是 top 级 bug 来源。

## 6. 第02章总结：完整管线心智模型

```
IA(装配) → VS(顶点/蒙皮/位移) → 装配剔除 → 裁剪 → ÷w/视口
        → 光栅化(覆盖判定+重心插值, 2x2 quad)
        → [Early-Z 拦截] → PS(纹理+光照) → 输出合并(模板/深度/混合)
        → RenderTarget(RGBA16F HDR 或 LDR, + Depth/Stencil)
```

你现在可以独立回答：
- 一个像素的颜色是怎么来的（管线全程）；
- 为什么远处会闪（深度精度 + mip）；
- 为什么有的物体"白画了"（Overdraw / 无 Early-Z / 背后被墙挡）；
- 透明为什么贵（混合无 Early-Z、排序、多层）。

这份硬件心智模型将在引擎章节反复被引用——**引擎的每一层设计（剔除、合批、SRP Pass），本质上都是在给这条硬件流水线"喂更少、更对的食物"。**
