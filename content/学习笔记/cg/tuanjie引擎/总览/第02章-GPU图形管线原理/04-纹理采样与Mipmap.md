# 04 - 纹理采样与 Mipmap

> 阅读时间：约 35 分钟
> 关键词：纹理、纹素、过滤、双线性、Mipmap、Trilinear、各向异性、纹理压缩

---

## 你将学到什么

- 纹素的本质：离散的"颜色格子"与连续 UV 的矛盾
- 最近点/双线性/三线性/各向异性过滤：一层层消除的失真
- Mipmap：为什么必须"提前缩小"，内存代价 1/3
- 纹理压缩（BCn/ASTC/ETC）：移动与桌面不同的思路
- 纹理与带宽：为什么"纹理是 GPU 的第一口粮"

---

## 1. 纹素：网格化的颜色仓库

纹理不是"图片"，是一块**按行排列的纹素数组**。纹素与像素的区别值得刻在脑子里：

| | 像素 Pixel | 纹素 Texel |
|---|---|---|
| 属于 | 屏幕/渲染目标 | 纹理 |
| 坐标系 | 左上原点、整数格 | 左下原点、UV ∈ [0,1] 连续 |
| 单位 | 离散格子 | 离散格子，但被**连续地址**访问 |

矛盾在这里爆发：PS 里插值出的 UV 是**连续**的小数（如 $u=0.3729\ldots$），纹素仓库只有**整数**格。直接四舍五入取最近纹素（**最近点过滤 NEAREST**）会怎样？

- 放大时：一个纹素被重复使用 → 像素块状感（马赛克）；
- 缩小时：多个纹素被跳过 → **摩尔纹/闪烁**（屏幕 1 像素对应纹理 5+ 纹素时，采样点随机踩中格子里的"黑白条纹"，逐帧抖动即闪）。

## 2. 双线性过滤：小范围的加权平均

**双线性过滤（Bilinear）**：对 UV 小数坐标四周的 4 个纹素按比例加权：

$$
u_f = u \cdot W - 0.5 \quad \Rightarrow \quad i = \lfloor u_f \rfloor,\ \ f = u_f - i
$$

$$
\text{color} = (1-f)(1-g)\, T_{i,j} + f(1-g)\, T_{i+1,j} + (1-f)g\, T_{i,j+1} + fg\, T_{i+1,j+1}
$$

直觉：$f,g$ 是"离哪边更近"，把 4 个邻居按距离加权调色。放大的块状感 → 平滑渐变。**但它只看 4 个纹素**——缩小时的"跳格闪烁"完全没解决，反而更糟：远处的路面上 1 像素对应几十纹素，4 个代表不了几十个。

## 3. Mipmap：给"远处"准备好的缩略图

### 3.1 思想

与其让 GPU 临时平均几十个纹素（还得算出该平均多少个），不如**离线把缩略图全部做好**——这就是 Mipmap：

- 第 0 层：原始纹理 $W \times H$；
- 第 1 层：每 2×2 平均成 1 格 → $\frac{W}{2} \times \frac{H}{2}$；
- …直到 1×1。

每个"屏幕 1 像素 = 纹理 N 纹素"的场景，都有一层缩略图恰好让"1 像素 ≈ 1 纹素"。GPU 用 PS 的 UV 屏幕导数（上一篇 ddx/ddy）**自动选层**：

$$
\rho = \max\left(\left|\frac{\partial u}{\partial x}\right|, \left|\frac{\partial v}{\partial x}\right|, \left|\frac{\partial u}{\partial y}\right|, \left|\frac{\partial v}{\partial y}\right| \right) \quad \Rightarrow \quad \lambda = \log_2 \rho
$$

$\lambda$ 即理想 mip 层（可为小数）。

**内存代价**：

$$
\sum_{k=0}^{\infty} \frac{1}{4^k} = 1 + \frac{1}{4} + \frac{1}{16} + \cdots = \frac{4}{3}
$$

完整 mip 链只多花 **33%** 显存，换来的是几乎无闪烁。这是图形学里性价比最高的发明之一。

### 3.2 三线性

GPU 选层 $\lambda$ 带小数时，**三线性（Trilinear）**= 在第 $\lfloor\lambda\rfloor$ 层和第 $\lfloor\lambda\rfloor+1$ 层各做一次双线性，再按小数部分线性混合两次结果。消除"层切换跳变"。代价：8 纹素采样。

### 3.3 各向异性过滤

三线性有个盲区：它假设屏幕像素对应纹理里一个**正方形**区域。斜视角下（贴地看向远方）实际对应一个**细长条**——按正方形采样依旧糊（远处地面纹理糊成一片）。**各向异性过滤（Anisotropic）**沿"拉长方向"多次采样多个点（16x = 最多 16 次），斜视角清晰度巨大提升，现代 GPU 上代价已可接受（桌面近乎免费，移动端按档位考虑）。引擎纹理导入设置的 Aniso Level 0~16。

### 3.4 三种失真对照表

| 症状 | 原因 | 解药 |
|---|---|---|
| 放大马赛克 | NEAREST | Bilinear 起步 |
| 远处闪烁/摩尔纹 | 缩小时跳格采样 | Mipmap（必须） |
| 远近切换处跳变 | 只取整数层 | Trilinear |
| 斜视角远处糊 | 采样区域非正方形 | Anisotropic |

## 4. 纹理压缩：为显存与带宽而生

一张 4096×4096 RGBA32 的图 = 64MB 显存，还有每次采样都要付的**带宽**。真实游戏动辄上千张纹理，不压缩不可想象。关键约束：**GPU 必须不decode 整块就能随机采样**——所以 PNG/JPG 这类"整图压缩"不可用，需要**块压缩**：

- **桌面：BCn（DXT）家族**。BC1/BC3/BC5/BC7：4×4 块存 2 端点颜色 + 每纹素 2~4 bit 索引，压缩 4~8 倍，采样时硬件解。BC5 常用于存双通道（法线 xy，z 重建）；BC7 质量最高；
- **移动：ASTC**（全面取代 ETC2 的新标准，4×4~12×12 可选块，率损灵活）、**ETC2**（OpenGL ES 标配）。团结/Unity 的纹理导入按平台自动选 BC/ASTC/ETC2；
- **法线图的 DXT5nm**：法线贴图压普通 BC1 会"蓝通道糊"，引擎做法：xy 存 RG，z 重建（$z=\sqrt{1-x^2-y^2}$）。源码 `Runtime/Graphics/DXT5nm.cpp` 即此逻辑；压缩实现在 `DXTCompression.cpp`、`ETC2Compression.cpp`、`ASTC` 相关。

> 💡 **带宽视角**：4K 屏 + 大量纹理 + 60FPS 下，纹理带宽常是 GPU 第一瓶颈。压缩不只是省显存，直接省"每像素读取量"——很多时候压缩纹理**更快**。

## 5. 采样器状态：地址环绕

UV 出了 [0,1] 怎么办？**Wrap**（循环，平铺地面）、**Clamp**（边缘拉长，防 mip 渗色）、**Mirror**（镜像循环）。地砖不 seams 全靠 Repeat；天空盒拼接错误八成是 Wrap 用错。

> 📁 **源码指引**：引擎纹理系统在 `Runtime/Graphics/Texture.cpp`（Texture 基类）、`Texture2D.cpp`（上传/生成 mip）、`TextureFormat.cpp`（格式表）。GfxDevice 采样器与过滤抽象在 `GfxDeviceTypes.h`（`TextureSampler`：过滤、地址模式、各向异性档位）。Cubemap 见 `CubemapTexture.cpp`（第10章反射探针的基础）。

## 小结

- 连续 UV vs 离散纹素 → 需要"过滤"：Bilinear（放大）、Mipmap（缩小）、Trilinear（层间）、Anisotropic（斜视角）；
- Mipmap 自动选层靠 UV 屏幕导数（ddx/ddy），显存代价 1/3，收益巨大；
- 纹理必须**块压缩**（BCn/ASTC/ETC2）才能被 GPU 高效采样，法线有专门存法；
- 纹理是 GPU 的第一带宽大户，压缩同时省显存与带宽。
