# 05 Hi-Z 深度金字塔与屏幕步进

> 屏幕空间射线查询的加速结构。六级查询的 ① 级、屏幕空间镜面追踪（SSR 类）都用它。

## 1. 解决什么问题

屏幕空间查询要沿画面推进一条射线，找"射线走到哪里进入了已画表面的背后"。逐像素比较深度不可行：一条射线在 1080p 上可横跨上千像素，每帧又有几十万条射线。Hi-Z（Hierarchical Z / depth pyramid）把这一过程压缩到几十步。

它与 [SDF 球体步进](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/01-背景知识/04-SDF与球体步进.md)是同一思想在 2D 的版本：**空旷处大步跳过、接近表面自动减速**——只是安全步长的来源从"3D 距离场读数"换成了"屏幕区域最近表面"。

## 2. 构造：深度图的 mip 链，取"最近"而非平均

把深度图当纹理逐级缩半：

- 第 0 层 = 原始深度图（如 1920×1080）；
- 第 k+1 层每格取 **2×2 子块中离相机最近的表面深度**（正 Z 约定取 min；倒序 Z 引擎取 max——方向相反，本质相同）；
- 缩到 1×1 为止，1080p 约 11 层。

粗格子的语义：这块 $2^k \times 2^k$ 像素区域内**最近的表面有多近**——一个保守下界。

模块对接（源码事实）：URP 的深度金字塔以 `Texture2DArray` 传入 `ViewContextURP.depthPyramid`，逐层偏移表在 `GIStructuredBuffer<int2> depthMipOffset`；`SampleHZB(mipLevel)` 读 `depthMipOffset.read(mipLevel)` 定位后采样（TuanjieGIForURP.h）。

## 3. 步进规则

1. 射线投到屏幕坐标，进入金字塔（从合适粗细的层开始）；
2. 当前层比较：若射线在这格覆盖的整个区间内都比"格内最近表面"更靠近相机——这块里不可能穿过任何东西——**整格跳过**；
3. 跳不过就降一层细的，原位重试；
4. 细到单像素还跳不过：射线在该像素进入表面背后——**命中候选**；
5. 候选不直接采信：按运动矢量带回上一帧核对深度，通过才接受——这属于 ① 级查询自身流程（见 [../04-屏幕层/03-六级查询与流压缩](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/03-六级查询与流压缩.md)）。

$$
\text{整格跳过}：z_{\text{ray}}(\text{整段}) < \min z(\text{块})
\qquad
\text{命中}：z_{\text{ray}} \geq z(\text{像素})
$$

粗层跳不过 ≠ 命中；命中只在最细层判定。

## 4. 与球体步进对照

| | SDF 球体步进 | Hi-Z 屏幕步进 |
|---|---|---|
| 存什么 | 3D 空间"离最近表面多远" | 2D 区域"离相机最近表面多近" |
| 保守下界 | 读数 ≤ 真实距离 | 粗格值 = 块内最近表面 |
| 安全跳过 | 半径 d 球内无表面 | 整格区间射线都在所有表面之前 |
| 接近表面 | 读数变小、自动减速 | 层级变细、自动减速 |
| 作用域 | 任意 3D 射线 | 仅屏幕内方向 |

## 5. 成本与局限

**成本**：构建 = 每层一次 2×2 归约下采样（1080p 约 10 个极快 pass）；显存 ≈ 额外 1/3（$\sum 4^{-k}$）；步数从千级降到几十级。

**局限**（也是屏幕空间查询的天花板）：

1. **只记第一层**：深度图只存每条相机射线最先撞到的表面；被挡住的几何不可见，射线进入可见表面背后后没有可信答案；
2. **只在画面内**：屏幕外、这一帧没画的东西一律答不了；
3. **深度非线性**：深度多按 1/z 存储，远处精度低，比较需阈值吸收误差或先线性化。

## 6. 谁在用它

TuanjieGI 的 ① 屏幕空间查询（命中后读上一帧最终画面——一份命中约等于接近两反弹的信息）与屏幕空间镜面追踪 `ScreenTraceSpecular`（[../04-屏幕层/07-屏幕空间镜面追踪](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/07-屏幕空间镜面追踪.md)）。SSR/SSAO 等外部系统同样共用这种结构。
