# 03 硬件光追后端（RayTracing/）

> 源文件：`RayTracing/GIHWRTScene.h/.cpp`、`RayTracing/InlineRayTracer.h`、`RayTracing/RayTracer.h`、`RayTracing/RayIntersectionTuanjieGI.h`、`RayTracing/GIHWRTMesh.h`、两个 `*Visualize.h`
> 作用：六级查询的 ④⑤ 级——有硬件光追的平台上用真三角形求交替换距离场 ②③，语义从"近似命中"升级为"精确命中"；取色依然读面片。
> 前置阅读：[../04-屏幕层/03-六级查询与流压缩](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/03-六级查询与流压缩.md) §1（六级总表与替换规则）

## 1. 启用条件（源码事实）

```cpp
// RayTracer.h HasValidData()（InlineRayTracer.h 同构，判据换 supportsInlineRayTracing）
sdfScene.sparseSDF.sdfMeshMappingGPUBuffer.usedSize > 0
&& accessor.HasValidData()
&& GetGraphicsCaps().supportsRayTracing          // InlineRayTracer: supportsInlineRayTracing
&& hwrtScene.hwrtSceneEnable
```

启用即**替换** ②③（QuadTraceSH mask 清 kSDF/kCDF 位，见 [../04-屏幕层/03-六级查询与流压缩](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/03-六级查询与流压缩.md)）。`enableHardwareRayTracing` 进 FrameContext 由 HDRP 接入层设置（URP 无此字段）。

## 2. GIHWRTScene：加速结构管理

**当前实现直接使用引擎的 `RayTracingAccelerationStructure`**（初始化注释 "Reference: HDRTASManager::Initialize()"）；文件里另有一整套自建 native TLAS 的代码（`UpdateMeshesAndRenderers`、`HWRTVerticesAllocator` 等）被 `#if 0 // TODO: build native tlasBuffer` 整块禁用——读代码时忽略。

- **实例剔除配置**（Initialize，.cpp）：
  - subMeshFlags：opaque = Enabled|ClosestHitOnly；transparent = Enabled|UniqueAnyHitCalls；alphaTested = Enabled；
  - 双面材质：keyword `_DOUBLESIDED_ON`（`checkDoubleSidedGIMaterial=true`）；
  - 队列：alphaTest 2450–2500（`_ALPHATEST_ON`）、transparent 2900–3100（`_SURFACE_TYPE_TRANSPARENT`）；
  - requiredShaderTags：`RenderPipeline=HDRenderPipeline`；deniedShaderPasses：Decal 系列；
  - GI 实例掩码 `instanceMask = 1<<0`（路径追踪掩码 `1<<1` 的行被注释）。
- **剔除**（SetupCullingData）：cullingMode=Sphere、**半径 1000**、附加 `EnableLODCulling|IgnoreReflectionProbes`。
- **每帧**（UpdateFrame）：`enableHardwareRayTracing && hwrtSceneEnable` → `Reset(); Cull(camera); Build();`，否则 `ReleaseResources()`。BLAS/TLAS 的拆分由引擎 `RayTracingAccelerationStructure` 内部管理（本文件不显式分建）。
- **顶点/三角形缓冲**（TrackedGPUBuffer 增量同步）：`GIHWRTVertex{position, u, normal, v}`（交错）、`GIHWRTTriangle{uint3}`、`GIHWRTRendererData{worldMatrix, HWRTMeshID, firstVertex, firstTriangle, facetMeshRendererID}`。

## 3. InlineRayTracer（④ 级）

```cpp
include("UnityRayQuery.cginc");
add_require_feature("inlineraytracing");
RayQuery<OC_RAY_FLAG_NONE> query;
query.TraceRayInline(hwrtScene.rayAccelStruct, OC_RAY_FLAG_NONE, 0xff, ray);
while (query.Proceed()) {}
$if (query.CommittedStatus() == OC_COMMITTED_TRIANGLE_HIT) {
    Float t = query.CommittedRayT();       // 命中距离
    hitPosition = Origin + Direction * t;
}
```

命中后**不直接读三角形属性**，转 SDF 级联：`LoadNormal`（中心差分梯度）+ `LoadClusterObject`（≤4 模型）→ 面片 accessor 取色累加。`traceMaxDistance` 实取 `min(选项, fctx.maxDistance)`。

## 4. RayTracer（⑤ 级）

- `TraceRay(hwrtScene.rayAccelStruct, OC_RAY_FLAG_CULL_BACK_FACING_TRIANGLES, RAYTRACINGRENDERERFLAG_ALL, 0, 1, 0, ...)`——**剔除背面三角形**。
- 命中 payload `RayIntersectionTuanjieGI`（OC_BUILTIN_STRUCT 注册）：`{t, normalWS, positionWS, baseColor, emissive, directLighting}`——命中着色器可写入材质属性。
- 两条取色路径（permutation `UseRtInsteadOfFacet`）：
  - `false`（GI 默认）：SDF 级联查法线 + cluster 面片取色（与 InlineRayTracer 相同）；
  - `true`：**直接用光追返回的材质数据**（baseColor/emissive/directLighting，`GIRadiosityVisitor` 分支把 directLighting/π×factor、可乘 baseColor²、加 emissive）——不经面片，用于"面片还没铺到"的场景验证。
- `traceMaxDistance` 默认 1000。

## 5. 命中后的共同逻辑

④⑤ 命中后回 SDF 级联取法线与 cluster（`hitCascadeIndex >= 0` 判据）、遍历 ≤4 个登记模型，`accessor->GetColor(...)` 加权累加，`w ≥ 0.9` 提前结束，`hitRadiance = sum.xyz/sum.w`——**与③级 CascadedSDFTracer 的取色代码同构**。换几何后端不换光照数据：距离场与光追共享同一套面片 Radiosity。

## 6. 可视化（编辑器）

- `InlineRaytracingVisualize`：ray query 全屏打射线，按 accessor 输出 primitive index 灰度 / SDF 法线 / 面片色；miss 白色。
- `RaytracingVisualize`：`dispatch_ray(..., "TuanjieGIDXR")`、`ray_max_recursion_depth(1)`；按 accessor 类型开全局关键字（`TJGI_RT_PRIMITIVE_INDEX / TJGI_RT_BASE_COLOR / TJGI_RT_NORMAL / TJGI_RT_EMISSIVE / TJGI_RT_DIRECT_LIGHTING`）后 dispatch 再关掉。两者都只写 VisualizeRT，不参与光照。

## 7. 快速问答

**Q：inline ray query 和完整光追有什么区别？**
A：`TraceRayInline` 在任意 shader 阶段即时逐条查询（无需命中着色器），适合批量穿插在 compute 里；完整 `TraceRay` 走递归着色器管线、信息更全（可取材质属性）。本模块两者都在，按硬件能力二选一（`supportsInlineRayTracing` vs `supportsRayTracing`），`SWRTPipeline` 同时构造两个 tracer、`HasValidData()` 决定谁进链。

**Q：为什么光追命中还要回距离场查法线？**
A：面片图集的取色与法线数据挂在 cluster→模型→面片 的链条上；复用这条链意味着"换几何后端，不换光照数据"。光追只把命中点定准，光照语义完全由世界层面片系统决定。

**Q：透明物体参与 GI 光追吗？**
A：参与但方式不同（transparent = UniqueAnyHitCalls）；GI 侧的透明镜面输出另走 HDRP 的 `updateForTransparency` 路径（[02-管线接入URP与HDRP](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/05-集成与工程/02-管线接入URP与HDRP.md) §4）。
