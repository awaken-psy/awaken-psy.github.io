# 04 增量更新与事件机制（Utility/ 的基础设施）

> 源文件：`Public/TuanjieGIEvent.h`、`Utility/SceneWatcher.h`、`Utility/TrackedList.h`、`Utility/StableTrackedList.h`、`Utility/SceneTrackedList.h`、`Utility/UpdateList.h`、`Utility/SpanAllocator.h`、`Utility/TSpanArrayAllocator.h`、`Utility/GPUItemAllocator.h`、`Utility/MaxNPriorityQueue.h`、`Utility/TrackedGPUBuffer.h`、`Utility/TrackedGPUTexture3D.h`、`Utility/TransformTracker.h`、`Utility/GPUFilter.h`、`Utility/BCCompression.h/.cpp`、`Utility/DispatchMemset.h`、`Utility/FullUpdateGPUBuffer.h`、`Utility/VRAMRef.h`
> 作用：TuanjieGI "静态世界 + 动态更新" 的全部基础设施——场景对象变化怎么感知、CPU↔GPU 怎么增量同步、GPU 槽位怎么分配回收。
> 前置阅读：[01-TuanjieGIManager与帧调度](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/05-集成与工程/01-TuanjieGIManager与帧调度.md)（三段事件与 watcher 宏）

## 1. 事件系统（TuanjieGIEvent.h，全文 41 行）

```cpp
template<typename... Args> class TuanjieGIEvent {
    std::function<void(Args&&...)> Prototype;   // 回调原型
    // AddListener 返回一个"注销函数"（lambda 捕获节点指针，调用即 UNITY_DELETE 节点）
    // Emit 按注册顺序（List 插入序）依次调用，无优先级
};
struct TuanjieGIListener { /* RAII：析构时自动调 remove() */ };
```

- 监听器节点持有回调，链表串联；**Emit 顺序 = 注册顺序**（因此子系统构造顺序决定执行顺序——SWRTPipeline 的成员声明顺序即帧内执行顺序）。
- `TuanjieGIListener` RAII 包装让监听者随生命周期自动注销（SWRTPipeline 里大量 `TuanjieGIListener xxx = ...AddListener(...)` 成员）。
- 注意：Emit 期间增删监听器**没有保护**（源码如实记录，未见防护）。

## 2. 场景监视：SceneWatcher 体系

- `SceneWatcher<T>`（每类场景对象一个，由 `TUANJIE_GI_DECLARE_WATCHER` 宏批量声明在 TuanjieGIManager 里）：
  - 三个事件 `Add/Remove/Update` + 一个 `TrackedList<T*> objectsTracker` + 一个 `UpdateList<T*> objectsUpdateList`；
  - `NotifyAdd/NotifyRemove/NotifyUpdate`：**先更新 tracker，成功才发事件**。
  - MeshRenderer 特化在编辑器额外维护 `rendererToName`（确定性排序用）。
- `UpdateList<T>`：极简动作队列——`unordered_map<T, 动作位>`；动作枚举 `kRemove/kUpdate/kAdd/kAddAndUpdate`；重复通知按位或合并，Remove 直接覆盖。**每帧末尾 `ClearChange()` 清空**（TuanjieGIManager::ExecuteGIPipeline 第 5 步）。
- `SceneTrackedList<T, Validator>`：把 SceneWatcher 事件桥接进 TrackedList，构造时可把已存在的对象批量加入。

## 3. ID 体系：TrackedList 与 StableTrackedList

| | `TrackedList` | `StableTrackedList` |
|---|---|---|
| ID 稳定性 | **不稳定**：Remove 用末尾元素填洞（被搬的记进 `itemsToMove`） | **稳定**：`TSpanArrayAllocator` 分配/释放槽位 |
| 增量同步 | move + update 两类变更都要传 | 只需 update |
| 底层 | vector + map 双向映射 | placement-new 数组（2 倍扩容 memcpy） |

GPU 侧槽位即"对象 ID"——面片渲染器缓冲、SDF 渲染器缓冲都用它（`GIFacetMeshRenderersTracker`、`GISDFRenderersTracker`）。

## 4. 分配器

- **`SpanAllocator`**（CPU 连续区间）：best-fit（最小剩余空间优先）空闲块查找；`Free` 只进 `m_PendingFrees` **延迟合并**（需要时 `MergeFreeSpans` 排序+合并相邻+回收尾部）；不够就从 `m_TotalSize` 尾部扩。`AllocDisContinue(n)` 分配 n 个不连续单元。SDF 的 brick 映射缓冲（`sdfMeshMappingAllocator.Allocate(mappingCount)`）用它。
- **`TSpanArrayAllocator<T>`**：在 SpanAllocator 上管理对象生命周期（placement new / 显式析构）。
- **`GPUItemAllocator`**（GPU 槽位）：freelist 式——`atomicCounterBuffer` 做栈顶、`interlocked_add(+1)` 分配、`(-1)` 回收；**注意源码注释：alloc 与 free 不能在同一 pass**。`pendingToFree/freePending/resetPendingCounter` 三段式延迟释放（级联砖的释放走它，[../03-世界层/03-级联距离场GISDFExt](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/03-世界层/03-级联距离场GISDFExt.md) §5.1）。`resize` 时 `DispatchMemset` 在 GPU 上清计数器。
- **`MaxNPriorityQueue<T>`**：维护最大 N 个元素——`std::priority_queue`（Compare=greater → **堆顶是已选中的最小者**）；`add(e)`：未满直接进；满了且 e 比堆顶大则挤出堆顶。面片调度用它选"最值得更新的 N 个面片"（[../03-世界层/02-面片系统GIFacet](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/03-世界层/02-面片系统GIFacet.md) §3.2）。

## 5. CPU↔GPU 增量同步

- **`TrackedGPUBuffer<T>` / `TrackedGPUStructuredBuffer<T>`**：与 TrackedList/StableTrackedList/vector 配对的镜像缓冲。`resizeGPUBuffer`（`NextPowerOfTwo` 扩容）→ dirty 时先试全量 `ApplyFullUpdates`，否则 **`ApplyDiff`**：
  1. `ApplyDiffMoves`：move shader 把 `data.y → data.x`（旧槽 → 新槽）复制；
  2. `ApplyDiffUpdates`：update shader 按 index 写更新项。
- **`TrackedGPUTexture3D<T, brickSize=8, R8_UNORM>`**：稀疏 3D 纹理——brick 化（8³ 体素/砖）、`NextPowerOfTwo` 求砖数、log2 分解到 x/y/z 三个方向的 `shift/mask`（线性砖号 ↔ 3D 坐标）、扩容用 `GetResizeShader` 在 GPU 内搬旧纹理、`ApplyBatchUpdates` 按 brick 批量写。SDF 精场/级联场都靠它。
- **`GPUFilter.h`**：GPU 并行过滤/压缩框架——`NaiveGPUFilter`/`GroupedGPUFilter`，模式 1-to-1、1-to-N（fixed/loop/custom）、N-to-M；内部 `interlocked_add` 块内压缩、objectBuffer 前 3 个 uint 作 indirect args。六级查询的流压缩、级联生成的 kernel 链、直接光过滤全用它。
- 其余小件：`DispatchMemset`（GPU memset 命令）、`FullUpdateGPUBuffer`、`VRAMRef<T>{baseAddr, offsetAddr}`（VRAM 内原子读写抽象）、`BCCompression`（BC7/BC5/BC6H/BC4 编码器，面片图集压缩用，见 [../03-世界层/02-面片系统GIFacet](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/03-世界层/02-面片系统GIFacet.md) §4）。

## 6. TransformTracker：变换变化感知

`TransformTrackerForComponent<T>`：注册进 Unity 的 `TransformChangeDispatch`（`RegisterSystem(name, kInterestedInGlobalTRS)`）；监听 SceneWatcher 的 Add/Remove 来登记/取消感兴趣的对象；`onUpdate`（挂在 `onBeforeUpdateFrame`）里 `GetAndClearChangedTransforms` 拿到本帧变化的 Transform 列表，逐个查组件调 `component->UpdateForTuanjieGI()`。TuanjieGIManager 持有 `meshRendererTransformTrakers`——**静态物体被移动时由此触发其面片/SDF 的失效重算**（违反"几何静止"假设时的正确性保障）。

## 7. 一个完整的增量案例：GISDFScene 的 LOD 反馈环（GISDFScene.cpp）

SDF 资产按需加载哪些 LOD，由 **GPU 回读的位图反馈**决定：

1. `NeedRequestActiveLOD`：分配 `(总ID数+31)/32` 大小的 bit buffer（**每个 SDF ID 1 bit**）；
2. GPU 侧某 pass 把"当前帧真实用到"的 ID 位写 1；
3. `FinishRequestActiveLOD`：`AddRequestAsyncReadback` 异步回读，轮转 `currentRequestID`；
4. `UpdateMeshesAndRenderers` 消费上次回读：`bit=1 && 未激活 → AllocLOD`；`bit=0 && 已激活 → FreeLOD`；
5. 同时处理增删改：Add → `dirtyRegion.push_back(worldAABB)`；Update（AABB 平方距离 >1）→ push 新旧两块区域；Remove → 尾部搬移 + dirty；
6. 上传：header/mapping/brick 数据各走 ApplyDiff；`dirtyRegion.size()>3` 时上传 dirtyRegionBuffer（给级联做增量重建，[../03-世界层/03-级联距离场GISDFExt](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/03-世界层/03-级联距离场GISDFExt.md) §2.3）。

## 8. 快速问答

**Q："哪些面片需要重算"这种名单怎么在系统里流动？**
A：SceneWatcher 感知场景变化 → UpdateList 合并动作 → 各子系统在 `onBeforeUpdateFrame` 时段消费（GISDFScene::UpdateMeshesAndRenderers、GIFacetScene::UpdateMeshRenderers）→ 帧末统一 `ClearChange()`。

**Q：为什么 Remove 一个对象 GPU 缓冲不缩容？**
A：TrackedList 用末尾填洞——被搬的元素经 move shader 挪到新槽即可，其余元素原地不动；只有 `usedSize` 超过 reserved 的 2 倍阈值才重建（NextPowerOfTwo）。

**Q：GPU 回读不会卡吗？**
A：全异步（`AddRequestAsyncReadback`）+ 轮转 ID——本帧发出请求、下帧消费上帧结果，LOD 的装载永远晚一拍但不阻塞渲染。
