# 01 屏幕层总体流程

> 屏幕层 = "你眼前的画面"。两条并行的追踪管线（间接光 + 镜面）+ 一个弯法线更新器，共用同一批 tracer 与世界层图集。本文给执行全景；算法细节见各分册。

## 1. 输入：ViewContext 里有什么

URP/HDRP 接入层每帧填充（[../05-集成与工程/02-管线接入URP与HDRP](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/05-集成与工程/02-管线接入URP与HDRP.md) §2）：

| 输入 | 用途 |
|---|---|
| `depthPyramid` + `depthMipOffset`（Hi-Z） | ①级屏幕空间查询的步进结构 |
| `normalBuffer`（w=1−perceptualRoughness） | 材质重建：世界法线 + 粗糙度 |
| `motionBuffer` | 重投影/历史深度校验 |
| `colorBuffer` | ①级取色（上一帧最终画面） |
| `GBuffer0..3` | 材质 flag 等（URP 用得少，HDRP 走完整 BSDF） |
| `historyStates` / `nextStates` | 像素层历史/当前双缓冲 |
| `blueNoise` | 抖动与重要性采样 |
| 光源数据（`numOfDirectionalLights/numOfOtherTypeLights` + LightData 缓冲） | 直接光（屏幕层不直接用，透传给面片侧） |
| `cloudBuffer`、skybox 相关 | 天光/云的取色 |

## 2. 执行链（一帧）

```
GIForURP/HDRP::updateView
  1. 包 CommandBuffer 成 oceanus Stream
  2. ExecuteGIPipeline(fctx)          ← 世界层在这里跑（三段事件）
  3. FillViewContextWithNecessaryData   ← 填 §1 的输入
  4. history/next 双缓冲切换
  5. 创建输出纹理（池化）
  6. onUpdateView.Emit(fctx, vctx)     ← 屏幕层在这里跑：
       ├─ TracingView(indirectView)：
       │     IndirectLightingScene<QuadTraceIndirectLighting> → QuadTraceSH
       │        （铺块→发线→六级查询→滤波→历史→SH→摊回）
       ├─ TracingView(indirectViewReflection)：
       │     IndirectLightingScene<ScreenTraceSpecular> → 反射管线
       │        （CountTiles→tracer→Resolve→双去噪）
       │     ※ 两个 TracingView 共用同一批 tracer（屏幕/SDF/cluster/级联/光追/天光）
       └─ GISampleBentNormalUpdater → 弯法线全屏图
  7. ReprojectHistoryTextures          ← 像素层历史混合（diffuse/specular/帧数[/bentNormal]）
  8. CompositeSpecularTextures         ← 反射与粗糙镜面合成
  9. viewStates 存档 nextStates → 下帧历史
```

输出三张主图：**间接漫反射**（outputDiffuse）、**合成镜面**（outputCompositeSpecular = 反射⊕粗糙高光）、**弯法线**（bentNormalBuffer），外加 `outputNumFrames`（累积帧数，供调试/材质）。

## 3. 两条管线怎么共享 tracer

SWRTPipeline 构造一组 tracer 实例（ScreenTracer/SDFTracer/ClusterTracer/SkyLightTracer/CascadedSDFTracer[+InlineRayTracer/RayTracer]），然后构造**两个 `TracingView`**：

- `indirectView = TracingView(giForRP, indirectLightingScene, screenTracer, sdfTracer, clusterTracer, cdfTracer, ...)`
- `indirectViewReflection = TracingView(giForRP, specularLightingScene, 同一批 tracer)`

区别只在第二个参数（lighting scene——决定射线生成器与后处理链）；命中查询完全同构。**TracingView 现役构造**（TracingDispatcher.h:289 起）：在监听 lambda 的捕获列表里就地 `createOptionalDispatcher(screen, sdf, cluster, cdf[, inlineRay, ray])` 组装 tracer 链，并带**透明 pass 门控**：

```cpp
if (RayScheduler::SupportTransparencyPass() && vctx.transparencyPass() || !vctx.transparencyPass())
    DispatchTracing(fctx, vctx, rayScheduler, rayDispatcher);
// 等价于：(支持透明 && 是透明pass) || 非透明pass
```

- `SupportTransparencyPass()`：`QuadTraceIndirectLighting` 返回 **false**（间接光不参与透明 pass）→ `indirectView` 只在非透明 pass 分发；`ScreenTraceSpecular` 返回 **true** → `specularLightingScene` 两个 pass 都分发（这就是 HDRP 透明镜面路径的入口，[../05-集成与工程/02](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/05-集成与工程/02-管线接入URP与HDRP.md) §4）。
- 旧构造（L267，被注释）无条件分发、按值捕获 dispatcher——历史版本。
- 相机销毁时两套 `indirectLightingStates` 分别清理（SWRTPipeline.h:298–318 两个监听）。

## 4. 三张输出图的消费方

| 图 | 消费 |
|---|---|
| outputDiffuse | URP/HDRP 光照合成 pass：`GetDiffuseIndirectTexture(camera)` |
| outputCompositeSpecular | `GetSpecularIndirectTexture(camera)`（含反射） |
| outputRoughSpecular | `GetRoughSpecularIndirectTexture(camera)`（分量，调试/材质用） |
| bentNormalBuffer | `GetBentNormalRT`——材质可用（`useBentNormal`：HDRP 默认 true、URP false） |

## 6. 快速问答

**Q：屏幕层先于还是后于世界层？**
A：后。`updateView` 第 2 步 `ExecuteGIPipeline`（世界层）完成后才 Emit `onUpdateView`（屏幕层）——射线读到"至少是本帧开始时"的 Radiosity。

**Q：反射相机/后视镜会跑几份屏幕层？**
A：每相机一套 viewStates 与两次 TracingView dispatch；世界层只跑一份。相机越多，屏幕层线性增长、世界层不变。
