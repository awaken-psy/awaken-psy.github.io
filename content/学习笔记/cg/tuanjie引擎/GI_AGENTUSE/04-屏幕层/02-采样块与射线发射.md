# 02 采样块与射线发射

> 源文件：`GITracing/QuadTraceSH.h`（execute/选项）、`GITracing/IndirectLightingScene.h`（方向分布）、`RenderPipeline/TuanjieGIForURP.h`（quad 逻辑/抖动/交错）、`Public/TuanjieGIManager.h`（kLightingQuadSize）
> 作用：屏幕层"在哪里、朝哪些方向发多少射线"的全部决定。
> 前置阅读：[../01-背景知识/03-八面体映射与方向采样](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/01-背景知识/03-八面体映射与方向采样.md)（本文是入口摘要；重要性采样的完整算法在 [08-方向采样与重要性采样](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/08-方向采样与重要性采样.md)——进阶篇，**非前置**，读完本文即可继续）

## 1. 采样块：16×16 像素一块

- 尺寸：`ViewContextURP::quadInterval = 16`（"must be 2^n"；QuadTraceSH 的 GIOption 默认 8 被接入层 `finalGatherQuadInterval=16` 覆盖）。**256 像素共享一套查询结果与 9 个 SH 系数**。
- 铺法：`GetQuadCount2D() = (viewportSize + interval−1)/interval`——全屏均匀网格。表面点从深度+法线缓冲反推（`ViewportCoordToWorldPosition/ToWorldNormal`）。
- 编码：`encodeCoord/decodeCoord`——"块索引 + 块内 8×8 射线 xy"压进一个 uint（QuadTraceSH.h:799–812）。
- 每块的持久状态：`framesAccumlatedPerQuad`（R8，累积帧数）+ 历史 SH。

**自适应加密的实情**：`ViewContextURP` 里 `PlaceQuadInViewport`/`WorldPositionToViewportCoord` 返回无效值并带 `// TODO: smart quad placer` 注释——断裂处自动加密尚为未实现的占位。当前均匀网格 + 滤波 + 时间累积兜底。

## 2. 采样点的抖动

采样点不固定在块中心——每帧移到块内某像素上，误差随时间打散（[../01-背景知识/03-八面体映射与方向采样](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/01-背景知识/03-八面体映射与方向采样.md) §4）：

- **主路径（蓝噪声）**：`GetJitter` → `blueNoise->Sample2D(quadCoord, frameNumber, channel=2)`，取 [0,1)² 映射为块内像素偏移（TuanjieGIForURP.h:800–830）。蓝噪声表 = Sobol 256×256 + ranking/scrambling tile 128×128（Heitz 采样器，Math/BlueNoise.h/.cpp；时间动画用黄金比例 `frac(s + (sampleIndex&255)×φ)`）。
  - **采样器五步算法**（`samplerBlueNoiseErrorDistribution_128x128_OptimizedFor_2d2d2d2d_1spp`，CPU/GPU 完全一致仅数据源不同）：① 四参取模（`pixel_i&127`、`pixel_j&127`、`sampleIndex&255`、`dimension&255`）；② `rankedSampleIndex = sampleIndex XOR RankingTiles[dimension + (i+j×128)×8]`（按像素重排样本序）；③ `value = Sobol256x256[dimension + ranked×256]`；④ `value XOR= ScramblingTiles[(dimension&7) + (i+j×128)×8]`（按像素异或打乱）；⑤ 返回 `(0.5+value)/256`。`Sample2D/3D` 用连续 dimension（+0/+1/+2）；**底层调用的 sampleIndex 恒传 0，帧间变化全部来自黄金比平移**（`GOLDEN_RATIO=1.6180339887…`）。
- **备用路径（确定性 8 周期）**：`GetQuadJitter`：`idx = frameNumber % 8`，`x = frac(idx/8)`，`y = reversebits(idx)>>16 / 65536`——8 帧一循环的固定抖动序列（history 用 `(frameNumber−1)%8`）。
- **平台实情（精读核实）**：URP 主路径用蓝噪声（`GetQuadJitter` 备用）；**HDRP 当前正相反——`GetJitter = GetQuadJitter()×quadSize` 走 8 周期确定序列，蓝噪声版被注释**（TuanjieGIForHDRP.h）。
- `jitterMode = (HDRP||URP) && integrateScreenSpace`（QuadTraceSH.h:362）。

## 3. 射线方向：8×8 = 64 条/块

每块 64 条射线，方向按**半球八面体网格**编号（`HemiOctahedronDirSampling`）：

- 均匀版：`generateDistribution` 为空——64 格均分半球，无偏（IndirectLightingScene.h）。
- **重要性采样版**（`ProductImportanceDirSampling`）：用上一帧系数重建亮度分布指导方向分配：

```cpp
pdf    = 0.3*L.x + 0.5*L.y + 0.2*L.z;     // L = 历史重建亮度
weight = dot(normal, dir) < 0 ? 0 : 1;      // 上半球
// 前缀和 64 项，pdfStep = lightingPDFSum / 128.0f（128 个分箱）
```

  求和按 `GetImportance = 4π/kLightingQuadSize²` 的立体角权重校正；上一帧只引导不取值，剧变不滞后。结果经 `alignRay` 归回规整 8×8 格（[04-QuadTraceSH主流程](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/04-QuadTraceSH主流程.md) §4.1）。

## 4. 交错更新：16 组轮换

- 分组：`interleavedUpdateSize = 4` → 4×4=**16 组**（块坐标按 4 取模编组）。
- 每帧只有一组真正发线：`GetValidQuadInterleaved` 里 `isTracing = (quadGroupOffset != interleaveIndex)` 决定（TuanjieGIForURP.h:687–731）；本帧轮到的组进"有效块"列表，其余 15 组不在列表里——它们的历史经 `GetQuadFromHistory` + `borrowRadiance` + `BlendHistoryQuads` 维持连续。
- 开关：`GIForURP.interleavedUpdate.enable` 默认 **true**（URP）；HDRP 的 ViewContext 固定 `enableInterleavedUpdate=false`。
- 代价：灯光剧变时最坏 16 帧延迟（约 0.27 s @60fps）——移动端从"跑不动"换到"跑得动"。

## 5. 每帧射线总量（URP 默认配置）

```
块数 ≈ (W/16)×(H/16)；每块 64 条；交错后每帧 1/16 的块发线
1080p：块数 ≈ 8100 → 全发 518,400 条 → 交错后 ≈ 32,400 条/帧
```

方向复用（64 方向蓝噪换位）+ 空间复用（256 像素/块）+ 时间复用（16 组轮换）——同一查询任务被三个维度分别压缩。

## 6. 快速问答

**Q：块内的 256 个像素都发线吗？**
A：不——一个块只在一个抖动采样点上发 64 条；256 像素靠摊回（系数插值）+ 历史混合补分辨率。

**Q：重要性采样会让亮处更准吗？**
A：会重新分配射线到亮方向，块级结果的方差降低；配合立体角校正保持无偏。

**Q：交错更新关闭会怎样？**
A：全部块每帧发线（桌面 HDRP 默认形态）——结果响应更快、成本约 16 倍于交错模式。
