# 03 六级查询与流压缩

> 源文件：`GITracing/QuadTraceSH.h`（TracerType/mask/dispatch）、`GITracing/TracingDispatcher.h`（流压缩）、`GITracing/ScreenTracer.h`（①级）、`GISDF/GISDFTracer.h`（②级之一）、`GISDF/GIClusterTracer.h`（②级之一）、`GISDFExt/CascadedSDFTracer.h`（③级）、`RayTracing/InlineRayTracer.h`（④级）、`RayTracing/RayTracer.h`（⑤级）、`GITracing/SkyLightTracer.h`（⑥级）
> 作用：每条 GI 射线的命中查询按成本分级——能用便宜级就不上贵级，贵级只服务极少数射线。

## 1. 六级总表（源码对应已全部核实）

| 级 | TracerType（QuadTraceSH.h L416–425） | 实现 | 回答什么 | 启用条件 |
|---|---|---|---|---|
| ① | `kScreen=0` | `ScreenTracer`（Hi-Z 屏幕步进） | 当前画面里的表面（读上一帧颜色） | 恒可用（起点须在屏幕内） |
| ② | `kSDF=1` | `SDFTracer`（单模型精场） / `kCDF=2` 之外另有 `ClusterTracer`（cluster 短程） | 起点附近的模型精场 | 精场数据有效 |
| ③ | `kCDF=2` | `CascadedSDFTracer`（级联粗场步进） | 整个世界 | 级联数据有效 |
| ④ | `kInlineRay=3` | `InlineRayTracer`（ray query） | 真实三角形（即时） | `supportsInlineRayTracing && hwrtSceneEnable` |
| ⑤ | `kRay=4` | `RayTracer`（完整光追） | 真实三角形（完整流程） | `supportsRayTracing && hwrtSceneEnable` |
| ⑥ | — | `SkyLightTracer` | 天光环境 | 恒可用（`HasValidData()=true`） |

**替换规则**（源码事实，QuadTraceSH.h L449–455）：硬件光追可用时 mask **直接清掉 kSDF/kCDF 位**——④⑤整体替换②③，不叠加。`lowestBit/highestBit` 决定链的首尾：第一级用最便宜的可用级、最后一级用最贵的。全落空 → 天光回退（⑥ 不是失败而是正确答案：逃出场景的光收集环境光，命中标记"无限远"）。

## 2. 流压缩（TracingDispatcher.h + Utility/GPUFilter.h）

**调度侧**（TracingDispatcher.h）：

- `FirstDispatch`（线程块=射线生成器的）执行第一级；`CompactDispatch`（64×1）做压缩。
- `DoDispatch` 四特化 → `nofilter`（不需压缩）或 `filter1To1`（把未命中的射线紧凑重排队）。
- `DoMultiPassDispatcher`：串联多级，**只有最后一级做压缩后的收尾**。
- `createOptionalDispatcher<DummyTracer, A, B, ...>`：按 `HasValidData()` 依序挑第一个有效的；`DummyTracer` 恒无效（占位）。

**压缩的实现底座**（Utility/GPUFilter.h，40KB）：

- 三个框架类：`NaiveGPUFilter<ResultType>`（一对一/一对多）、`GroupedGPUFilter<Result,GroupResult>`（分组，级联生成的 node→brick 两级过滤用它）；Context 惯用法见 [../02-代码方言/01-Oceanus-DSL速成](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/02-代码方言/01-Oceanus-DSL速成.md) §6。
- shader 工厂四件：`GetInitCounter1To1Shader`（objectCountBuffer/threadCountBuffer 初始化）、`GetNofilterShader`（不过滤直通）、`GetFilter1To1Shader`（**group_shared + `interlocked_add` 块内压缩写**——这就是"未命中射线紧密排队"的实现）、`GetNofilterRayTracingShader`（光追版直通，带 HDRP hlsl include 与 `try_disable_permutation_with_value` 的排列裁剪）。
- `objectCountBuffer` 的**前 3 个 uint 是 indirect args**（组数）——压缩结果直接驱动下一级的 dispatch 尺寸，CPU 不回读。
- `reserveGPUBuffer` 用 `NextPowerOfTwo` 预留容量防抖动。

**效果**：①命中占大头；每级接手的名单都比上一级短；一个线程组恰好处理一队"还没结果"的射线——GPU 并行度不打折。

## 3. ① 级：ScreenTracer 的 Hi-Z 步进（L68–227 全文核实）

`traceMaxDistance` 默认 50（注释 "Tracer max distance."）；`vignetteScale=2`（"SSR vignette falloff scale. Smaller value = wider falloff region."）。

**入口约束**：起点投到屏幕（`WorldPositionToScreenPosition`：xy→uv、z→deviceDepth），起点必须在屏幕内且深度 > 1e-9，否则整条射线放弃；`ClampRayDistanceToNearNDC` 先裁到近平面内，`FactorToScreenEdge` 裁到屏幕边缘。

**步进主循环**（`$while(true)`，迭代上限 **32** 硬编码；mip clamp **[0,6]** 即最多 7 层）：

1. 当前位置换 uv；边缘吸附 `clamp(raySign×(round(curPos)−curPos)+2e-4, 0, 2e-4)`（注释 "TODO: magic number"）；
2. `mipCoord = curPos.xy >> mipLevel`；**`SampleHZB(uv, mipLevel)` 只提供深度 z**（h 侧 `SampleHZB` 读 `depthMipOffset` 定位 depthPyramid）；xy 边界由 mip 网格算术算出（`(mipCoord+rayStep)<<mipLevel`）——不是从纹理取 4 分量；
3. `distWall = min(dist.x, dist.y)`（冲到格子 xy 边界）；`distFloor = dist.z`（冲到该层深度平面）；
4. `hitFloor = (t ≤ distFloor ≤ distWall)`；**命中判定 `hit = (mipLevel==0) && (hitFloor || belowFloor)`——只在最细层判定**；
5. 步进选择：撞深度面→推进到 distFloor；非 0 层且已低于深度面→**t 不动、降 mip**；否则→推进到 distWall（格子边界）；`curPos.z = bounds.z`（表面行走）；
6. **mip 升降**：`mipLevel += (hitFloor || belowFloor || rayTowardsEye) ? −1 : +1`——撞到/穿到深度就细化，否则粗化；clamp [0,6]。

**厚度判定**（mip0 命中后）：`thickness = depth×0.9901 − 0.000157`（n=2/f=128 推导在注释）；命中点比厚度还浅 → 疑似薄物穿透，**再走 4 步**验证，离开表面则判 miss。

**命中收尾**：

- `QueryHistoryCoordDepth` 把命中像素按运动矢量带到上一帧坐标（深度校验）；
- **暗角剔除**：`vignette = 1−dot(saturate(|posCS|×2−1)²)`，与 `InterleavedGradientNoise(prevTexelPos, frameNumber)`（常量 0.06711056/0.00583715/52.9829189，帧缩放 2.083/4.867）比较——按噪声随机剔除屏幕边缘命中，摊薄边缘漏检；
- **取色读上一帧颜色缓冲**（历史坐标采样），乘 `GetInversePreviousExposureMultiplier()/fLightRangeCompressFactor` 还原；
- **注意**：`hitNormal` 存的是 `(uv.x, uv.y, bufferZ)` 而非世界法线（被注释的 `ViewportCoordToWorldNormal` 行说明作者考虑过但未启用）；
- `hitDistance = distance(命中点, 起点) × 0.5f`——0.5 缩放无注释（源码如实记录）。

①级的物理含义：上一帧颜色 = 直接光 + 已算好的反弹光 → 一份命中约等于**接近两反弹**的信息。

## 4. ② 级：短程距离场

### 4.1 两个 tracer

- `SDFTracer`（GISDFTracer.h）：单模型精场 ray marching；`traceMaxDistance` 默认 1000、实取 `min(它, fctx.maxDistance)`；`sampleBias=0.2`；步进上限 64 步（`rayMarchingMaxCount`）。
- `ClusterTracer`（GIClusterTracer.h 全文 84 行，`trace()` L62–84）——**完整流程**：

```cpp
hitResult.hitDistance = startInWorldSpace.maxDistance;   // 查询距离 → 当作 cluster 数预算传入
sdfCascadeView->ShortRangeTraceSdfMeshUseCluster2(hitResult, sdfScene, start, direction);
$if(命中) {
    Float4 rtn = accessor->GetColor(hitResult.facetMeshRendererID, hitPosition, hitNormal, sampleBias=0.2);
    $if(rtn.w > 0) hit.hitRadiance = rtn.xyz()/rtn.w;    // 多候选加权平均
}
```

`traceMaxDistance` GIOption 默认 **1**、注释写 "Tracer cluster count."（名字/注释/语义错位——实际含义是**沿途扫过的 cluster 数预算**）；面片朝灯的**遮挡检测线**走这一级。

### 4.2 UseCluster2 的实际算法（L1131–1177，逐行核实）

```cpp
Float clusterCount = hitResult.hitDistance;              // 预算（世界距离，即 GIOption 值×世界尺度）
Uint n = cast<uint>(floor(clusterCount));                // 沿途要扫的 cluster 数
$for(j, n) {
    traceOriginVS = worldToVolume(起点 + 方向 × 已走距离);  // 注意：用累加前的 hitDistance 采样
    hitResult.hitDistance += worldClusterSize();         // 每步前进一个簇边长
    Uint4 currentObject = LoadClusterObject(traceOriginVS).data & 0xffffff;  // 该簇 ≤4 个模型
    $for(i, 4) { meshIdx == 0xffffff → break;            // 哨兵即终止
        TraceSdfMesh(单模型 AABB+march, 预算=剩余距离);     // 命中且更近则更新
    };
    $if(已命中) $break;                                    // 提前结束
};
```

三个源码级细节（如实记录）：
1. **簇采样与步进有一格偏移**：位置用**累加前**的 hitDistance 算，随后才 `+=`——采样点比标称步进落后一格（无注释说明）；
2. **相邻簇去重被注释掉**（`lastObject` 整段 `//`）——跨簇重复登记的模型会被重复 trace；
3. 起点不在任何级联内 → hitDistance 归零（未命中）。

### 4.3 同族另外两个函数（存在但未被 ClusterTracer 使用）

| 函数 | 行 | 算法 |
|---|---|---|
| `ShortRangeTraceSdfMeshUseCluster` | L1068–1129 | **纯两次 4 元素扫描，无任何 march**：起点簇扫 4 模型 → 用更新后的命中距离推**终点簇**再扫 4 模型（终点簇对起点簇去重）——各簇内部走 `sdfScene->TraceSdfMesh`（GISDFScene 的单模型 AABB+`RayMarchingVS`，见 [../03-世界层/04-模型距离场GISDF](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/03-世界层/04-模型距离场GISDF.md) §2.3） |
| `TraceSdfMeshUseCluster` | L972 起（L1015 的 `$while(marchCount < rayMarchingMaxCount)` 在此） | **贪心 cluster march**：以 cluster 级大步推进（64 步上限），是"cluster 加速 march"（[../06-参考/02-常量表](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/06-参考/02-常量与魔法数字表.md)）的真身；当前无 cluster tracer 调用 |

级联选择：`GetCurrentCascadeSubCluster(pos, 1.001)`（L877）——从 0 级顺序找**包含该点的级联**（判据 `all(abs(pos−center) < extent − clusterSize×1.001)`），找不到返回 usedSize（=越界）。

精场步进（GISDFScene.h `RayMarchingVS`）：阈值 `clamp(0.25×已走距离, 0, SDFBiasDistance)`、命中判 `abs(distance) < 阈值`（UDF 兼容）——与级联版（`distance <` 不取绝对值）不同，见 [../01-背景知识/04-SDF与球体步进](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/01-背景知识/04-SDF与球体步进.md) §3。

## 6. ④⑤ 级：硬件光追

- `InlineRayTracer`：`RayQuery` + `TraceRayInline` + `while(query.Proceed())`，`CommittedStatus()==OC_COMMITTED_TRIANGLE_HIT` 取 `CommittedRayT()`；
- `RayTracer`：`TraceRay(hwrtScene.rayAccelStruct, OC_RAY_FLAG_CULL_BACK_FACING_TRIANGLES, RAYTRACINGRENDERERFLAG_ALL, ...)`，payload `RayIntersectionTuanjieGI{t, normalWS, positionWS, baseColor, emissive, directLighting}`。

## 8. 命中载荷（payload）

- `RayStart`（GITracing.h）：start/maxDistance/direction，`maxIteration=100`；`RayHit`：hitRadiance/hitNormal/hitDistance，`maxHitDistance=65536`。
- 支持记录 payload 的 tracer 把命中写进 `hitPayloadBuffer`（3×W×H uint4：rendererIndex / hitPositionAndBias / hitNormal），供②级之后的级取用。
- 压缩：`PackRGBE_sqrt`（RGBE 共享指数 + 先开方，保小值精度）。

## 9. 快速问答

**Q：为什么 ①级命中后还要查历史深度？**
A：屏幕内容会动——直接采信当前帧命中像素的颜色可能采到"已经移走的表面"。按运动矢量带回上一帧核对深度，防止拖影。

**Q：六级是每条射线逐级试吗？**
A：不是逐条——是**每级对全体（未命中）射线批量执行**，未命中的经流压缩排队交给下一级；每条射线的一生只按 cheapest→expensive 走到自己有结果为止。

**Q：屏幕 tracer 的 32 次迭代够吗？**
A：Hi-Z 金字塔大步推进下，32 次迭代覆盖典型屏幕路径足够；超限判 miss——这是有意的预算控制（traceMaxDistance=50 也限制了总路径长度）。
