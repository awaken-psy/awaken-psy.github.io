# 08 方向采样与重要性采样（IndirectLightingScene 完整算法）

## 1. 三个方向采样策略（编译期可选）

`IndirectLightingScene.h` 定义了三个策略结构，QuadTraceSH 按 `importanceSampling` 开关选用：

| 策略 | 行 | 行为 |
|---|---|---|
| `FullOctahedronDirSampling` | L~65 | **全球面**八面体格；`GenerateDistribution` 为空 = 均匀（无半球裁剪） |
| `HemiOctahedronDirSampling` | L~85 | **半球**八面体格；方向采样后经 `ConstructOrthoNormalBasis`（L~370 调用）把"法线朝上"局部系旋回世界系 |
| `ProductImportanceDirSampling` | L~108 | **重要性采样**；额外持有 `importanceRayUV`/`importancePDF` 两张纹理；有 biased/unbiased 两个模板特化 |

`ConstructOrthoNormalBasis`（Math/OrthoNormalBasis.h L12）：由法线构正交基——Duff 等人 2017 的无分支算法（signFactor/scaleFactor/crossTerm 三常数式），半球→任意朝向的标准工具。

**自适应块（adaptive quads）现状**：`adaptiveQuadPercent = 0.0f`（L~20，注释 "50% 0.5 for default"），且 `ViewContextIndirectQuads` 整块被注释（L~24–60，含 PlaceAdaptiveQuads/GetQuadCount2D）——自适应加密采样**当前关闭**，与 [02 §1](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/02-采样块与射线发射.md) 的 TODO 证据一致。

## 2. 重要性采样的完整算法（`generateDistribution`，L~440–520）

每个采样块一组线程，在 kernel 内现场重建"这个块该往哪些方向多派射线"：

1. **读历史照明**：从历史纹理逐系数读上帧该块的 SH 结果（`LoadSH/LoadSHReal`，L~215+——**9×3 = 27 个系数逐个从纹理读入**），或直接读 Importance 缓存；照明值经 **`UnpackRGBE_sqrt`** 解码（`as<uint>(from.read(...))` 位重解释 → `Math/TextureCodec.h` 的 RGBE 解包）。
   - **RGBE 编码**（TextureCodec.h，源自 Microsoft Miniigraph / James Stanard）：颜色共享一个指数（R9G9B9E5 类思路），`PackRGBE/UnpackRGBE` 基础版 + `_sqrt` 变体（尾数先开方/平方——**非线性斜坡**，小值精度更高）。命中载荷的压缩（`PackRGBE_sqrt`）与重要性采样的历史读取是同一套编码。
2. **亮度→概率**：`pdf = 0.3×L.x + 0.5×L.y + 0.2×L.z`（L~448——亮度权重不是标准 luminance 系数，是模块自定的近似）；半球裁剪 `weight = dot(normal, dir) < 0 ? 0 : 1`。
3. **并行前缀和**：组共享内存 `pdfArray`/`quadCoord` 上做 **6 步二分归约**（`$for_unroll(stepCount, 6)`——64 项的 log2 前缀和）得 CDF。
4. **等概率分段**：`pdfStep = lightingPDFSum / 128.0f`（L~495）——把 CDF 值域均分 **128 段**；每段概率质量相等（逆变换采样的分层版本）。
5. **领号发射线**：每条射线算自己的 `ISCellIndex`（所属 CDF 段），段内 `interlocked_add(rayCounter)` 领号，**每段最多 1 条、全程上限 64**——64 条射线按"亮度占 64 个等概率段"分布。

## 3. 为什么这不会偏色（无偏性的原理）

等概率分段是关键设计（下文是这一实现的原理推导；分段规则上文已按源码逐条给出）：

- CDF 均分 128 段 ⇒ 每段的概率质量恰为总量的 1/128（与该段覆盖的角度大小无关——亮的方向段窄、暗的方向段宽）；
- 每条射线从自己负责的段内取一个**代表方向**，结果经 `alignRay` 按真实方向归回 8×8 格子（[04-QuadTraceSH主流程](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/04-QuadTraceSH主流程.md) §4.1）；
- 求和（`convertSH`）按格子语义用均匀立体角权重 `GetImportance = 4π/kLightingQuadSize²`。

组合起来的含义：**格子 j 的值 = 该格覆盖的那些 CDF 段的代表样本**。期望上，每格的加权和重建的是"格子立体角 × 格内平均亮度"——采样在亮的区域密（段多、每段窄）、暗的区域疏，但权重始终按格子立体角计，样本分配只影响**方差**不影响期望。这就是"只引导、不取值"（上一帧只决定方向分配，不直接当结果）的统计基础；灯光剧变时分配短暂错位仅表现为一帧内噪声略高，无系统性偏差。

## 4. executeIndirectPipeline：按相机的状态管理（L~140–165）

- `indirectLightingStates`：`unordered_map<Camera*, States>`——每个相机一份间接光状态（历史 SH、帧数、interleaveIndex 等）；
- options 注入点：`states.options` 从 ViewContext 拷贝 `integrateScreenSpace / quadInterval / finalGatherQuadInterval / enableInterleavedUpdate / integrateEnableBentNormal`——QuadTraceSH 的行为开关在此与接入层接合；
- `finalGatherQuadInterval > 0 ? finalGatherQuadInterval : 16`（L~165）——采样块尺寸的最终裁决处。

## 5. 快速问答

**Q：三个策略谁在跑？**
A：屏幕层默认 `HemiOctahedronDirSampling`（均匀）；开启重要性采样选项后 `ProductImportanceDirSampling`。`FullOctahedronDirSampling` 供需要全球面方向的场景（如面片间接光）使用。

**Q：为什么读历史要用 RGBE 开方版？**
A：开方编码让小值（暗部）占更多量化步——暗部的 SH 细节对间接光质量更关键；写侧对应 `PackRGBE_sqrt`（命中载荷也用它）。

**Q：重要性采样会不会让亮处"更亮"？**
A：不会改变期望（见 §3），只降低方差——同样 64 条射线下，有光的块噪声更小；均匀采样下亮格常常只分到少量射线，噪声高。

**Q：adaptive quads 会出问题吗？**
A：当前整块机制处于注释状态（`adaptiveQuadPercent=0`），实际运行只有均匀网格；正文 [02 §1](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/02-采样块与射线发射.md) 的"TODO: smart quad placer"说的是同一件事。
