# 00 系统总览

> 本文目标：30 分钟内建立 TuanjieGI 的完整全景。读完应能回答：它解决什么问题、用什么结构解决、一帧里发生什么、代码放在哪些目录。

## 1. TuanjieGI 解决什么问题

**全局光照（Global Illumination, GI）**：光从光源出发，经场景表面多次弹射后到达相机。直接从光源照到表面的部分叫**直接光**；经至少一次反弹后到达的部分叫**间接光**——墙上的影子不是全黑的、红色地毯把地面映红、窗帘透进来的屋内柔光，都是间接光。

实时渲染的难点是**间接光的多次反弹（multi-bounce）**。传统方案各有硬伤：

| 方案 | 能力 | 硬伤 |
|---|---|---|
| 烘焙 GI（Lightmap） | 能算好任意多级反弹，质量高 | 灯光或几何一动全部作废，需重新烘焙；纯静态 |
| Light Probe 网格 | 支持一定动态更新 | 连一反弹都难以支持；空间分辨率粗 |
| 纯屏幕空间 GI（SSGI） | 快、全自动 | 屏幕外信息完全缺失，漏光/糊边 |

TuanjieGI 的定位：**"静态世界 + 动态灯光"场景下的实时多反弹间接光**。昼夜循环、开关灯、追光灯都能实时响应；大量移动/破坏静态几何不在目标场景内（动态物体只获得部分支持）。

它输出三张全屏图供渲染管线合成：**间接漫反射（indirect diffuse）**、**粗糙镜面反射（rough specular）**、**弯法线（bent normal）**。

## 2. 核心结构：两层分工

**一页数据流图**（所有细节都能挂在这张图上；框内是数据，箭头上是处理）：

```
                    ┌──────────────────────── 世界层（与相机无关） ────────────────────────┐
  离线资产           GISDFMesh(精场) ──登记──> GISDFScene ──dirty──> GICascadedSDFScene(级联粗场)
  GIDataBuilder  →   GIFacetMesh(面片) ──登记──> GIFacetScene：4096²出射光图集(Radiosity 图层)
                                                │  ↑ 每帧：优先级调度 → 工作台512²重录属性
                                                │  │   → 直接光入账(GILighting,8×8光照块)
                                                │  │   → 复合:出射光=ρ²×(直接+间接)+自发光
                                                │  └── 面片间接射线读"别的面片上帧Radiosity"
                                                │       （每帧推进一反弹；面片级累积 8 帧）
                    └──────────────┬───────────────────────────────────────────────┘
                                   │ Radiosity 图集（本帧开始时的快照）
                                   ▼
                    ┌──────────────────────── 屏幕层（每相机一份） ──────────────────────┐
   GBuffer/深度/     采样块16×16 → 64 射线/块(8×8射线格, 蓝噪声抖动)
   Hi-Z/运动矢量  →   │  六级查询(流压缩): ①屏幕Hi-Z → ②短程精场 → ③级联步进
   上一帧颜色        │      (硬件光追可用时 ④⑤ 替换②③) → ⑥天光回退
                    │   后处理: alignRay → borrowRadiance → 滤波 → 块级历史混合(2–16帧)
                    │   → 压成 9×3 SH → 摊回(邻域5×5插值+按瓣求值,弯法线求值方向)
                    │   弯法线全屏图(0.35m/4方向)    [屏幕镜面管线并行另一条 TracingView]
                    └──────────────┬───────────────────────────────────────────────┘
                                   ▼
                    像素层重投影(运动矢量+深度/法线校验, 上限 8×updateSpeed 帧)
                                   ▼
              三张输出图: 间接漫反射 / 合成镜面(反射⊕粗糙高光) / 弯法线 → 交回 URP/HDRP 光照合成
```

TuanjieGI 把"算出全世界的光"与"算出眼前画面的光"拆成两个互补层。

### 2.1 世界层：面片光场，逐帧迭代多反弹

给每个静态物体的表面铺一层小**面片（facet）**。每块面片记录自己向外发出的光——**出射光**，按物理量是辐射亮度。所有面片的出射光存进一张 4096×4096 的**出射光图集**。

每帧，面片计算自己的出射光：

$$
\text{出射光} = \text{表面颜色} \times (\text{直接光} + \text{间接光}) + \text{自发光}
$$

- **直接光**：对每盏够得着它的灯算"强度 × 朝向系数"，并朝灯发一条遮挡检测线，有遮挡则归零。
- **间接光**：面片朝自己的上半球发一批射线（与屏幕层同一套命中查询机制），命中后读取**别的面片上一帧的出射光**。

多级反弹不需要在一帧内算完：上一帧的出射光作为这一帧的间接光来源，**每帧向前推进一反弹**。静止场景中逐帧收敛到接近无限反弹。这在数学上是把辐射度方程组的求解拆成了逐帧迭代——世界层本质是一个逐帧运行的辐射度求解器。

### 2.2 屏幕层：采样块查询，把世界数据用进画面

把屏幕切成 16×16 像素的**采样块**（quad），每块从深度+法线缓冲取一个表面点，朝半球发射 64 条射线，查询"这个方向上谁会把光反弹给我"——命中后读取**该处面片存储的出射光**（世界层的数据在这里被消费）。

64 条射线的结果按方向归入 8×8 方向格，压缩成 **9 个球谐（SH）系数**（RGB 共 27 数），经空间滤波与历史混合后，摊回块内 256 个像素，产出间接漫反射与粗糙镜面两张全屏图。

### 2.3 两层之间不同步

屏幕层读到的是**这一帧开始时**的图集；面片算间接光的输入里有**上一帧**的屏幕画面。这种"各读各的旧值"的松弛设计是实时跑得动的关键：每帧只推进一步，正确结果随时间收敛，无需全局同步。

## 3. 一帧的执行顺序

### 3.1 世界层更新（先）

1. **变更检测**：维护"哪些面片需要重算"名单——新加入物体、刚移动的模型、太久没更新的面片。
2. **重录基础属性**：面片的颜色、法线、自发光、深度从原模型重新采样。经一张 512×512 **工作台**纹理批量渲染，再写入 4096×4096 图集（全量重画不现实，工作台只装本批待办）。
3. **计算光照**：直接光逐灯入账；间接光朝上半球发射线读别的面片上一帧的出射光。
4. **合成写回**：按 §2.1 公式写回图集。

### 3.2 屏幕层查询与输出（后）

1. **复用历史**：上一帧输出按运动矢量搬到这一帧的位置继续使用（重投影）。
2. **铺采样块、发射线**：命中查询按六级成本从低到高进行（§4）。
3. **汇总输出**：结果按方向归位 8×8 格 → 压成 9 个 SH 系数 → 与邻块空间滤波 → 与历史加权混合 → 摊回像素 → 输出三张全屏图。

**顺序不可颠倒**：世界层先更新，屏幕层射线才能读到"至少是本帧开始时"的出射光。

**世界层与相机无关**：分屏、反射相机、后视镜——图集只算一次，各相机各自的屏幕层去读它。相机越多，这块固定开销分摊越薄。

### 3.3 帧间持久数据（五样）

1. 面片出射光图集（下一帧间接光的读取源）
2. 每个相机的屏幕输出历史（重投影复用）
3. 每个采样块的历史 SH 系数与累积帧数（越静越精）
4. 上一帧最终画面颜色（屏幕空间查询的取色来源）
5. 相机周围的级联粗距离场（几何索引）

## 4. 射线的六级命中查询

每条射线要回答"这个方向上撞到什么"。六级按成本从低到高：

| 级 | 方式 | 能回答什么 | 成本 |
|---|---|---|---|
| ① | 屏幕空间查询 | 当前画面里有什么（Hi-Z 步进 + 上帧颜色） | 极低 |
| ② | 局部精场查询 | 起点附近一小段（本格索引表的 ≤4 个模型精场） | 低 |
| ③ | 粗场步进 | 整个世界（级联粗场，接近处转精场判定） | 中 |
| ④ | 内联光追 | 真实三角形（硬件加速，逐条即时） | 高 |
| ⑤ | 完整光追 | 真实三角形（硬件加速，完整命中流程） | 最高 |
| ⑥ | 天空回退 | 天光环境 | 几乎为零 |

规则：**能用便宜的就不上贵的**。①命中即止；答不了的交距离场（短程用②，长程用③）；有硬件光追的平台上④⑤整体替换②③；全落空取天光⑥。实现方式是**流压缩**：每级查询后，未命中的射线紧密排队交给下一级，贵的级别只服务极少数射线。

①的屏幕空间查询本身就是一次步进：射线投到屏幕坐标沿画面推进，用 **Hi-Z 深度金字塔**跳大步（远处用粗档、接近命中换细档），射线深度超过画面深度产生命中候选，再按运动矢量带回上一帧核对深度，采信后取色读**上一帧最终画面**——那里面已含直接光与上一帧算好的反弹光，一份命中约等于接近两反弹的信息。

③的粗场步进：从包含射线起点的级联层开始，走出该层包围盒就换外层，每层只走自己罩住的那段；读数变小接近表面时，在步进点前方（提前量约等于命中阈值）查该格模型索引表转入精场精确判定；每段有步数上限，保证掠射射线一定给出结论。

## 5. 从采样块到像素：五步处理

64 份"方向 → 亮度"结果到全屏输出图之间：

1. **归位**：重要性采样后结果的格子号与实际方向错位，按真实方向重新归入规整 8×8 方向格。
2. **空间滤波**：与邻块混合，但须通过**三判据**加权（屏幕距离近 / 3D 深度近 / 表面朝向接近，各一个高斯 σ）——同一物理表面内部混合消噪，不同表面之间不渗透。
3. **历史混合**：与上一帧结果按 $\text{新} = \text{lerp}(\text{旧}, \text{本帧}, 1/\min(\text{帧数},16))$ 滚动平均；权重 1/帧数恰好构成 n 帧滚动平均；下限 2 防止单帧噪声全量进入、上限 16 防止惯性无限增长。历史查找在 5×5 邻域内按三判据匹配（采样点每帧在块内抖动）。物体移动/表面变化时帧数清零。
4. **压缩**：每块 64 格方向亮度表投影成 9 个 SH 系数。
5. **摊回**：每个像素取邻域 5×5 块的系数按三判据加权插值（块→像素分辨率、消除块印），再按瓣求值——漫反射以**弯法线**为方向套余弦瓣求值（输出除以 π），粗糙镜面以反射方向为轴、锥角 = π/2 × 粗糙度的瓣对同一组系数求值。（**弯法线仅 HDRP 启用**：URP 的 `useBentNormal=false`，求值回退世界法线——[../04-屏幕层/05-弯法线GISampleBentNormal](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/04-屏幕层/05-弯法线GISampleBentNormal.md) §3。）

**弯法线**：逐像素在深度缓冲上朝若干方向（默认 4 条）做短距离遮挡检查（默认 0.35 米），通过的方向加权平均——墙角处该方向偏向开阔侧且更短，长度携带该点可见度。它替代原法线用于漫反射求值、并派生粗糙镜面反射方向，让块级低频数据补上像素级遮挡，角落与缝隙自动出现遮蔽感，无需另叠 SSAO。**平台现状：HDRP 全开；URP 三关全关（不计算、不求值、不累积），角落遮蔽需另配 SSAO**。

## 6. 代码放在哪：模块目录职责

源码根：`Modules/TuanjieGI/`。每个子目录的职责：

| 目录 | 层 | 职责 |
|---|---|---|
| `Public/` | — | 对外接口：TuanjieGIManager（总装）、Options/Config、C# 绑定 |
| `GIPipeline/` | 总装 | 管线抽象接口 ITuanjieGIPipeline、SWRTPipeline 等 |
| `RenderPipeline/` | 集成 | URP/HDRP 接入（TuanjieGIForURP/ForHDRP）、ReprojectHistory |
| `GITracing/` | 屏幕层 | 采样块追踪 QuadTraceSH（**全模块最核心文件**）、屏幕空间镜面、弯法线、分发器、IndirectLightingScene |
| `GISDFExt/` | 世界层 | 级联粗场 GICascadedSDF、索引表、级联 tracer |
| `GISDF/` | 世界层 | 模型精场：GISDFScene 存储与查询、短程/全程 tracer |
| `GIFacet/` | 世界层 | 面片系统：GIFacetScene、图集分配、工作台、面片光栅化 |
| `GILighting/` | 世界层 | 面片光照入账：方向光/点光/聚光的直接光 |
| `GIDataBuilder/` | 离线 | 资产生成：SDF 测量、面片布局（编辑器侧） |
| `RayTracing/` | 硬件 | 硬件光追后端：BLAS/TLAS、ray query（④⑤级） |
| `Utility/` | 工具 | GPU 资源跟踪（TrackedGPUBuffer/Texture3D）、分配器（SpanAllocator/GPUItemAllocator）、增量列表、优先队列；内含 `Utility/RadeonRays/`——AMD 第三方 BVH 构建库（离线测量用） |
| `Atlas/` | 工具 | 2D 纹理图集分配封装；底层为第三方 **smol-atlas**（`Atlas/external/smol-atlas/`） |
| `TrackedApi/` | 工具 | GPU 资源跟踪封装（薄头文件） |
| `Math/` | 自研 | 数学工具：BlueNoise 蓝噪声、SphericalHarmonics 球谐、BilateralFilter 双边滤波、GPUCone/GPUCylinder、Matrix3x4f 等 |

代码是 **Oceanus DSL** 写法——C++ 模板生成 GPU 程序（不是手写着色器）。理解本套文档各篇里的 GPU 代码写法前，必须先读 [02-代码方言/01-Oceanus-DSL速成](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/02-代码方言/01-Oceanus-DSL速成.md)。

## 7. 已核实的关键源码事实（路标）

以下断言均已逐条对照源码核实过（详见 [06-参考/02-常量与魔法数字表](学习笔记/cg/tuanjie引擎/GI_AGENTUSE/06-参考/02-常量与魔法数字表.md)）：

- `GICascadedSDF.h`：级联数 4；每 cluster 最多登记 4 个模型（保留最近 4 个）；步进上限 128（级联 march `rayMarchingMaxCountCDF`）/ 64（cluster 加速 march `rayMarchingMaxCount`）；生效命中阈值 = min(半体素, 沿途最大读数)，硬编码 0.5 钳制；`occludeFactor`（注释 "Set this to avoid light leaking"，默认 0.5）只接在无调用者的 `RayMarchingJumped` 上
- `QuadTraceSH.h`：历史混合下限 2（注释 "for fast moving object"）、上限 16（"for static object"）；邻域核 5；三判据 sigma；摊回邻域 5×5（范围 2–7）、三个 sigma 默认（1.5×块尺寸 / 0.3 / 1.0）；漫反射以弯法线求值（permutation `integrateEnableBentNormal`——URP 关闭时回退世界法线）、输出除以 π；粗糙镜面锥角 = π/2 × 粗糙度
- `GISampleBentNormal.h`：遮挡检查距离默认 0.35 米、方向数默认 4；向量长度随遮挡变短
- `GIFacetInclude.h`：面片侧累积上限 8 帧（注意与屏幕侧 16 不同）
- `GISDF/GISDFTracer.h`：全程 tracer 距离上限 1000；`GIClusterTracer.h`：短程 tracer 预算 1 个 cluster
- `ReprojectHistory.h`：像素层历史重投影同样累积弯法线

## 8. 系统的假设与边界

1. **几何基本静止**：面片和距离场在资产导入/构建时生成；移动静态几何需重新生成 GI 资产。目标是"静态世界 + 动态灯光"。动态物体的反弹由屏幕层部分处理。
2. **反弹以漫反射与粗糙镜面为主**：锐利镜面倒影（镜子）由 SSR 等系统负责，本模块输出的是粗糙镜面（锥角随粗糙度展宽的瓣）。
3. **需要 3D 纹理与 GPU 通用计算**：中高端移动设备可跑（有低成本模式），老旧平台与微信小游戏当前不在支持范围。
