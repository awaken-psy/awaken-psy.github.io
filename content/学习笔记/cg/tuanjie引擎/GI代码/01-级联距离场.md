# 01 级联距离场（GICascadedSDF）

> 源码：`GISDFExt/GICascadedSDF.h`（结构 + 查询）＋ `GISDFExt/GICascadedSDF.cpp`（每帧构建）
> 对应原理册：[SDF 与球体步进](学习笔记/cg/tuanjie引擎/GI原理/01-数学基础/03-SDF与球体步进.md)、[分层距离场](学习笔记/cg/tuanjie引擎/GI原理/02-世界表示/02-分层距离场.md)
> 阅读基线：pre-trunk `cd150c21804`（2026-09-18 同步后，本文件改动见 §3.5）

## 1. 结论

这两个文件实现相机周围的粗场：`.h` 定义数据结构和全部 GPU 查询函数，`.cpp` 每帧增量构建。

### 1.1 尺寸体系

粒度从小到大共五级：

| 层级 | 尺寸 | 职责 |
|---|---|---|
| voxel | brick ÷ 7 | 存距离值 |
| cluster | brick ÷ 4 | 存模型索引表，每 brick 64 个 |
| brick | 第 0 层 0.5m，每层 ×2 | 图集分配单位 |
| node | 4³ bricks | 脏区筛选 |
| cascade | 32³ bricks × 4 层 | 一层完整的距离场 |

关键数字：

- brick 尺寸逐层翻倍，每层 extent 也翻倍。窗口宽恒为 32 bricks，相机永远在窗口中心。
- voxel = brick ÷ 7。brick 实占 8³ texels，内容只有 7³，第 8 个 texel 是边界 padding——防止三线性插值跨 brick 串值。
- 粗场值域只有 ±4 个体素（R8_UNORM 存储）。编码 `raw = (d+a)/(2a)`，解码 `d = raw·2a − a`，其中 a = 4 个体素。
- 更远的距离一律截断为 +4 体素；没有 brick 的地方读数也是 +4 体素。
- 面片采样最大距离 = 第 0 层 extent × 16。

### 1.2 存储

- **mapping buffer**：131072 项（32³ × 4 层）。key 是层号 + 世界 brick ID（对 32 取模），值是图集槽位或无效标记 `0xFFFFFFFF`。
- **brick 图集**：65536 槽（预算 × sparsity 0.5）。实际存 7³ 距离值，槽位由 GPU 分配器按需分配、释放。

### 1.3 每帧更新：增量，不重建

相机位置按 brick 网格 snap 对齐。移动窗口后，世界 brick ID 没变的格子**连同图集数据直接沿用**——只有新露出的部分需要重算。

每帧只处理"脏 brick"：

1. 脏区 = 相机移动新露出的条带（每轴最多一个）∪ 场景侧报上来的变化区域
2. 脏区 → 脏 node → 脏 brick
3. 判断哪些 brick 需要：模型表面距 brick 中心在 ±4 体素内才需要。需要就分配槽位，不需要就释放
4. 重算脏 brick 的每个 voxel：对所有相交模型采样精场，取 min，clamp 到 ±4 体素，写入图集
5. 同一个 pass 里写 cluster 索引表：每个 cluster 登记最近的 4 个模型（新模型替换最远项）

模型名单逐层收缩：最粗层从全场景筛一遍，细层直接复用粗层筛过的结果。精场半径小于 minRadius 的模型不进级联（minRadius = 0.2 / minGIDetail）。

### 1.4 查询：四个入口

- `GetCurrentCascade` —— 找包含某点的最细层
- `TraceCascadeSDF` —— 层间 march。本层没命中，就从 AABB 出射点跳到下一层
- `TraceSdfMeshUseCluster` —— march 时顺路查索引表（查询位置提前一个阈值），把登记的 ≤4 个模型转各自精场精查，取最近命中
- `ShortRangeTraceSdfMeshUseCluster` —— 不 march。预算 1 个 cluster，只查起点和终点两个 cluster

命中后的法线用 6 邻域中心差分算，背向射线就翻转；命中点回退 1 体素。

### 1.5 RayMarching 四变体

文件里有四个 march 函数，是演化痕迹。步数上限都是 128：

| 变体 | 命中阈值 | 命中回退 | 现状 |
|---|---|---|---|
| RayMarchingVS | 随射线距离增长 | t + d − 阈值 | 无调用者 |
| RayMarchingOld | 随最大读数增长 | 无 | 无调用者 |
| **RayMarching** | **min(半体素， 沿途最大读数)，硬编码 0.5** | **1 体素** | **生效路径** |
| RayMarchingJumped | 体素 × occludeFactor | 无 | 无调用者 |

### 1.6 关键结论：occludeFactor 当前不生效

`occludeFactor`（GIOption，默认 0.5，注释原文 "Set this to avoid light leaking"）在 GPU 侧只被 `RayMarchingJumped` 引用，而 `TraceCascadeSDF` 的三处调用全部使用默认的 `useJump = false`，全模块没有 true 的实例化。

**当前版本调这个参数没有任何效果。生效阈值是硬编码的半体素**，并被"沿途最大读数"封顶——贴近表面时阈值自动收紧，避免贴面平行的射线误报命中。

### 1.7 杂项

- 步进上限：级联 march 128（`rayMarchingMaxCountCDF`）；带索引表的 march 只有 64（`rayMarchingMaxCount`，GISDFMesh.h）；短程不 march
- `SortForTest`：测试模式下把图集 brick 紧凑化复制一份，给测试确定性的布局
- CDFSpreading（GIOption，默认关）：mip 层间扩散距离值，注释称改善梯度平滑
- UDF 相关代码（`LoadUDFAmount` 等）当前全部关闭

## 3. 与原理册的差异

1. **[分层距离场 §3]（已同步修正）**：命中阈值不是"引擎的防漏参数"——参数存在但没接线，生效阈值硬编码 0.5，且被沿途最大读数封顶。
2. **[数学基础 03 §3.1] "阈值随距离放宽"**：活跃路径按"沿途最大读数"自适应，不是按射线距离。该节是通用论述，保留不改。
3. **"每段步进上限 128 步"**：级联 march ✓；带索引表的 march 是 64；短程不 march。六级查询篇的"128 步"对应哪条路径，station 4 核对。
4. **"每格最多 4 个模型" ✓**：粒度是 cluster（非 voxel）；保留最近的 4 个，升序存放。
5. **本次同步（3819 提交）的改动**：`minRadius` 默认统一为常量 `cdfOriginCullingSDFRadius = 0.2`（Public/TuanjieGIManager.h）；`CascadedSDFTracer` 命中写入改用 `screenCoord`（station 4 处理）。

原理册未覆盖的新事实：7+1 texel 结构、±4 体素值域、sparsity 0.5、wrap-32 世界 key 与槽位复用、脏区条带算法、三级粒度分工、SortForTest、CDFSpreading。
