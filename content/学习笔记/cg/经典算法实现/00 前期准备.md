## 0.1 这个项目是什么

GraphicAlgorithm 是 GitHub 上 AngelMonica126 的开源项目，**逐篇复现了 28 篇经典实时渲染论文**，每篇配一份可运行 demo 和知乎解析。

它不是"一堆独立脚本"，而是共享同一个自研渲染框架 **FRAME**：

```
你的 demo（薄薄一层 main.cpp + 几个 Pass）
        │  调用
        ▼
   FRAME 动态库（窗口/相机/shader/FBO/资源管理/渲染管线调度）
        │  依赖
        ▼
   OpenGL + GLFW + GLEW + GLM + Assimp + ImGui ...
```

> [!important] 核心认知
> 28 个 demo 看似各不相同，本质都是**同一套积木（FRAME）的不同拼法**。
> 所以读任何一篇算法前，先吃透 FRAME——也就是 [[学习笔记/cg/经典算法实现/01 框架.md|01 框架（FRAME）]]。
> 之后每篇 demo 的差异，只在"拼了哪几个 Pass、Pass 之间传了什么数据"。

## 0.2 工具链与依赖

> [!abstract] 构建系统：premake5 → Visual Studio

| 项 | 内容 |
|---|---|
| 平台 | **仅 Windows x64** |
| 编译器 | MSVC（VS2017，可在 set.bat 里改版本） |
| 工程生成 | premake5（仓库自带 `premake5.exe`） |
| 图形 API | OpenGL 4.x（GLEW + GLFW） |
| 第三方库 | GLM / Assimp / SOIL + stb_image / Boost / Eigen / ImGui |

外部库**不在仓库里**，靠一组环境变量定位，需要单独下载 `GraphicSDK` 并运行其中的 `Graphic.bat` 来配置：

`EIGEN` `BOOST` `ASSIMP` `STB_IMAGE` `GLM` `OPENGL` `SOIL` `GLI` `PARTIO`

> [!warning] Linux 用户请注意
> 本项目是纯 Windows / VS 工程（`system "Windows"`、链接 `opengl32.lib`、`Graphic.bat` 用 .bat 配置环境变量）。
> **在 Linux 上无法用官方 premake 工程直接编译运行。**
> 你的选择：
> - **只读代码**（推荐，本笔记的核心目标）——算法和框架逻辑与平台无关；
> - 想运行：Windows 机器 / 虚拟机 / Wine；或自行用 CMake 移植构建（工作量不小，见 [[学习笔记/cg/经典算法实现/roadmap.md|GraphicAlgorithm 学习路线图]] 附录）。
>
> 读代码不需要编译。后面的所有笔记都假设你在"读"，而不是"跑"。

## 0.3 构建与运行（Windows）

```bat
:: 1. 克隆（大模型走 LFS）
git lfs clone git@github.com:AngelMonica126/GraphicAlgorithm.git

:: 2. 下载 GraphicSDK，管理员权限运行 Graphic.bat 配置环境变量

:: 3. 生成 VS 解决方案
set.bat                  :: 内部执行 premake5 vs2017

:: 4. 打开 GraphicAlgorithm.sln
::    先单独 build【Frame】项目 → 生成 FRAME 动态库
::    再把目标 demo（如 018）设为启动项 → 运行
```

> [!note] 为什么要先 build Frame
> 所有 demo 都链接 `FRAME.lib`（FRAME.dll 的导入库）。
> Frame 没编译出来时，其它 demo 链接会失败。这是新手最常踩的坑。

产物：各项目下的 `x64/Debug` 或 `x64/Release`。

## 0.4 目录约定

```text
GraphicAlgorithm/
├── premake5.lua          workspace：include 所有子项目
├── function.lua          create_console_project() 模板（公共头/库/警告配置）
├── set.bat               一键 premake5 vs2017
├── FRAME/                ★ 自研渲染框架（动态库）—— 笔记 01 的主角
├── 001_～028_            每个编号目录 = 一篇论文的 demo
├── Model/                共享模型（Sponza/Dragon/Lucy…，大文件走 LFS）
├── Textures/             共享纹理（BRDFLUT/Skybox…）
├── SDK/                  随仓库的 imgui_master + iconfontheaders
├── BRDF_Sampler / SH_Sampler / FitLTCMatrix / DepthToPositionAndNormal
│                         离线工具：生成查找表 / 拟合矩阵 / 重建位置法线
```

**编号目录内部**高度统一：

```text
018_Cascaded Shadow Maps/
├── premake5.lua        仅两行：include function.lua + create_console_project(...)
├── main.cpp            入口：注册 GameObject/Pass/GUI → 启动主循环
├── GBufferPass.{h,cpp} + GBuffer_VS.glsl + GBuffer_FS.glsl   一个 Pass = 一组同名文件
├── CascadedShadowMapPass.{h,cpp} + CascadedShadowMap_{VS,FS}.glsl
└── ...
```

> [!tip] Shader 命名约定
> `<Pass名>_VS.glsl`（顶点）/ `_FS.glsl`（片元）/ `_GS.glsl`（几何）/ `_CS.glsl`（计算）。
> Pass 类与它的 shader 文件**同名配对**，看 Pass 名就知道去找哪几个 .glsl。

## 0.5 读代码前的 OpenGL 概念对齐

demo 重度依赖以下 OpenGL 机制。下面只给"项目里怎么用"的定位，不展开教程。

| 概念 | 项目里干嘛 | 不熟就看 |
|---|---|---|
| **FBO + MRT** | GBuffer = 一个 FBO 挂多张纹理（位置/法线/反照率同时写） | LearnOpenGL 帧缓冲 |
| **纹理格式** | `STexture.InternalFormat = GL_RGBA32F` 等浮点纹理存 GBuffer | LearnOpenGL 纹理 |
| **计算着色器 CS** | 大量算法用 CS（如 `DirectLightPass_CS.glsl`）做屏幕空间计算 | LearnOpenGL 计算着色器 |
| **VAO/VBO** | `getOrCreateScreenQuadVAO()` 画满屏四边形跑后处理 | LearnOpenGL |
| **UBO** | `UBO4ProjectionWorld` 把投影/视图矩阵共享给所有 shader | LearnOpenGL 高级数据 |
| **延迟渲染** | 先 GBuffer 存几何/材质 → 再逐像素算光照（绝大多数 demo 的骨架） | LearnOpenGL Deferred Shading |

> [!note] 几乎每个 demo 都是"延迟渲染 + 屏幕空间后处理"的变体
> 标准骨架：
> 1. **GBuffer Pass**：把位置/法线/颜色写进一组纹理
> 2. **（各种算法 Pass：阴影/GI/AO…）** 读 GBuffer、算结果、写新纹理
> 3. **DirectLight / Shading Pass**：合成最终颜色
> 4. **ScreenQuad Pass**：把结果画到屏幕
>
> 抓住这个骨架，再复杂的 demo 都是往第 2 步里塞东西。

## 0.6 怎么"读"一个 demo（固定套路）

读算法代码别从 main 顺着硬啃。按这个顺序：

> [!example] 三步阅读法
> 1. **`main.cpp`**：看注册了哪几个 Pass、顺序号是多少 —— 这就是管线的骨架
> 2. **`grep` 所有 `registerSharedData` / `getSharedDataByName` 的字符串键** —— 这就是 Pass 之间的数据管线（谁生产、谁消费什么纹理/矩阵）
> 3. **按 `executionOrder` 逐个 Pass 读** `initV()`（建 FBO/纹理/shader）和 `updateV()`（每帧逻辑）

> [!important] SharedData 是灵魂
> Pass 之间不直接互相引用，全靠 `ResourceManager` 的字符串键 + `boost::any` 传数据。
> **看不懂一个 demo？多半是没理清它的 SharedData 键。**
> 这套机制的细节在 [[学习笔记/cg/经典算法实现/01 框架.md|01 框架（FRAME）]]。
