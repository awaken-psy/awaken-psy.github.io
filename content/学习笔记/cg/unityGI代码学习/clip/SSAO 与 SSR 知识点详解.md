# SSAO 与 SSR 知识点详解

## 1 什么是"屏幕空间"

SSAO 和 SSR 都有一个共同前提：**只能看到屏幕上已有的信息**。

延迟渲染的 Geometry Pass 之后，屏幕上有：

| 纹理 | 信息 |
|---|---|
| 深度图 | 每个像素离相机多远 |
| 法线图 | 每个像素表面的朝向 |
| 颜色图 | 每个像素的最终颜色 |

"屏幕空间"技术就是**只利用这些已有的 2D 纹理来做近似计算**，不碰 3D 几何体。

> [!warning] 屏幕空间的根本局限
> 只能看到"相机能看到的"。如果遮挡物或反射目标在画面之外，屏幕空间技术感知不到。这就是 TuanjieGI 除了 ScreenTracer 之外还需要 SDF/Facet 加速结构的原因。

## 2 SSAO — 屏幕空间环境光遮蔽

### 2.1 要解决什么问题

Phong 模型的环境光是一个常数——所有地方一样亮。但现实中：

```
    墙壁
     │
     │  角落 ← 间接光被周围几何体挡住，应该暗
     │
     │
     │  开阔处 ← 间接光通畅，应该亮
     │
     └──────────── 地面
```

> [!info] SSAO 的目标
> **找出哪些地方被周围几何体遮挡，把那些地方压暗。**

### 2.2 核心原理

SSAO 不发射射线（太慢），而是用**深度图来近似估计遮挡**。

> [!info] SSAO 算法
> ```
> 对每个像素 P：
>
>   1. 在 P 周围一个半球内，随机撒 N 个采样点
>   2. 对每个采样点 S：
>      - 查深度图，获取 S 位置的实际深度
>      - 如果 S 比实际几何体"更近"（S 在几何体前面）
>        → 说明 S 这个方向有几何体挡着 → 计入遮挡
>   3. 遮蔽率 = 被挡的采样点数 / 总采样点数
>   4. 最终环境光 = 原环境光 × (1 - 遮蔽率)
> ```

图示（截面）：

```
         相机
          ↓
    ──────P────────── 地面
    
    P 周围撒采样点：
    
    ●  ← 查深度：这个点前面是空气 → 没被挡 ✓
    ●  ← 查深度：这个点后面有墙壁 → 被挡了 ✗
    ●  ← 查深度：这个点前面是空气 → 没被挡 ✓
    ●  ← 查深度：这个点后面有墙壁 → 被挡了 ✗
    
    4 个采样点里 2 个被挡 → 遮蔽率 = 50%
    → 环境光打 5 折
```

### 2.3 为什么"采样点在几何体前面"就是被挡

> [!note] 直觉理解
> 想象你站在地面上的 P 点，抬头往四面八方看：
> - 往上看 → 看到天花板 → 没被挡 → 有间接光
> - 往左看 → 看到墙壁 → 被挡了 → 少一点间接光
>
> SSAO 用采样点比深度图来近似"你往某个方向看，是不是有东西挡着"。
>
> 如果采样点在几何体前面（深度比深度图值小）→ 说明那个方向有几何体 → 被挡。
> 如果采样点在几何体后面（深度比深度图值大）→ 说明那个方向通畅 → 没被挡。

### 2.4 SSAO 的效果

```
没有 SSAO：                 有 SSAO：

┌──────────────┐            ┌──────────────┐
│              │            │▓▓            │
│              │            │▓▓ 角落变暗   │
│   全部均匀    │            │              │
│              │            │   开阔处正常  │
│              │            │              │
└──────────────┘            └──────────────┘
```

### 2.5 SSAO 的局限

> [!warning] SSAO 的局限
> - **看不到屏幕外**：画面外的遮挡物感知不到
> - **只能近似**：采样点数量有限，结果有噪声
> - **不区分方向**：只知道"被挡了多少"，不知道"被哪个方向挡的"

> [!tip] Bent Normal
> Bent Normal（弯曲法线）可以部分解决"不区分方向"的问题——它记录"最少被遮挡的方向"。TuanjieGI 在 HDRP 路径中使用了 Bent Normal（`useBentNormal = true`），URP 路径没有（`useBentNormal = false`）。

## 3 SSR — 屏幕空间反射

### 3.1 要解决什么问题

光滑表面（镜子、金属、水面）会反射周围环境的影像。延迟渲染的 Lighting Pass 只算直接光，不算反射——反射是间接光的一种。

### 3.2 反射的物理原理

```
视线方向 V 打到表面 → 按法线 N 翻转 → 得到反射方向 R
沿 R 方向看出去，看到什么颜色，就是反射颜色

    法线 N
     ↑
V ───→│←── R (反射方向)
     │
  ───┴─── 表面
```

> [!info] 反射方向公式
> `R = reflect(V, N)` = `2 × (V·N) × N - V`

### 3.3 SSR 的核心原理

SSR 在屏幕空间沿反射方向**步进深度图**，找到射线"穿过"表面的位置：

> [!info] SSR 算法
> ```
> 对每个像素 P：
>   1. 拿到 P 的法线 N 和视线方向 V
>   2. 算反射方向 R = reflect(V, N)
>   3. 把 R 投影到屏幕空间（变成 2D 方向）
>   4. 沿这个 2D 方向，一步一步前进
>   5. 每走一步，比较：
>      - 射线的深度（射线在这一步离相机多远）
>      - 深度图的值（这个位置的实际几何体离相机多远）
>   6. 如果射线深度 > 深度图值 → 射线穿到表面下方了 → 命中！
>   7. 返回命中位置的像素颜色作为反射颜色
> ```

图示：

```
    屏幕空间步进（俯视截面）：

    P(起点)  step1  step2  step3(命中!)
     ●──────●──────●──────●
      │      │      │   │
      │      │      │  ╱ 射线深度 > 表面深度
      │      │      │ → 穿过了红色物体的表面
      │      │      │
     地面    地面    地面  红色物体

    → 反射颜色 = 红色物体在 step3 位置的颜色
```

### 3.4 为什么步进深度图能找到反射目标

> [!note] 深度比较的原理
> 深度图记录了每个像素最近的几何体距离。
> - 射线深度 ≈ 深度图值 → 射线碰到了表面 → 命中
> - 射线深度 < 深度图值 → 射线在表面前面 → 还没碰到，继续走
> - 射线深度 > 深度图值 → 射线穿到表面后面了 → 刚才穿过的就是命中点

### 3.5 HZB（层级 Z 缓冲）加速步进

> [!tip] HZB = Hierarchical Z Buffer（层级深度图）
> 一步一步走太慢。SSR 使用 HZB 加速：
>
> ```
> 原始深度图（mip 0）：每个像素一个深度值，分辨率最高
>     ↓ 降采样取最大值
> mip 1：2×2 像素合并，保留最远的深度
>     ↓
> mip 2：4×4 像素合并
>     ...
> mip N：整张图一个深度值
> ```

**加速原理**：

```
在低分辨率 mip 上走大步 → 一步跨越很多像素
如果低 mip 显示"这个区域没有表面" → 直接跳过
如果显示"这个区域可能有表面" → 降到高分辨率 mip 精细步进
```

> [!tip] 类比
> 先看地图概览确定大致方向，再放大地图看细节。

### 3.6 SSR 的效果

```
没有 SSR：                   有 SSR：

┌──────────────┐            ┌──────────────┐
│              │            │    ┌────┐   │
│   地面纯色    │            │   │反光│    │
│   没有反射    │            │   │    │    │
│              │            │  地面反射了   │
│              │            │  上面的物体   │
└──────────────┘            └──────────────┘
```

### 3.7 SSR 的局限

> [!warning] SSR 的局限
> - **看不到屏幕外**：反射目标在画面外就找不到
> - **屏幕边缘消失**：接近边缘的反射射线会走出屏幕
> - **厚度问题**：不知道几何体的厚度，可能穿透薄物体
> - **噪声**：离散步进可能跳过小物体 → 需要时序累积降噪

## 4 SSAO 和 SSR 的对比

> [!summary] 对比表
>
> | | SSAO | SSR |
> |---|---|---|
> | **解决什么** | 角落和缝隙的间接光遮蔽 | 光滑表面的环境反射 |
> | **输入** | 深度图 | 深度图 + 法线 + 颜色图 |
> | **方法** | 周围撒采样点比深度 | 沿反射方向步进深度图 |
> | **输出** | 遮蔽率（标量 0~1） | 反射颜色（RGB） |
> | **屏幕空间局限** | 感受不到画面外的遮挡物 | 找不到画面外的反射目标 |
> | **加速结构** | 无（直接采样） | HZB（层级深度图） |

## 5 在 TuanjieGI 中的角色

> [!important] TuanjieGI 的 ScreenTracer 本质就是 SSR
> TuanjieGI 的 **ScreenTracer** 在屏幕空间沿射线方向步进 HZB 深度图，找到命中点后读取颜色图作为间接光。

但 TuanjieGI 不止用 ScreenTracer。因为屏幕空间的根本局限是**看不到画面外的东西**，所以 TuanjieGI 有一套级联回退策略：

```
射线发射后，依次尝试：

1. ScreenTracer（屏幕空间，最快）
   ↓ 没命中（射线走出屏幕了）
2. SDFTracer（SDF 空间，可以追踪屏幕外）
   ↓ 没命中（距离太远）
3. CascadedSDFTracer（级联 SDF，可追踪很远）
   ↓ 没命中
4. （可选）硬件光追踪（最精确，需要 RTX GPU）
```

> [!tip] SSAO 对应的 TuanjieGI 组件
> SSAO 对应的是 TuanjieGI 的 **Bent Normal** 追踪——不只判断"被挡了多少"，还记录"被哪个方向挡了"，得到一个"弯曲后的法线"用于更准确的间接光计算。TuanjieGI 在 HDRP 路径中启用了 Bent Normal（`useBentNormal = true`），URP 路径没有（`useBentNormal = false`）。

## 6 关键概念速查

> [!summary] 速查表
>
> | 概念 | 一句话 |
> |---|---|
> | 屏幕空间 | 只用屏幕上已有的 2D 纹理（深度、法线、颜色）做近似 |
> | SSAO | 在像素周围撒采样点，比深度图判断遮挡，压暗角落 |
> | SSR | 沿反射方向在屏幕空间步进深度图，找到反射目标的颜色 |
> | HZB | 多级深度图，先大步跳过空区域再精细搜索，加速步进 |
> | Bent Normal | "最少被遮挡方向"的法线，比 SSAO 多了方向信息 |
> | 屏幕空间局限 | 看不到画面外的几何体 |
> | TuanjieGI 的回退 | ScreenTracer → SDFTracer → CascadedSDFTracer |
