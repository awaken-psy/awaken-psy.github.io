# 第 10 章：混合密度

## 本章核心

第九章已经能够直接朝光源采样，但只使用光源 PDF 会忽略材质本身偏好的方向。

第十章把两种各有所长的采样策略组合起来：

$$
\boxed{
p_{mix}(\omega)
=
\frac12p_{light}(\omega)
+
\frac12p_{surface}(\omega)
}
$$

- $p_{light}$ 知道光从哪里来；
- $p_{surface}$ 知道材质更容易向哪里散射；
- 混合分布同时覆盖直接照明、材质高贡献方向和部分间接光路径。

> 混合的是“方向生成的概率分布”，不是把两次渲染出的颜色简单平均。

上一章：[[学习笔记/cg/rt in one weekend/rest_life/09-直接采样光源.md|第 9 章：直接采样光源]]。

## 为什么不能永远只朝灯采样

Lambertian 材质的自然采样分布是：

$$
p_{surface}(\omega)
=
\frac{\max(0,\cos\theta_S)}{\pi}
$$

它把更多样本放在表面法线附近，因为 Lambertian 的物理贡献本来就含有接收面余弦。

光源采样则使用：

$$
p_{light}(\omega)
=
\frac{r^2}{A_L|\cos\theta_L|}
$$

它能显著提高小光源被命中的概率，但不会考虑当前材质的方向偏好。

因此两种单独使用时各有局限：

| 采样策略 | 优点 | 局限 |
|---|---|---|
| 只用材质 PDF | 符合材质响应，适合间接反弹 | 小光源很难被随机命中 |
| 只用光源 PDF | 直接照明方差低 | 忽略材质偏好的方向和其他重要路径 |
| 混合 PDF | 同时照顾光源和材质 | 需要正确计算完整混合密度 |

## 线性混合为什么仍然是合法 PDF

一般的混合密度为：

$$
p_{mix}(\omega)
=
\sum_{i=0}^{n-1}w_i p_i(\omega)
$$

只要：

$$
w_i\ge0,
\qquad
\sum_iw_i=1
$$

并且每个 $p_i$ 都已经归一化，那么：

$$
\begin{aligned}
\int p_{mix}(\omega)d\omega
&=
\int\sum_iw_ip_i(\omega)d\omega\\
&=
\sum_iw_i\int p_i(\omega)d\omega\\
&=
\sum_iw_i\\
&=1
\end{aligned}
$$

所以任意非负、权重和为 1 的 PDF 加权平均仍然是 PDF。

书中使用 $0.5/0.5$ 只是简单策略，不是物理常数。也可以使用：

$$
p_{mix}=0.8p_{light}+0.2p_{surface}
$$

但生成器与密度评估必须同步采用相同权重。

## 生成混合分布

若使用等权混合，生成过程是：

```cpp
if (random_double() < 0.5)
    return p0->generate();
else
    return p1->generate();
```

这相当于一个两阶段随机实验：

1. 以 $0.5$ 的概率选择 $p_0$ 或 $p_1$；
2. 再从选中的子 PDF 中生成方向。

对一个很小的方向区域 $d\omega$：

$$
\begin{aligned}
P(\omega\in d\omega)
&=
P(\text{选 }p_0)P(\omega\in d\omega\mid p_0)\\
&\quad+
P(\text{选 }p_1)P(\omega\in d\omega\mid p_1)\\
&=
\frac12p_0(\omega)d\omega
+
\frac12p_1(\omega)d\omega
\end{aligned}
$$

因此生成器的真实方向密度就是：

$$
p_{mix}(\omega)
=
\frac12p_0(\omega)
+
\frac12p_1(\omega)
$$

## 为什么分母必须评估两个子 PDF

不能写成：

```text
如果方向来自 p0，就只用 p0(direction)
如果方向来自 p1，就只用 p1(direction)
```

原因是同一个方向可能同时由两个分布产生。

例如一个方向既接近表面法线，又恰好指向灯：

- `cosine_pdf` 可能生成它；
- `hittable_pdf` 也可能生成它。

积分器关心的是整个采样程序产生该方向的总密度，而不是这一次内部恰好选中了哪个分支。

因此必须始终计算：

$$
\boxed{
p_{mix}(\omega)
=
\frac12p_0(\omega)
+
\frac12p_1(\omega)
}
$$

例如：

$$
p_{light}(\omega)=0.08,
\qquad
p_{surface}(\omega)=0.12
$$

则：

$$
p_{mix}(\omega)
=0.5(0.08)+0.5(0.12)
=0.10
$$

即使本次方向由 `light_pdf.generate()` 产生，分母也必须使用 $0.10$，不能只使用 $0.08$。

## `pdf` 抽象接口

文件：`rest_life/pdf.h`

```cpp
class pdf {
  public:
    virtual ~pdf() {}

    virtual double value(
        const vec3& direction
    ) const = 0;

    virtual vec3 generate() const = 0;
};
```

两个函数是同一个分布的两面：

| 函数 | 责任 |
|---|---|
| `generate()` | 按 $p(\omega)$ 生成方向 |
| `value(direction)` | 返回该方向在同一分布中的密度 |

它们必须严格配套。如果生成分布与分母中的 PDF 不一致，Monte Carlo 估计会产生偏差。

## `sphere_pdf`

```cpp
class sphere_pdf : public pdf {
  public:
    double value(const vec3& direction) const override {
        return 1 / (4*pi);
    }

    vec3 generate() const override {
        return random_unit_vector();
    }
};
```

它在整个单位球面上均匀采样：

$$
p(\omega)=\frac1{4\pi}
$$

主要用于各向同性体积散射。因为密度处处相同，所以 `value()` 与具体方向无关。

## `cosine_pdf`

```cpp
class cosine_pdf : public pdf {
  public:
    cosine_pdf(const vec3& w) : uvw(w) {}

    double value(const vec3& direction) const override {
        auto cosine_theta =
            dot(unit_vector(direction), uvw.w());

        return std::fmax(0, cosine_theta/pi);
    }

    vec3 generate() const override {
        return uvw.transform(
            random_cosine_direction()
        );
    }

  private:
    onb uvw;
};
```

`random_cosine_direction()` 先围绕局部 $+z$ 生成方向，ONB 再把局部 $+z$ 旋转到真实表面法线。

对应密度：

$$
p(\omega)
=
\frac{\max(0,\cos\theta)}{\pi}
$$

## `hittable_pdf`

```cpp
class hittable_pdf : public pdf {
  public:
    hittable_pdf(
        const hittable& objects,
        const point3& origin
    ) : objects(objects), origin(origin) {}

    double value(const vec3& direction) const override {
        return objects.pdf_value(origin, direction);
    }

    vec3 generate() const override {
        return objects.random(origin);
    }
};
```

它是 PDF 层和几何层之间的适配器：

- `pdf` 接口要求 `generate/value`；
- `hittable` 接口提供 `random/pdf_value`；
- `hittable_pdf` 将二者连接起来。

其中 `objects` 不一定是发光物体，也可以是玻璃球、窗口等值得提高采样概率的几何体。

## `mixture_pdf`

```cpp
class mixture_pdf : public pdf {
  public:
    mixture_pdf(shared_ptr<pdf> p0,
                shared_ptr<pdf> p1) {
        p[0] = p0;
        p[1] = p1;
    }

    double value(const vec3& direction) const override {
        return 0.5 * p[0]->value(direction)
             + 0.5 * p[1]->value(direction);
    }

    vec3 generate() const override {
        if (random_double() < 0.5)
            return p[0]->generate();
        else
            return p[1]->generate();
    }
};
```

这里最重要的契约是：

```text
generate() 的选择权重
            =
value() 的混合权重
```

## 在 `camera::ray_color()` 中使用

```cpp
auto light_ptr =
    make_shared<hittable_pdf>(lights, rec.p);

mixture_pdf p(light_ptr, srec.pdf_ptr);

ray scattered(
    rec.p,
    p.generate(),
    r.time()
);

auto pdf_value =
    p.value(scattered.direction());
```

然后计算：

```cpp
color color_from_scatter =
    srec.attenuation
    * scattering_pdf
    * sample_color
    / pdf_value;
```

数学形式：

$$
C_o
\approx
C_e
+
\frac{
A\,p_{scatter}(\omega)\,C_i(\omega)
}{
p_{mix}(\omega)
}
$$

## 为什么结果仍然无偏

令：

$$
f(\omega)
=
A\,p_{scatter}(\omega)C_i(\omega)
$$

方向按照 $p_{mix}$ 生成：

$$
\omega\sim p_{mix}
$$

则：

$$
\begin{aligned}
E\left[
\frac{f(\omega)}{p_{mix}(\omega)}
\right]
&=
\int
\frac{f(\omega)}{p_{mix}(\omega)}
p_{mix}(\omega)d\omega\\
&=
\int f(\omega)d\omega
\end{aligned}
$$

混合分布只改变寻找方向的效率，不改变目标积分。

但还需要保证：

1. `generate()` 与 `value()` 表示同一个实际分布；
2. 权重非负且总和为 1；
3. 凡是被积函数可能非零的方向，都必须满足 $p_{mix}(\omega)>0$。

## 本章结论

$$
\boxed{
\text{材质 PDF 知道表面偏好}
+
\text{光源 PDF 知道光在哪里}
\Longrightarrow
\text{更低方差的混合采样}
}
$$

> `generate()` 可以只选择一个子 PDF 生成本次方向，但 `value()` 必须返回整个混合采样器产生该方向的总密度。
