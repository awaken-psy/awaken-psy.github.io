# 第 11 章：架构决策

## 本章核心

这一章不引入新代码，而是决定渲染器接下来采用什么结构。

主要问题有四个：

1. 继续使用混合密度，还是改用传统阴影光线；
2. 如何移除 `ray_color()` 中硬编码的材质 PDF；
3. 如何恢复被普通 PDF 架构破坏的理想金属和玻璃；
4. 是否在当前阶段扩展背景、HDR、光谱和偏振系统。

上一章：[[学习笔记/cg/rt in one weekend/rest_life/10-混合密度.md|第 10 章：混合密度]]。

## 混合密度与阴影光线

### 混合密度路线

第十章的路径是：

```text
当前交点
   ↓
从材质 PDF 或重要物体 PDF 中选择一个
   ↓
生成一条新的路径光线
   ↓
继续递归追踪
```

光源采样方向仍然是一条普通路径光线。它命中什么、是否被遮挡、是否继续反弹，都由场景求交和递归自然决定。

### 阴影光线路线

传统直接光照通常在每个交点额外发出阴影光线：

```text
当前交点
   ├── 阴影光线：只检查交点到灯之间是否可见
   └── 路径光线：继续计算后续间接反弹
```

阴影光线有几个特点：

- 通常直接瞄准某个光源；
- 命中遮挡物或灯后立即终止；
- 不继续递归反弹，因此单条光线较便宜；
- 可以一次发送多条，例如 1、4、8 或 16 条，以改善直接光照估计。

## 两条路线的比较

| 混合密度 | 阴影光线 |
|---|---|
| 从多个 PDF 中选择一条继续递归的方向 | 额外发射终止型可见性射线 |
| 一套 $f/p$ 估计器统一处理 | 通常把直接光和路径延续分开计算 |
| 可以把灯、窗口、玻璃球、亮门缝都作为采样目标 | 传统形式主要对发光体做直接采样 |
| 光线可能继续反弹，成本较高 | 遇到遮挡或灯即终止，通常更便宜 |
| 适合本书统一讲解重要性采样 | 在专业和实时渲染器中很常见 |

两种方法都可以产生正确结果。它们的主要区别是：

- 代码结构；
- 每次着色需要发出多少光线；
- 每条光线的成本；
- 如何组合直接光与间接光；
- 在具体场景中的方差。

本书选择继续使用混合密度，因为它可以采样任意“重要方向”，不局限于传统发光体，而且能继续沿用统一的 PDF 框架。

## 当前代码的职责混乱

第十章阶段的 `ray_color()` 会直接创建：

```cpp
auto p0 = make_shared<hittable_pdf>(lights, rec.p);
auto p1 = make_shared<cosine_pdf>(rec.normal);
mixture_pdf mixed_pdf(p0, p1);
```

其中第二行隐含了一个硬编码假设：

```text
所有材质都应该使用 cosine_pdf
```

但这不成立：

- Lambertian 适合 `cosine_pdf`；
- 各向同性介质适合 `sphere_pdf`；
- 其他粗糙材质可能有自己的连续分布；
- 理想金属和玻璃根本不能用普通有限 PDF 表示。

因此材质 PDF 应由材质自己选择，而不是由 `camera` 根据表面法线猜测。

## 连续散射与 Delta 散射

### 连续散射

Lambertian 可以朝整个上半球散射：

$$
p_{Lambertian}(\omega)
=
\frac{\max(0,\cos\theta)}{\pi}
$$

它是普通连续密度，可以正常执行：

```cpp
direction = pdf.generate();
weight = f(direction) / pdf.value(direction);
```

### 理想镜面

理想镜面只允许一个方向：

$$
\omega_r
=
\operatorname{reflect}(\omega_i,n)
$$

数学上它对应狄拉克 Delta：

$$
p(\omega)
=
\delta(\omega-\omega_r)
$$

直观上：

- 除了精确反射方向，其他方向密度为 0；
- 所有概率质量集中在一个没有立体角面积的方向上；
- 精确方向处的密度不能用普通有限浮点数表达。

如果强行塞进 `double pdf_value`，容易产生：

```text
0、无穷大、除零或 NaN
```

### 理想玻璃

理想玻璃通常在两个离散方向之间选择：

- 反射方向；
- 折射方向。

全反射时只能反射；否则根据 Fresnel/Schlick 反射率随机选择反射或折射。

这仍然是离散 Delta 事件，而不是普通的球面连续分布。

## 两种镜面解决方案

### 方案一：使用很小但非零的粗糙度

把无限窄的镜面方向扩展成很窄的连续波瓣：

```text
理想镜面 → 几乎镜面
```

优点是可以继续使用普通 PDF；缺点是材质已经不再是严格理想镜面，而且很窄的波瓣仍可能产生数值和采样问题。

### 方案二：镜面作为特殊路径

由材质直接生成反射或折射光线，并跳过显式的：

$$
\frac{f(\omega)}{p(\omega)}
$$

当前代码已经有平滑金属和玻璃，因此本书选择第二种方案。

> “跳过 PDF”不是不考虑概率，而是不把 Delta 分布强行转换成一个普通 `double`。反射/折射选择和对应权重由材质的专用采样规则隐式处理。

## `scatter_record` 的设计目标

下一章将使用一个统一记录同时表示两种情况：

```cpp
class scatter_record {
  public:
    color attenuation;
    shared_ptr<pdf> pdf_ptr;
    bool skip_pdf;
    ray skip_pdf_ray;
};
```

### 连续散射

```text
attenuation = 能量/颜色因子
pdf_ptr      = 材质建议的连续 PDF
skip_pdf     = false
```

积分器随后把 `pdf_ptr` 与重要物体 PDF 混合，并计算 $f/p$。

### Delta 散射

```text
attenuation  = 能量/颜色因子
pdf_ptr      = nullptr
skip_pdf     = true
skip_pdf_ray = 材质直接生成的反射/折射光线
```

积分器直接递归追踪 `skip_pdf_ray`。

## 合理的职责划分

| 组件 | 责任 |
|---|---|
| `material` | 决定物理散射和适合自己的采样方式 |
| `pdf` | 保证 `generate()` 与 `value()` 描述同一分布 |
| `hittable` | 描述怎样朝某个几何体生成方向 |
| `camera` / 积分器 | 组合材质与重要物体策略并计算 $f/p$ |

这种结构有两个好处：

1. `camera` 不需要知道具体材质类型；
2. 新材质可以提供自己的 PDF，而无需改动积分器的材质判断逻辑。

## 背景和颜色系统的取舍

本章还指出了当前渲染器的其他局限：

- 背景只是一个简单颜色；
- 没有完整环境贴图接口；
- 环境贴图可能需要 HDR 数据；
- 渲染器内部使用浮点 RGB；
- 更物理精确的系统可能使用光谱甚至偏振。

作者决定暂时保持 RGB 和简单背景，把重点放在 PDF、散射和积分器架构上。

这是一个范围决策，而不是说光谱渲染不重要。

## 当前代码中的最终形态

当前 `rest_life/camera.h` 已经采用下一章完成后的结构。

连续散射：

```cpp
auto light_ptr =
    make_shared<hittable_pdf>(lights, rec.p);

mixture_pdf p(light_ptr, srec.pdf_ptr);

ray scattered(rec.p, p.generate(), r.time());
auto pdf_value = p.value(scattered.direction());
```

Delta 散射：

```cpp
if (srec.skip_pdf) {
    return srec.attenuation
         * ray_color(
               srec.skip_pdf_ray,
               depth-1,
               world,
               lights
           );
}
```

所以最终架构是：

```text
连续材质 → 显式 PDF → mixture_pdf → f/p
Delta 材质 → skip_pdf_ray → 直接递归
```

## 本章结论

第十一章做出的决定是：

1. 保留混合密度方案；
2. 让材质返回自己的 PDF；
3. 连续散射继续使用显式 $f/p$；
4. 理想金属和玻璃作为 Delta 特例处理；
5. 暂时保持 RGB 和简单背景。

> “生成器与修正 PDF 一致”仍然是连续采样的核心规则；第十一章补充的边界是：理想镜面和理想折射属于 Delta 测度，不能由普通有限的 `pdf_value()` 表示。
