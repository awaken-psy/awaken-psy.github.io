# 08 实现管线与赛道收官

> 本篇在思维链上的位置：**收官**。先把 SSGI 从采样到写回的全流程串成一条线、算清三本账，然后把它放上 GI 赛道——在那里它会贡献一个新的身份：继"烘、推、烤、算"之后的第五种场来历，**读**。

## 全流程管线

```text
本帧（顺序）
  ① GBuffer：深度 / 法线 / albedo / motion vector
  ② history：上一帧线性 HDR 颜色 + 上帧累积状态（重投影对齐到本帧）
  ③ Trace（半分辨率）：
       探针网格（8×8 px）× 64 根余弦加权射线
       → Hi-Z 屏幕步进 → 命中读色（四道拒收）→ 距离衰减
       → 聚合成每探针的 SH L2 / 八面体辐照
  ④ 重建：
       可分离双边滤波（深度/法线权重）→ 重组升回全屏
       时间累积 EMA + history clamp + 动态 rejection
  ⑤ 合成：间接漫反射 GI × albedo + 直接光 + emissive
  ⑥ 写回：本帧输出写入 history buffer —— 闭合 [[06-反馈循环-多弹射的诞生]] 的环
```

## 三本账

| 账 | SSGI 的立场 |
|---|---|
| **样本** | 每像素等效 1 根（探针共享 64 根）；帧轴 × 降噪补——**采样是全场最穷的 GI** |
| **性能** | 半分辨率 trace + 可分离滤波；无场更新、无烘焙、零额外资产——**帧内成本可控，帧间成本为零** |
| **内存** | 几张全屏 RT（history/速度/中间 SH）——对照 APV 的磁盘流式资产，SSGI **没有任何资产** |

第三行值得咀嚼：全 GI 赛道里，**只有 SSGI 的"场"不需要任何预计算与存储**——因为它的场就是上一帧的输出，渲染反正要渲。这是"读"派的注册商标。

## "场从哪来"：第五种来历

把 [[学习笔记/cg/games202/专题/apv/08-实现管线与GI赛道对照.md|08 实现管线与 GI 赛道对照]] 的三档来历扩成五档：

| 来历 | 代表 | 场怎么有 | 有什么代价 |
|---|---|---|---|
| **烘** | APV / Lightmap / LPG | 离线烤好答案 | 静态假设、需资产管线 |
| **推** | LPV（[[学习笔记/cg/games202/专题/lpv/08-动态GI赛道与对照.md|08 动态 GI 赛道与对照：LPV 的位置和它的思想后裔]]） | 每帧从光源推 | 无遮挡、粒度粗 |
| **烤** | VXGI（[[学习笔记/cg/games202/专题/vxgi/08-四法对照与收官.md|08 四法对照与收官：PRT × IBL × LPV × VXGI]]） | 每帧重体素化 | 内存与更新成本巨大 |
| **算** | Lumen / TuanjieGI（[[学习笔记/cg/tuanjie引擎/GI原理/00-全景/01-TuanjieGI是什么.md|TuanjieGI 是什么]]） | 每帧实算射线+缓存 | 平台门槛高 |
| **读** | **SSGI** | **直接复用上一帧的画面** | **被屏幕边界钉死** |

"读"是 [[学习笔记/cg/games202/专题/ibr/02-渲染谱.md|02 渲染谱：从几何到图像的连续谱]] 兑换率的极端案例：**运行时计算几乎为零——因为账单已经在上一帧付过了**。它是 impostor 思想（[[学习笔记/cg/games202/专题/ibr/09-替代物.md|09 替代物（Impostor）：缓存一次渲染，顶替整个物体]]：缓存一次渲染反复用）在时间维上的化身：impostor 缓存"别的视角"，SSGI 缓存"上一刻的世界"。

## 赛道终局对照（合龙版）

| 系统 | 场 | 来历 | 分辨率 | 屏幕外 | 动态几何 | 多弹 | 平台 |
|---|---|---|---|---|---|---|---|
| Lightmap | 表面纹理 | 烘 | 纹素 | ✓ | ✗ | ✓（离线） | 全平台 |
| **APV** | brick 探针场 | 烘+拆分 | 米级 | ✓ | ✗ | ✓（离线） | SM4.5 |
| **LPV** | 均匀 SH 格 | 推 | 格子级 | ✓ | ✓ | 弱 | 中端 |
| **VXGI** | 体素 mip | 烤 | 体素级 | ✓ | ✓ | ✓ | 高端 |
| **SSGI** | 上一帧画面 | **读** | **像素级** | **✗** | ✓ | **帧反馈** | 中端 |
| Lumen / TuanjieGI | 屏幕+世界双层 | 算 | 像素+表面 | ✓ | 部分 | ✓ | 中高端 |
| RTGI + 降噪 | BVH 实算 | 算 | 像素 | ✓ | ✓ | ✓ | 光追硬件 |

读法：**SSGI 独占"像素级 + 全动态 + 零资产"** 三项，代价是屏幕外归零——所以它几乎注定活在混合管线里（[[学习笔记/cg/games202/专题/ssgi/07-缺陷与混合管线.md|07 缺陷与混合管线：屏幕之外没有世界]] 的结论），而它的四层功夫（采样/缓存/重建/反馈）在 RTGI 时代原样可迁移。

## 记忆压缩

> **SSGI = 用上一帧付账的 GI**：场不烘、不推、不烤、不算，直接"读"——这是全赛道唯一的零资产方案；代价是户口被钉在屏幕里，所以注定当混合管线的细节层。它教的技术里最值钱的是那套"预算→噪声→重建"的工程纪律：**采样可以穷到一根，重建必须富到时空两轴**——这套纪律今天撑着 SSGI，明天原样撑起 RTGI。屏幕空间一脉，至此收官。
