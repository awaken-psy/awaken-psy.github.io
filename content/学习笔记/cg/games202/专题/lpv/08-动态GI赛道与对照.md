# 08 动态 GI 赛道与对照：LPV 的位置和它的思想后裔

> 本篇在思维链上的位置：**收官**。把 LPV 放进动态 GI 方法梯度里，看它解决了什么、被什么解决，最后把四个专题（PRT / IBL / LPV / VXGI）的"场与查询"句式写完整。

## 为什么必须换赛道

PRT/IBL 的预计算之所以成立，靠的是**变化时间尺度的分离**（慢变因子离线算）。动态 GI 的需求恰恰相反：

```text
物体在动 → V 变化 → 传输因子每帧都变 → 没有任何东西是"慢变"的
```

于是所有动态 GI 方法都在回答同一个问题：**每帧预算内，用什么便宜结构近似传输？** LPV 的答案是一张会流动的 3D SH 场。这个赛道的其他选手：

| 方法 | 传输的近似结构 | 一句话 |
|---|---|---|
| RSM | 不近似，直接采样几百个 VPL | 每像素自己算，贵在重复 |
| **LPV** | 3D SH 场 + 固定传播算子 | 算一次推全场，输在无遮挡 |
| VXGI（[[学习笔记/cg/games202/专题/vxgi/01-VXGI原理主线.md|VXGI 原理主线：体素场上的锥形拉光]]） | 体素 mip 场 + 锥形拉取 | 拉光自带遮挡，贵在锥追 |
| SSDO / SSGI | 屏幕空间深度场 | 只有屏幕内可见的传输 |
| RTRT | 不近似，直接积分 | 贵但终极 |

## 推与拉：LPV 与 VXGI 的分水岭

把两个专题的关系压缩成一张图：

```text
LPV（推）：光源视角出发
    把能量从发点向全场"广播"，不管谁需要
    优点：一次传播全场复用
    缺点：广播不问遮挡 → 漏光

VXGI（拉）：着色点出发
    每个点自己去"采集"周围的预滤波场
    优点：采集时顺带问遮挡（α 合成）
    缺点：每个点都要采一遍 → 贵
```

**同一个场的两种遍历方向**：推（scatter，从光源）与拉（gather，从着色点）。PRT 其实是"推"（离线推好每点传输），IBL 是"拉"（每点查图）。四个专题在这张地图上各占一角。

## LPV 的思想后裔

作为具体技术，LPV 在 3A 中已被探针 GI 与 RTRT 取代；但它的两个思想活了下来：

1. **"光的网格场 + 传播/更新"**：现代引擎的 irradiance volume、网格探针（[[学习笔记/cg/games202/专题/ibl/08-局限与PRT对照.md|08 IBL 的局限、探针修补与 PRT 对照]] 里 IBL 探针的体积化），本质上就是"把 LPV 的格子场换成探针网格、把传播换成离线烘焙/帧间更新"——同一个空间共享思想的更稳形态。
2. **"与场景脱钩的传输算子"**：预计算"数学"而不是"场景"，让动态成为可能。这条思路后来也活在 DDGI 一类探针 GI 的更新逻辑里。

## 四专题并排：句式的完成

| | 压成什么场/表 | 查询动作 | 丢掉了什么 | 动态吗 |
|---|---|---|---|---|
| PRT | 每点 SH 传输系数 | 点乘 | 光照高频 | ❌ |
| IBL | 2D 预滤波 mip + LUT | 查两次 | 遮挡 | ⭕（场景动，天空换得贵） |
| LPV | 3D SH 光场（推出来的） | 插值 + SH 求值 | 遮挡、空间/方向分辨率 | ⭕ |
| VXGI | 3D 体素 mip 光场（烤出来的） | 锥形追踪 | 精度换内存换成本 | ⭕（重体素化贵） |

$$
\boxed{
\text{实时渲染的一门手艺}：
\text{找到贵的东西} \to \text{压成场或表} \to \text{运行时只做便宜查询}
}
$$

四个专题是这个句式的四次实现，差别只在**压什么（传输/光照）、压到什么域（2D/3D/每点）、查询是什么（点乘/查表/插值/锥追）**。而 RTRT 的威胁对四个专题一视同仁：算力足够时，不压、直接算。

## 全专题最终结论

$$
\boxed{
\text{LPV}
=
\underbrace{\text{RSM 每帧收集二级光源}}_{\text{动态的燃料}}
+
\underbrace{\text{SH 场：空间粗、方向粗}}_{\text{压缩}}
+
\underbrace{\text{每轮一格的无遮挡传播}}_{\text{速度与漏光的共同来源}}
}
$$

> 记住 LPV 只需要一句：**把光当流体，倒进格子，推几轮，大家来查**。它的全部优点（便宜、动态、规整）和全部缺点（漏光、低频、闪烁）都长在"格子+传播"这同一个决定上。
