# 02 环境光阴影的困境：实时渲染为什么算不动

> 本篇在思维链上的位置：**提出问题**。先看清敌人长什么样，才能理解 PRT 为什么这样设计。

## 承接：IBL 遗留的假设

在 [[学习笔记/cg/games202/lecture5 Real-time Environment Mapping 1.md|lecture5 Real-time Environment Mapping 1]] 中，我们已经解决过"环境光 + 任意 BRDF"的着色：

```text
split-sum / prefiltering
    把环境光按粗糙度预先模糊，BRDF 项存进二维 LUT
    运行时：一次纹理查询 + 一次查表
```

但它悄悄用了一个假设：**visibility 恒等于 1**。

$$
L_o(\omega_o)
=
\int_{\Omega^+}
L(\omega_i)\,
f_r(\omega_i,\omega_o)\,
\cos\theta_i\,
\underbrace{V(p,\omega_i)}_{\text{被假设为 1}}
\,d\omega_i
$$

没有 $V$，光照是唯一的空间变量，才能对所有点**共享**同一张预滤波贴图。一旦把阴影放回方程，每个点被照亮的情况都不同，一张共享贴图就不够了。

PRT 的起点，就是把 $V$ 认真地放回来。

## 渲染方程的完整形式

$$
\boxed{
L_o(p,\omega_o)
=
\int_{\Omega^+}
L(\omega_i)\,
f_r(\omega_i,\omega_o)\,
\cos\theta_i\,
V(p,\omega_i)\,
d\omega_i
}
$$

| 因子 | 依赖什么 | 变化频率 |
|---|---|---|
| $L(\omega_i)$ 环境光 | 只依赖方向（无限远） | 天空级，天然低频 |
| $f_r$ BRDF | 材质 + 两端方向 | 漫反射=常数；镜面=冲激 |
| $\cos\theta_i$ | 入射方向与法线夹角 | 低频（一阶多项式截断） |
| $V(p,\omega_i)$ 遮挡 | **点 + 方向** | 可以非常高频（硬阴影边缘） |

注意 $V$ 的依赖项是 $(p,\omega_i)$——**每个点**在**每个方向**上都要单独回答"这条光路上有没有东西挡着"。这就是问题所在。

## 为什么环境光下的阴影特别难

### 环境光的本质：无穷多盏方向光

环境贴图的每一个 texel 都是一盏小方向光。要给这样的光源做阴影：

```text
方案A：每个 texel 生成一张 shadow map
    → texel 数量上万，存储和绘制都爆炸
    
方案B：只给最亮的一(几)盏"代表光"做 shadow map
    → 工业界的妥协方案，阴影与真实环境光不匹配
    
方案C：光线追踪
    每个着色点、每个入射方向发一条 shadow ray
    → 结果正确，但实时帧预算下采样数远远不够
```

方案 C 在离线渲染里天天用（[[学习笔记/cg/rt in one weekend/rest_life/09-直接采样光源.md|第 9 章：直接采样光源]] 里的直接光采样就是它的工程化形态），代价是**每帧每点都要发射成百上千条射线**。实时渲染一帧只有几毫秒，这条路在当年（2002 年，也在很大程度上包括现在）走不通。

### 困境的数学结构

$$
\underbrace{\int_{\Omega}}_{\text{球面积分}}
\underbrace{L(\omega_i)}_{\text{换灯才变}}
\underbrace{T(p,\omega_i)}_{\text{动场景才变}}
d\omega_i,
\qquad
T = f_r\cdot\cos\theta_i\cdot V
$$

乘积积分的三个因子，**变化的时间尺度完全不同**。这就是整个 PRT 赖以成立的关键观察。

## 关键观察：变化时间尺度的分离

把视角从"空间频率"切换到"变化时间尺度"：

| 因子 | 什么时候变 | 一旦确定，多久有效 |
|---|---|---|
| 光照 $L(\omega)$ | 换环境贴图 / 旋转天空时 | 只要不换灯，永远有效 |
| 传输 $T(p,\omega)$ | 物体移动 / 变形 / 换材质时 | 只要场景静止，**每帧都一样** |

实时渲染的典型情形正是：**光照会旋转/切换，但场景几何在大部分时间里是静止的**。

> 于是自然产生一个念头：既然传输每帧都不变，能不能把它**预先**算好？"预计算"的诱惑一直存在，问题在于——预计算出来的结果必须**足够小**（每个点只能存少量数字），而且运行时必须能和任意光照**快速组合**。这正是 [[学习笔记/cg/games202/专题/prt/03-函数即向量-基函数与投影.md|03 函数即向量：基函数、投影与正交]] 要解决的数学问题。

![product integral 的频率论证](<Attachments/Pasted image 20260808133811.png>)

另一个有用的视角是频率：product integral 的结果频率由被积函数中**最低频率**的一方决定（[[学习笔记/cg/games202/lecture6 Real-time Environment Mapping 2.md|lecture6 Real-time Environment Mapping 2]] 的结论）。自然天空是低频的，所以无论传输多复杂，最终答案也是低频的——这暗示我们：即使只保留光照的低频成分，答案也不会错得太离谱。这个直觉将在 [[学习笔记/cg/games202/专题/prt/05-漫反射PRT-从积分到点乘.md|05 漫反射 PRT：把整个渲染方程压成一次点乘]] 中变成严格的论证。

## 困境重述与下一步

把问题整理成一句话：

> 每帧每点都算 $\int L\cdot T\,d\omega$ 付不起；两个因子的绝大部分内容在帧与帧之间根本不变。需要的工具是：能把"球面函数"变成"少量数字"，并且能让两个函数的积分变成这两组数字之间的廉价运算。

这个工具存在，它就是**正交基函数**。下一篇从"函数其实是向量"这个翻译开始。

## 本篇结论

$$
\boxed{
\text{环境光阴影}
=
\text{每点每方向一次遮挡查询}
\Rightarrow
\text{实时不可行}
\quad\Longrightarrow\quad
\text{需要把慢变的因子预计算成少量数字}
}
$$
