# 08 实现管线与 GI 赛道对照

> 本篇在思维链上的位置：**收官**。先把 APV 从烘焙到运行时的全流程串成一条线，算清三本账（内存/性能/平台），再把它放上 GI 赛道的审判台——与 Lightmap、LPV、VXGI、DDGI、Lumen、TuanjieGI 同台对照，给"建场派"的知识网补上最后一块拼图。

## 全流程管线

```text
离线（每场景一次）
  ① 贴 Contribute GI 的静态几何 + 标记 Mixed/Baked 灯
  ② 生成结构：Volume → cell → brick，按几何密度自适应细分（min/max spacing）
  ③ Progressive (GPU) Lightmapper：
       每探针积分间接光 → SH 辐照度系数
       + validity / virtual offset（几何知识落盘）
       + 天空可见度与主方向（拆分一的原材料）
       （可选）多套 lighting scenarios（拆分二的原材料）
  ④ 落盘：cell 为单位（Streaming Assets 或 Addressables/AssetBundle）
运行时（每帧）
  ⑤ 流入：视锥内 cell 磁盘 → CPU → GPU
  ⑥ 着色查询：采样位置（+ bias、virtual offset）→ 三线性 → SH 求值
       剔除/降权 invalid 探针；逐像素或逐顶点两档
  ⑦ 动态拆分：当前天空 × 天空可见度重积分；场景按权重混合
```

## 三本账

| 账 | APV 的立场 |
|---|---|
| **内存** | 约 32 字节/探针；比"间接光全上贴图"的 lightmap 省；三闸门（spacing / trimming / scenario 数）兜底 |
| **性能** | 查询 = 三线性 + 几次乘加；逐顶点档几乎白送，逐像素档移动端也扛得住；**没有每帧的场更新成本**（对照 LPV/VXGI 的传播/重体素化） |
| **平台** | URP 与 HDRP；SM4.5 起——**手机可跑**，这是它对 Lumen 类系统的最大差异点 |

## GI 赛道终局对照

| 系统 | 场（载体） | 场从哪来 | 几何在场里？ | 动态性 | 平台 |
|---|---|---|---|---|---|
| Lightmap | 表面 2D 纹理 | 烘焙 | 在（逐纹素） | ✗ 全静态 | 全平台 |
| LPG / LPPV | 稀疏点云 | 烘焙 | ✗ | ✗ | 全平台 |
| **APV** | **自适应 brick 探针场** | **烘焙 + 拆分** | **✗（存影子）** | **天空/灯状态** | **SM4.5，含手机** |
| LPV（[[学习笔记/cg/games202/专题/lpv/08-动态GI赛道与对照.md|08 动态 GI 赛道与对照：LPV 的位置和它的思想后裔]]） | 均匀 SH 格 | 每帧推 | ✗ | 全动态但粗糙 | 中端起 |
| VXGI（[[学习笔记/cg/games202/专题/vxgi/08-四法对照与收官.md|08 四法对照与收官：PRT × IBL × LPV × VXGI]]） | 体素 mip 场 | 每帧重烤 | 在（α） | 全动态 | 高端 |
| DDGI | 探针场 | 每帧射线更新 | 深度统计软遮挡 | 全动态 | 中高端 |
| Lumen / TuanjieGI（[[学习笔记/cg/tuanjie引擎/GI原理/00-全景/01-TuanjieGI是什么.md|TuanjieGI 是什么]]） | 屏幕 + 表面缓存 | 每帧实算 | 在（追踪） | 全动态 | 中高端 |

读法建议：按"**场从哪来**"分三档——**烘**（Lightmap/LPG/APV）、**推/烤**（LPV/VXGI/DDGI）、**算**（Lumen/TuanjieGI）——每往右一档动态性越强、平台门槛越高。APV 的独特身位是"烘"档里唯一同时给出**动态天光、动态物体受光、流式大世界**的方案。

## 与"建场派"知识网的合龙

把 [[学习笔记/cg/games202/专题/ss/08-屏幕空间对照与GI全景.md|08 屏幕空间三兄弟对照与 GI 全景]] 的场分辨率阶梯补上 APV 一格：

```text
场分辨率阶梯（从粗到细）
天空盒 2D 方向函数 → LPG 稀疏点 → LPV 均匀 3D SH → 【APV 自适应 3D SH】
→ 探针级动态（DDGI）→ VXGI 体素 mip → 表面探针/贴图（Lumen FinalGather / Facet）
```

- **与 LPV 的合龙**：同一种"3D SH 场 + 双插值查询"数据结构，一个每帧推（动态无遮挡）、一个离线烘（静态有修补）——本专题与 [[学习笔记/cg/games202/专题/lpv/01-LPV原理主线.md|LPV 原理主线：让光在格子里流动起来]] 隔空握手；
- **与 PRT 的合龙**：天空遮蔽 = 传输预计算 × 光照运行时点乘（[[学习笔记/cg/games202/专题/prt/05-漫反射PRT-从积分到点乘.md|05 漫反射 PRT：把整个渲染方程压成一次点乘]]）——探针是"低保真 PRT"；
- **与 ibr 的合龙**：APV 是 [[学习笔记/cg/games202/专题/ibr/02-渲染谱.md|02 渲染谱：从几何到图像的连续谱]] "预计算与运行时兑换"的教科书案例——把整条着色积分兑换成 32 字节 × 插值，再用拆分买回一部分自由度；
- **与 TuanjieGI 的合龙**：预计算+拆分 vs 每帧实算——两种产品哲学在"静态几何"这个假设上分道扬镳。

$$
\boxed{
\text{APV}
=
\underbrace{\text{自适应答案场}}_{\text{brick + SH}}
+
\underbrace{\text{几何的影子}}_{\text{validity / 偏移}}
+
\underbrace{\text{可变维度的拆分}}_{\text{天空 / 场景}}
\quad\Longrightarrow\quad
\text{静态大世界的间接光：手机也跑得动}
}
$$

## 记忆压缩

> **APV = 预计算答案场的工业完全体**：brick 让分辨率追着几何跑，32 字节探针让内存服帖，validity/偏移把烘焙时的几何知识存成校正量，天空与灯态拆出来现场重算——它不追"全动态"（那是 Lumen/TuanjieGI 的战场），它把"静态世界 + 动态天光 + 动态物体"这个最常见的品类做到**下限最低、上限够用**。探针系统的三代进化（摆位→离线遮挡→运行时遮挡）与建场派的三档来历（烘→推烤→算），是本专题留给 GI 赛道的两张地图。
