# 07 天空遮蔽与光照场景：把可变的拆出来

> 本篇在思维链上的位置：**动态性**——APV 眼里最核心的思想。烘焙的宿命是"静态"，APV 用两次**拆分**给自己松了绑：把"天空"从答案里拆出来（PRT 式的传输 × 光照），把"灯的状态"从答案里拆出来（多套烘焙 × 运行时混合）。一句话：**不把可变的维度烘死**。

## 拆分一：天空遮蔽（PRT 思想的探针版）

间接天光 = 天空（会变）× 探针处的天空可见度（不变）。把不变的先算好：

$$
\boxed{
E_{\text{sky}}(p,\mathbf n)
=
\big\langle
\underbrace{L_{\text{sky}}(\omega)}_{\text{运行时：随昼夜换}}
\;,\;
\underbrace{T_{\text{sky}}(p,\omega)}_{\text{烘焙：每探针的天空可见度}}
\big\rangle
}
$$

这正是 PRT 的"传输预计算 × 光照现场积分"结构（[[学习笔记/cg/games202/专题/prt/05-漫反射PRT-从积分到点乘.md|05 漫反射 PRT：把整个渲染方程压成一次点乘]]、[[学习笔记/cg/games202/专题/prt/01-PRT原理主线.md|PRT 原理主线：从环境光阴影难题到实时点乘]]）——只不过 APV 用的是极简的传输基：每探针一个**天空可见度**（再配一个**主方向 sky direction**，标记"天窗开在哪边"）。代价是近似的，收益是决定性的：

| 事件 | 需要重新烘焙吗 |
|---|---|
| 换天空盒 / 调整天空强度 | ✗——拿新 $L_{\text{sky}}$ 对 $T_{\text{sky}}$ 重新积分 |
| **太阳移动（昼夜循环）** | ✗——GDC 演示里拖动太阳，间接光实时跟随 |
| 体积云飘过、天空渐变 | ✗——同上 |

**天空被当作"运行时光照"而不是"烘焙答案"**——这是 APV 敢做开放世界昼夜循环的全部底气。

## 拆分二：光照场景（lighting scenarios）

第二类可变的是**灯的离散状态**：开灯/关灯、白天模式/夜晚模式、灯光秀。APV 的做法朴素而有效：

```text
scenario A（全亮）    → 一套完整探针数据
scenario B（夜灯）    → 一套完整探针数据
scenario C（应急灯）  → 一套完整探针数据
运行时：按权重混合（美术/脚本控制，空间上可过渡）
```

| 性质 | 说明 |
|---|---|
| 混合是**线性的** | 探针数据按权重插值即可——SH 系数的线性性（[[学习笔记/cg/games202/专题/prt/04-球谐函数.md|04 球谐函数：球面上的正交基]]）保证了混合的合法性 |
| 成本 = 数据 | 每多一套场景 = 一份完整探针数据（受 [[学习笔记/cg/games202/专题/apv/03-砖块与自适应细分.md|03 砖块与自适应细分：结构层的智慧]] 的内存闸门约束） |
| 状态空间是**离散的** | 能表达"这 N 种布置之间的过渡"，不能表达"任意新布置" |

## 动态化的边界：APV 管什么、不管什么

| 想要的动态 | APV 的态度 |
|---|---|
| 天空/太阳/昼夜 | ✓ 天空遮蔽，现场重积分 |
| 预设的灯状态切换 | ✓ 光照场景混合 |
| **动态几何** | ✗ 探针不重算（静态假设的产品边界） |
| **手持移动光源** | ✗ 归实时一弹（SSGI）或探针级动态系统（DDGI 一族） |
| 动态 albedo / 任意动态灯的完整间接 | ✗（Unity 官方将其列为"预计算动态 GI"的演进方向——在静态环境内扩展，尚未是 APV 本体的承诺） |

边界表右半边是 [[学习笔记/cg/games202/专题/apv/08-实现管线与GI赛道对照.md|08 实现管线与 GI 赛道对照]] 的入口：**APV 的"动态"是有预算的动态——每帧零重计算，只把可变维度从答案里拆出来现场算**。

## 两条路线的哲学对照

| | **预计算 + 拆分**（APV） | **每帧实算**（Lumen / [[学习笔记/cg/tuanjie引擎/GI原理/00-全景/01-TuanjieGI是什么.md|TuanjieGI 是什么]]） |
|---|---|---|
| 静态几何间接光 | 烘焙答案 | 每帧重算（屏幕 + 世界缓存） |
| 动态天空/灯 | 拆分出来现场积分 | 天然支持（本就在每帧算） |
| 动态几何 | ✗ | ✓ |
| 运行时成本 | 极低（插值+求值） | 高（射线/更新预算） |
| 平台下限 | SM4.5、手机可跑 | 中高端起 |

**没有更好的路线，只有产品假设的忠实映射**（[[学习笔记/cg/games202/专题/ibr/02-渲染谱.md|02 渲染谱：从几何到图像的连续谱]] 的老结论）：静态大世界 + 昼夜循环 + 手机要跑——APV 的每个选择都严丝合缝。

## 记忆压缩

> **APV 的动态性 = 两次拆分**：天空拆出来（烘焙可见度 × 运行时天空 = PRT 的点乘结构），灯的状态拆出来（多套烘焙 × 线性混合）。守恒律照旧生效——你存的每一套"可变"都要付数据的钱，你拆不出来的动态就管不了。最后一站把全流程和整个 GI 赛道拉通对照：[[学习笔记/cg/games202/专题/apv/08-实现管线与GI赛道对照.md|08 实现管线与 GI 赛道对照]]。
