# 07 公告板：一张图冒充一个三维对象

> 本篇在思维链上的位置：[[学习笔记/cg/games202/专题/ibr/06-精灵与层.md|06 精灵与层：图像当表面的开端]] 的图是平铺在屏幕上的；公告板（billboard）把同一张 2D 图**放进三维场景**，并强迫它每帧"以合适的朝向对着相机"——用一张平面图冒充有体积的对象。代价也在这句话里：你永远绕不到它的侧面。

## 原理：quad + 每帧重算朝向

一个公告板 = 一个四边形，顶点在**每帧、每个实例**由相机位置现场构造：

$$
\text{corner}_{i}
=
c
\pm
\frac{w}{2}\,\mathbf{r}
\pm
\frac{h}{2}\,\mathbf{u}
$$

其中 $c$ 是公告板中心（实例位置），$\mathbf{r},\mathbf{u}$ 是按"朝向约定"选出的右/上方向。**朝向约定就是公告板的全部分类学**——选哪种，取决于对象是什么。

## 四种朝向约定

| 约定 | 构造 | 典型对象 | 穿帮条件 |
|---|---|---|---|
| **屏幕对齐**（screen-aligned） | $\mathbf{r},\mathbf{u}$ = 相机屏幕基 | 光点、魔法符号、辉光 | 相机滚转时跟着滚（多数时候无所谓） |
| **视平面平行**（viewplane-aligned） | quad 平行于近平面 | 粒子（[[学习笔记/cg/games202/专题/ibr/08-粒子系统.md|08 粒子系统：公告板 × 数量 × 时间]] 的主力） | 对"躺平"的对象（如地面烟雾）形状错误 |
| **面向视点**（viewpoint-facing） | 法线 $\mathbf{f}$ 指向相机位置 | 球形云、光环 | 俯仰时竖直感丢失 |
| **世界竖直约束** | $\mathbf{u}$ = 世界 up，$\mathbf{r} = \mathbf{f}\times\mathbf{u}$ | 树、草、人物剪影、头顶血条 | 强俯视/强仰视穿帮 |
| **轴向**（axial） | 绕固定轴（通常 Y）旋转到面向相机 | 侧视游戏的树、立柱 | 相机离开"环带"后穿帮 |

前两种"整机跟随屏幕"，后两种"保一根世界轴"——**保轴的约束越强，冒充的立体感越强，可用的相机区间越窄**。

```glsl
// 世界竖直约束的公告板顶点（伪码）
vec3 f = normalize(camPos - center);
vec3 r = normalize(cross(f, worldUp)); // 保竖直
vec3 u = cross(r, f);
vec3 corner = center + r * halfW * sign.x + u * halfH * sign.y;
```

## 冒充为什么成立：视差去哪了

真实对象侧转时形状改变（自遮挡、轮廓变化），公告板永远给你"正面照"——**它删掉了视角信息**。观众不穿帮的条件就是"删掉的视角信息感知不到"：

| 条件 | 为什么救了它 |
|---|---|
| 对象近似轴对称 / 球对称 | 正面照 ≈ 任意角度照片 |
| 屏幕尺寸小、动得快 | 没时间、也没像素去看侧影 |
| 观察方向范围受限（俯视/侧视游戏） | 设计保证玩家到不了侧面 |
| 配合交叉片（cross quads） | 两三张交叉贴片补出"厚度"，树的经典做法 |

注意最后一条：**交叉片 = 用数量买回视角自由**——一维采样（单 billboard）变二维采样（几个离散朝向），是 [[学习笔记/cg/games202/专题/ibr/05-光场渲染.md|05 光场渲染：把视差买回来]]"多存一维就多一分自由"的迷你版预演。

## 阴影与反射的连带穿帮

公告板的伪装在**主相机**成立，但阴影贴图是从**光源**看的——光源方向的公告板还是"朝主相机"的那张图，投影形状立刻穿帮。通行解法：

- 阴影用 blob / 贴花阴影（不再追求剪影精确）；
- 或广告牌本身参与光照渲染但影子换成代理几何；
- 树的软影常用"轴向公告板的影子仍是轴向公告板"——侧视游戏里勉强成立。

**教训：任何"为某个观察者定制的答案"（缓存/冒充），在其他观察者面前都会打折**——这句结论将贯穿 09 替代物。
