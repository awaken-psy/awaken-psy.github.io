# 06 精灵与层：图像当表面的开端

> 本篇在思维链上的位置：**第二段开卷**。01–05 讲"图像替代整个场景"——理论漂亮但游戏用得少。实时画面里更常见的是：**实时几何的画面中，混入预计算的图像小片**。本篇讲最小的混入单元（层、精灵）和全专题的第一块基石公式（alpha 合成）。

## 画面 = 一叠 2D 图

层（layer）模型把画面简化成一摞 2D 图像，每层配一个**离散的深度序号**。渲染 = 画家算法：从最远的层画到最近的层，一层层覆盖：

```text
背景层（天空、远山）
  → 中景层（建筑）
    → 精灵层（角色、道具）
      → UI 层（文字、血条）
```

**精灵（sprite）** = 可动的小层：一张小图 + 一个位置（红白机时代它是硬件概念——一条独立的 sprite 通道；今天是 GPU 上一个 quad）。

## 基石公式：alpha over

层之间怎么"覆盖"？每张图每个像素带一个**不透明度** $\alpha\in[0,1]$，合成只有一行：

$$
\boxed{
C_{\text{out}} = \alpha\,F + (1-\alpha)\,B
}
$$

前景颜色 $F$ 与背景 $B$ 按 $\alpha$ 线性混合。这行公式值得盯住——**它是 07 公告板、08 粒子、09 替代物、10 公告板云、17 体渲染的全部合成基础**，也是本专题最重要的一行。

## 辨析：premultiplied（预乘）alpha

实践中更常用的是先给前景颜色乘上 $\alpha$ 再存：

| | 直通 alpha（straight） | 预乘 alpha（premultiplied） |
|---|---|---|
| 存储内容 | $F$ 与 $\alpha$ 分开 | $F' = \alpha F$ 与 $\alpha$ |
| 合成公式 | $C = \alpha F + (1-\alpha)B$ | $C = F' + (1-\alpha)B$ |
| 双线性插值边缘 | 半透明边缘与背景互相"漏色" | 插值后再合成依然正确 |
| 加法混合 | 需要切混合模式 | $F'$ 直接加即可（$\alpha$ 参与或不参与都一致） |
| 过滤/模糊 | 颜色与权重脱节 | 天然正确 |

一句话：**预乘 alpha 让"颜色"和"占多少"绑在一起走任何过滤与混合都不出错**——这是为"图像要被缩放、旋转、插值"设计的存储格式，而 IBR 里图像永远在被缩放、旋转、插值。

## 层的深度只有 1.5 维

层模型的"深度"是离散层号，不是连续 $z$。但 2D 游戏早就发现了伪造视差的办法：**视差滚动（parallax scrolling）**——相机移动时，让各层按"越远越慢"的速率平移：

$$
\Delta\text{layer} \propto \frac{1}{z_{\text{层}}}
$$

这恰恰是 [[学习笔记/cg/games202/专题/ibr/03-固定视角渲染.md|03 固定视角渲染：把答案整张存下来]] 里"视差"的卡通版：远处的东西在屏幕上动得慢。**2D 游戏在用 1.5D 的数据结构模拟三维世界最深的那条物理直觉**——这也解释了为什么它至今好用。

## 现代引擎中的它们

| 场景 | 本质 |
|---|---|
| UI / HUD | 层模型，最后一个"层"总是 UI |
| 精灵图集（sprite atlas） | 把许多小图合一张大图，一次 drawcall 全画完 |
| 九宫格（9-slice） | 一张小图 + 拉伸规则 = 任意尺寸的 UI 框 |
| 序列帧动画 | 精灵换帧 = 最古典的"图像当动画" |

引擎侧的实现在 [[学习笔记/cg/tuanjie引擎/总览/第12章-GPU优化与高级专题/03-粒子与VFXGraph渲染.md|03 - 粒子系统与 VFX Graph 渲染]] 同一章的姊妹篇里能看到（SpriteRenderer / BillboardRenderer）；本篇只要确立一件事：**2D 与 3D 的边界从来不是硬的**——接下来就把这层"贴在屏幕上的图"放进三维场景里。
