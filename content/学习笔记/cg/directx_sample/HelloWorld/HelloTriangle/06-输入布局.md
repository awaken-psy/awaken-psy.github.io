# 06 输入布局

上一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/05-像素着色器.md|像素着色器]]  
下一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/07-着色器加载与图形管线状态.md|着色器加载与图形管线状态]]

## 为什么需要输入布局

顶点缓冲区视图可以把连续字节切分成一个个 `Vertex`，但它只知道每个顶点的整体边界，仍不知道顶点内部哪些字节是位置、哪些字节是颜色。

另一方面，顶点着色器声明了 `POSITION` 和 `COLOR` 输入，却不知道它们在缓冲区中的具体格式和偏移。

【核心】输入布局就是二者之间的翻译表：

> 顶点中的原始字节 → 输入布局按格式和偏移取出字段 → 根据语义交给顶点着色器参数。

## 本例的两项输入描述

```cpp
D3D12_INPUT_ELEMENT_DESC inputElementDescs[] =
{
    { "POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT,
      0, 0, D3D12_INPUT_CLASSIFICATION_PER_VERTEX_DATA, 0 },

    { "COLOR", 0, DXGI_FORMAT_R32G32B32A32_FLOAT,
      0, 12, D3D12_INPUT_CLASSIFICATION_PER_VERTEX_DATA, 0 }
};
```

每个元素最需要理解的只有三件事：

| 元素 | HLSL 语义 | 格式 | 顶点内偏移 |
| --- | --- | --- | --- |
| 位置 | `POSITION` | 3 个 32 位浮点数 | 0 字节 |
| 颜色 | `COLOR` | 4 个 32 位浮点数 | 12 字节 |

## 为什么 COLOR 的偏移是 12

`Vertex` 的第一个字段是：

```cpp
XMFLOAT3 position;
```

输入布局把它声明为三个 32 位浮点数，每个浮点数占 4 字节，因此位置共占：

```text
3 × 4 = 12 字节
```

所以 `color` 从当前顶点起点后的第 12 字节开始。

```text
一个 Vertex
├─ 偏移 0  ：POSITION，12 字节
└─ 偏移 12 ：COLOR，16 字节
```

这里的偏移是“相对当前顶点起点”，不是相对整个缓冲区起点。

## 语义如何连接 HLSL

C++ 输入布局中的：

```cpp
"POSITION"
"COLOR"
```

分别匹配顶点着色器中的：

```hlsl
float4 position : POSITION
float4 color : COLOR
```

【核心】连接依据是冒号后的语义，而不是变量名 `position`、`color`，也不是 C++ 成员名。

### 三分量位置为什么能进入 float4

输入布局只读取 `x、y、z` 三个分量，而 HLSL 参数是 `float4`。按照着色器输入的分量补全契约，缺失分量通常补 0，但缺失的 `w` 补为 1，因此顶点着色器收到 `(x, y, z, 1)`。

这也是为什么源码不需要在 C++ `Vertex` 中额外保存一个始终为 1 的 `w`。

## 其余字段【可略】

- `SemanticIndex = 0`：本例只有第一组 `POSITION` 和 `COLOR`，没有 `POSITION1` 或 `COLOR1`。
- `InputSlot = 0`：数据来自输入槽 0；稍后 `IASetVertexBuffers` 也会绑定槽 0。
- `PER_VERTEX_DATA`：每前进一个顶点就读取下一份数据。
- `InstanceDataStepRate = 0`：本例不使用按实例变化的数据；对逐顶点元素该值为 0。

## 输入布局何时生效

声明 `inputElementDescs` 数组本身不会执行 GPU 工作。代码把它放入图形管线状态描述：

```cpp
psoDesc.InputLayout = { inputElementDescs, _countof(inputElementDescs) };
```

因此输入布局会成为该图形管线固定的一部分。具体的 PSO 创建过程留到后面的专门一节。

## 职责边界

- 顶点缓冲区：保存原始字节。
- 顶点缓冲区视图：给出缓冲区起点、单个顶点步长和总范围。
- 输入布局：解释每个顶点内部字段的语义、格式和偏移。
- 顶点着色器：接收解释后的属性并处理一个顶点。

这里关注 `D3D12_INPUT_ELEMENT_DESC` 的调用契约，不深入 Runtime 或驱动如何取数和转换格式。

## 暂时只需记住

1. 输入布局把顶点字节翻译成顶点着色器输入。
2. 最关键的是语义、格式和顶点内字节偏移。
3. `POSITION` 从偏移 0 读取三个浮点数，`COLOR` 从偏移 12 读取四个浮点数。
4. 输入布局最终是 PSO 的一部分。
