## 根签名为什么存在

着色器除了接收顶点属性，还可能访问很多外部数据，例如：

- 常量缓冲区；
- 纹理；
- 可读写资源；
- 采样器。

应用需要在命令列表中绑定这些数据，着色器也需要按相同规则读取它们。

【核心】根签名就是双方事先约定的资源绑定接口：它规定着色器允许接收哪些外部绑定，以及这些绑定位于什么位置。

因果关系是：

> 着色器可能依赖外部资源 → 应用和着色器必须采用同一绑定规则 → 用根签名声明这份契约。

根签名不是纹理或缓冲区本身，也不保存资源内容；它只定义绑定接口。

## 为什么 HelloTriangle 使用空根签名

HelloTriangle 的着色器只使用：

- 输入装配阶段提供的 `POSITION`；
- 输入装配阶段提供的 `COLOR`。

它没有读取常量缓冲区、纹理、UAV 或采样器，所以没有需要通过根签名暴露的外部资源。

【核心】“空根签名”表示根参数数量和静态采样器数量都是 0；它仍然是一个真正创建并持有的 `ID3D12RootSignature` 对象，不等于空指针，也不等于省略根签名。

顶点缓冲区属于输入装配阶段的输入，不需要为它添加根参数。这正是空根签名仍能画出三角形的原因。

## 第一步：准备描述

```cpp
CD3DX12_ROOT_SIGNATURE_DESC rootSignatureDesc;

rootSignatureDesc.Init(
    0,
    nullptr,
    0,
    nullptr,
    D3D12_ROOT_SIGNATURE_FLAG_ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT);
```

五个值分别表示：

| 参数 | 本例取值 | 含义 |
| --- | --- | --- |
| 根参数数量 | `0` | 没有根常量、根描述符或描述符表 |
| 根参数数组 | `nullptr` | 数量为 0，因此没有数组 |
| 静态采样器数量 | `0` | 没有静态采样器 |
| 静态采样器数组 | `nullptr` | 数量为 0，因此没有数组 |
| 标志 | `ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT` | 本例允许输入装配阶段使用顶点输入布局 |

这里仅仅填写了一份 CPU 侧描述，还没有创建 D3D12 根签名对象。

## 第二步：序列化描述

```cpp
ComPtr<ID3DBlob> signature;
ComPtr<ID3DBlob> error;

D3D12SerializeRootSignature(
    &rootSignatureDesc,
    D3D_ROOT_SIGNATURE_VERSION_1,
    &signature,
    &error);
```

为什么不能直接把 `rootSignatureDesc` 传给 Device？因为创建接口接收的是一段版本明确的二进制描述。

`D3D12SerializeRootSignature` 的调用契约是：

1. 接收根签名描述和目标版本；
2. 检查描述能否被序列化；
3. 成功后把二进制结果写入 `signature`；
4. 失败时可以把诊断文本写入 `error`。

`signature` 和 `error` 都是 CPU 侧的 Blob，不是最终根签名对象。

本例选择 `D3D_ROOT_SIGNATURE_VERSION_1`。当前不需要展开不同版本之间的能力差异。

【可略】源码把 `error` 传给 API 接收诊断信息，但没有另外读取或打印它；失败仍会由 `ThrowIfFailed` 中止初始化。

## 第三步：创建根签名对象

```cpp
m_device->CreateRootSignature(
    0,
    signature->GetBufferPointer(),
    signature->GetBufferSize(),
    IID_PPV_ARGS(&m_rootSignature));
```

各参数的作用是：

- `0`：NodeMask；单适配器示例使用 0。
- `GetBufferPointer()`：序列化数据的起始地址。
- `GetBufferSize()`：序列化数据的字节数。
- `m_rootSignature`：接收创建出的根签名对象。

创建成功仍不会执行 GPU 工作，也不会自动绑定任何资源。

## 根签名后面在哪里使用

这一个对象会出现在两个关键位置：

```cpp
psoDesc.pRootSignature = m_rootSignature.Get();
```

PSO 声明这套着色器遵守该根签名的绑定契约。

```cpp
m_commandList->SetGraphicsRootSignature(m_rootSignature.Get());
```

录制绘制命令时，命令列表绑定同一套图形根签名。

因此完整关系是：

```text
根签名描述
    ↓ 序列化
二进制 Blob
    ↓ Device 创建
ID3D12RootSignature
    ├─ 被 PSO 引用为着色器绑定契约
    └─ 被命令列表绑定为当前图形根签名
```

## 空根签名与后续样例

HelloTriangle 没有着色器外部资源，因此根签名为空。后续样例增加纹理和常量缓冲区后，根签名会开始包含真正的资源绑定入口。

现在先建立最小认识：根签名不是负责绘制的对象，它只是把“着色器能够从外部接收什么”明确写成契约。

## API 边界

这里只关注 `Init → Serialize → CreateRootSignature` 的输入、输出和先后依赖，不深入 Blob 格式、Runtime 验证过程或驱动内部表示。

## 暂时只需记住

1. 根签名是应用与着色器之间的资源绑定契约。
2. HelloTriangle 没有外部着色器资源，因此使用没有参数和采样器的空根签名。
3. 空根签名仍是真实对象，不是空指针。
4. 创建过程是“准备描述 → 序列化 → Device 创建对象”。
5. 创建根签名不会触发绘制。
