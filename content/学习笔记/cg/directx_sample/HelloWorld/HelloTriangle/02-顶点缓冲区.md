# 02 顶点缓冲区

上一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/01-顶点与三角形.md|顶点与三角形]]  
下一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/03-顶点缓冲区视图.md|顶点缓冲区视图]]

## 为什么普通数组还不够

上一节的 `triangleVertices` 是 CPU 内存中的普通 C++ 数组。它能让程序准备三个顶点，却还不是 D3D12 绘制时长期读取的资源。

【核心】因此需要一个顶点缓冲区：它是一段保存顶点原始字节、可供 GPU 读取的 D3D12 缓冲区资源。

因果关系是：

> CPU 准备三份顶点 → 创建 GPU 可读取的缓冲区 → 把顶点字节复制进去。

## 第一步：确定缓冲区容量

```cpp
const UINT vertexBufferSize = sizeof(triangleVertices);
```

【核心】缓冲区只是一段字节空间，所以创建前必须告诉 D3D12 需要多少字节。`sizeof(triangleVertices)` 正好包含三个 `Vertex` 的全部数据。

## 第二步：创建缓冲区资源

本例调用 `CreateCommittedResource`。这里只需要记住它的外部调用契约：

- 输入内存属性、资源形状、容量和初始状态。
- 成功后得到一个 `ID3D12Resource`。
- `m_vertexBuffer` 长期持有这个资源，供后续绘制使用。

本例最重要的三个参数是：

| 参数 | 本例取值 | 原因 |
| --- | --- | --- |
| 内存类型 | `D3D12_HEAP_TYPE_UPLOAD` | CPU 可以映射并写入，GPU 可以读取 |
| 资源描述 | `Buffer(vertexBufferSize)` | 需要的是保存顶点字节的一维缓冲区 |
| 初始状态 | `D3D12_RESOURCE_STATE_GENERIC_READ` | 该 UPLOAD 资源供 GPU 读取 |

【可略】正式项目里的静态顶点通常会从 UPLOAD 堆复制到 DEFAULT 堆，让 GPU 更适合长期读取。本例仅有三个顶点，直接使用 UPLOAD 堆是为了避免现在就引入上传命令、额外资源和状态转换。

## 第三步：写入三份顶点

```cpp
m_vertexBuffer->Map(..., &pVertexDataBegin);
memcpy(pVertexDataBegin, triangleVertices, sizeof(triangleVertices));
m_vertexBuffer->Unmap(0, nullptr);
```

这三步的含义是：

1. `Map` 取得 CPU 可以写入的地址。
2. `memcpy` 把三份顶点的原始字节复制到资源中。
3. `Unmap` 结束这次 CPU 映射。

`readRange(0, 0)` 表示 CPU 不打算读取资源中的旧内容，只准备写入数据。

这里不需要研究 `Map`、驱动或内存系统内部如何实现；调用契约只要求映射成功后使用返回的指针，并保证写入不超过创建时给出的容量。

## 现在还缺什么

缓冲区里已经有正确的顶点字节，但它本身没有说明：

- 第一份顶点从哪个 GPU 地址开始；
- 每份 `Vertex` 跨多少字节；
- 整个有效数据区有多大。

下一节的“顶点缓冲区视图”会补上这三项解释规则。

## 暂时只需记住

1. CPU 数组负责准备数据，顶点缓冲区负责让 GPU 能读取这些字节。
2. `CreateCommittedResource` 创建资源，`Map → memcpy → Unmap` 填入数据。
3. 使用 UPLOAD 堆是这个教学样例为了简单而做的选择。
4. 缓冲区目前只有字节，还需要视图说明读取方式。
