# 07 着色器加载与图形管线状态

上一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/06-输入布局.md|输入布局]]  
下一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/08-根签名.md|根签名]]

## 先纠正原英文注释

源码原注释写着：

```cpp
// Create the pipeline state, which includes compiling and loading shaders.
```

它容易让人误以为 `LoadAssets()` 会在程序运行时编译 `shaders.hlsl`。HelloTriangle 的真实流程是：

```text
构建时                                  运行时
shaders.hlsl ──DXC──> 两个 .cso 文件 ──读取字节──> 填写 PSO 描述 ──> 创建 PSO
```

【核心】构建时负责“编译”，运行时这段 C++ 只负责“加载已编译字节码并创建 PSO”。

构建项目时，DXC 分别选择：

- `VSMain` 作为顶点着色器入口，生成 `shaders_VSMain.cso`；
- `PSMain` 作为像素着色器入口，生成 `shaders_PSMain.cso`。

## 为什么要先读取着色器字节码

`CreateGraphicsPipelineState` 不接收 `.hlsl` 文本。它需要的是已经编译好的着色器字节码及其长度：

```cpp
UINT8* pVertexShaderData = nullptr;
UINT8* pPixelShaderData = nullptr;
UINT vertexShaderDataLength = 0;
UINT pixelShaderDataLength = 0;
```

每个着色器都由两个值描述：

- 指针：字节码在 CPU 内存中的起点；
- 长度：从该起点开始有多少有效字节。

随后读取构建产物：

```cpp
ReadDataFromFile(GetAssetFullPath(L"shaders_VSMain.cso").c_str(),
                 &pVertexShaderData, &vertexShaderDataLength);

ReadDataFromFile(GetAssetFullPath(L"shaders_PSMain.cso").c_str(),
                 &pPixelShaderData, &pixelShaderDataLength);
```

【核心】这里没有重新编译 HLSL，也没有执行着色器，只是把两个 `.cso` 文件读入 CPU 内存。

## 为什么需要 PSO

到这里，我们已经分别知道：

- 顶点字节怎样解释；
- 顶点着色器和像素着色器做什么；
- 后台缓冲区使用什么格式。

但一次绘制不能把这些规则随意拼在一起。例如，像素着色器的输出必须与渲染目标格式兼容，着色器资源访问必须符合根签名。

【核心】图形管线状态对象（PSO）把一组必须相互兼容、绘制时相对固定的规则组合成一个对象。创建成功后，命令列表可以反复绑定它；若需要另一套规则，则创建另一个 PSO。

因果关系是：

> 绘制依赖许多彼此相关的固定状态 → 把完整描述一次性交给 Device → 得到不可逐字段修改的 PSO。

## 从零开始填写 PSO 描述

```cpp
D3D12_GRAPHICS_PIPELINE_STATE_DESC psoDesc = {};
```

`{}` 把整份描述清零，保证未设置字段从确定的 0 或空值开始，而不是携带未初始化内存。

## 本例填写的状态

### 1. 输入布局

```cpp
psoDesc.InputLayout = { inputElementDescs, _countof(inputElementDescs) };
```

告诉管线如何把顶点缓冲区中的字节解释成 `POSITION` 和 `COLOR`。详见 [[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/06-输入布局.md|输入布局]]。

### 2. 根签名

```cpp
psoDesc.pRootSignature = m_rootSignature.Get();
```

根签名规定着色器可访问哪些外部绑定资源。HelloTriangle 不读取纹理、常量缓冲区或采样器，因此使用空根签名；其创建过程放到下一篇单独解释。

### 3. 顶点和像素着色器

```cpp
psoDesc.VS = CD3DX12_SHADER_BYTECODE(pVertexShaderData,
                                     vertexShaderDataLength);
psoDesc.PS = CD3DX12_SHADER_BYTECODE(pPixelShaderData,
                                     pixelShaderDataLength);
```

`CD3DX12_SHADER_BYTECODE` 只是把“地址 + 长度”包装成 PSO 所需的描述，不负责编译或执行着色器。

### 4. 光栅化状态

```cpp
psoDesc.RasterizerState = CD3DX12_RASTERIZER_DESC(D3D12_DEFAULT);
```

光栅化状态控制如何把三角形变成候选像素。本例使用 D3D12 默认设置，不在这一阶段展开填充模式、背面剔除等细节。

### 5. 混合状态

```cpp
psoDesc.BlendState = CD3DX12_BLEND_DESC(D3D12_DEFAULT);
```

混合状态决定像素着色器输出如何与渲染目标原值合成。默认状态不启用颜色混合，因此本例直接写入像素着色器输出。

### 6. 深度与模板状态

```cpp
psoDesc.DepthStencilState.DepthEnable = FALSE;
psoDesc.DepthStencilState.StencilEnable = FALSE;
```

HelloTriangle 没有创建深度或模板缓冲区，因此关闭二者。

### 7. 采样掩码【可略】

```cpp
psoDesc.SampleMask = UINT_MAX;
```

采样掩码决定允许写入哪些多重采样样本。`UINT_MAX` 表示全部允许；本例只有一个样本，所以不会筛掉它。

### 8. 图元拓扑类别

```cpp
psoDesc.PrimitiveTopologyType = D3D12_PRIMITIVE_TOPOLOGY_TYPE_TRIANGLE;
```

这表示 PSO 接受三角形类别的图元。它还没有区分三角形列表或三角形条带；具体拓扑稍后由命令列表通过 `IASetPrimitiveTopology` 指定。

### 9. 渲染目标数量和格式

```cpp
psoDesc.NumRenderTargets = 1;
psoDesc.RTVFormats[0] = DXGI_FORMAT_R8G8B8A8_UNORM;
```

像素着色器向一个颜色渲染目标输出。该格式必须与实际绑定的 RTV 和交换链后台缓冲区格式兼容；本例三者都采用 RGBA8 UNORM。

### 10. 采样数量

```cpp
psoDesc.SampleDesc.Count = 1;
```

每个像素只有一个样本，即本例没有开启 MSAA。

## 创建 PSO

```cpp
ThrowIfFailed(m_device->CreateGraphicsPipelineState(
    &psoDesc,
    IID_PPV_ARGS(&m_pipelineState)));
```

这个调用的外部契约是：

1. 输入完整的图形管线描述；
2. D3D12 检查这些状态能否组合；
3. 成功后返回 `ID3D12PipelineState`；
4. 失败时返回错误，由 `ThrowIfFailed` 终止初始化。

【核心】创建 PSO 不会画出任何东西。它只准备好一套绘制规则，后面还要让命令列表绑定该 PSO，并调用 `DrawInstanced`。

## 整段代码的因果链

```text
构建 HLSL
  ↓
得到 VS/PS 字节码文件
  ↓
运行时读取字节码
  ↓
填写输入布局、根签名、着色器和其他固定状态
  ↓
CreateGraphicsPipelineState
  ↓
得到可供命令列表绑定的 m_pipelineState
```

## 暂时只需记住

1. HLSL 在构建时编译，`LoadAssets()` 运行时只读取 `.cso`。
2. PSO 把相互关联的固定绘制状态组合成一个对象。
3. 输入布局、根签名、VS、PS、光栅化、混合和输出格式必须形成兼容组合。
4. 创建 PSO 只是准备规则，不会触发绘制。
