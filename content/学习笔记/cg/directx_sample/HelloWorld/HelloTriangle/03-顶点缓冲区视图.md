# 03 顶点缓冲区视图

上一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/02-顶点缓冲区.md|顶点缓冲区]]  
下一篇：[[学习笔记/cg/directx_sample/HelloWorld/HelloTriangle/04-顶点着色器.md|顶点着色器]]

## 为什么有了缓冲区还需要视图

上一节已经把三个顶点的字节复制进 `m_vertexBuffer`。但是，缓冲区本身只是一段连续字节，不会自动说明“一个顶点到哪里结束、下一个顶点从哪里开始”。

【核心】顶点缓冲区视图就是这段字节的读取说明书。它不保存新的顶点，也不拥有缓冲区资源，只记录三项信息：

1. 从哪个 GPU 地址开始读取；
2. 每个顶点跨多少字节；
3. 这段有效数据总共有多少字节。

因果关系是：

> 缓冲区已有顶点字节 → GPU 仍不知道顶点边界 → 用视图描述起点、步长和总范围。

## 三个字段

```cpp
m_vertexBufferView.BufferLocation = m_vertexBuffer->GetGPUVirtualAddress();
m_vertexBufferView.StrideInBytes = sizeof(Vertex);
m_vertexBufferView.SizeInBytes = vertexBufferSize;
```

| 字段 | 含义 | 本例中的来源 |
| --- | --- | --- |
| `BufferLocation` | 第一个顶点的 GPU 起始地址 | `m_vertexBuffer->GetGPUVirtualAddress()` |
| `StrideInBytes` | 从当前顶点起点走到下一个顶点起点的字节数 | `sizeof(Vertex)` |
| `SizeInBytes` | 整段有效顶点数据的总字节数 | `vertexBufferSize` |

## Stride 为什么不是“位置的大小”

【核心】本例的一个完整 `Vertex` 同时包含 `position` 和 `color`。因此，读取完一个顶点后，必须跨过整个 `Vertex`，才能到达下一个顶点。

```text
顶点 0 起点 ── sizeof(Vertex) ──> 顶点 1 起点 ── sizeof(Vertex) ──> 顶点 2 起点
```

如果只把 `position` 的大小当成步长，那么下一次读取会错误地落到前一个顶点的 `color` 中。

【可略】代码使用 `sizeof(Vertex)`，而不是手写一个固定数字。这样以后修改 `Vertex` 结构时，步长可以自动跟随真实结构大小。

## 视图没有完成什么

`D3D12_VERTEX_BUFFER_VIEW` 是一个普通描述结构体：

- 创建它不会分配新资源；
- 填写字段不会复制数据；
- 填写字段也不会立即执行 GPU 命令。

它只把连续字节划分为一个个顶点记录。至于每条记录中的哪些字节是 `POSITION`、哪些字节是 `COLOR`，还要由后面的“输入布局”说明。

在真正绘制前，程序还会通过 `IASetVertexBuffers` 把这份视图绑定到命令列表。绑定动作留到绘制一节再讲。

## API 调用契约

`GetGPUVirtualAddress()` 的调用契约很简单：资源已经成功创建后，调用它取得该缓冲区的 GPU 地址。这里把返回值作为视图的读取起点即可，不需要研究地址映射或驱动实现。

## 暂时只需记住

1. 顶点缓冲区保存字节，顶点缓冲区视图解释顶点记录的边界。
2. `BufferLocation` 是起点，`StrideInBytes` 是相邻顶点的间隔，`SizeInBytes` 是总范围。
3. 视图不拥有资源，也不会触发绘制。
4. 视图还没有解释 `position` 和 `color`；那是输入布局的职责。
