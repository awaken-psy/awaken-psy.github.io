# 技术选型文档：Unity 游戏多相机注入（Windows / BepInEx）

> 日期：2026-07-07
> 依据：`multi-camera-injection-unity-unreal.md` 阶段 0
> 状态：选型已确定，目标游戏待定

---

## 1. 已确定的技术路线

| 决策项 | 选定方案 | 理由 |
|---|---|---|
| 目标引擎 | Unity | 已确定 |
| 目标平台 | Windows | 工具链成熟、GPU 余量大、注入最简单 |
| 注入框架 | BepInEx | 生态最大、文档最全、社区活跃 |
| 渲染管线 | 待定（Built-in / URP / HDRP） | 取决于目标游戏，需逐游戏确认 |
| 脚本后端 | 待定（Mono / IL2CPP） | 取决于目标游戏，影响注入难度 |

---

## 2. 目标游戏筛选标准

### 2.1 硬性条件（必须满足）

| 条件 | 原因 |
|---|---|
| Unity 引擎制作 | 技术路线已确定为 Unity 侧方案 |
| Windows 平台有可运行版本 | PoC 平台 |
| 无反作弊（EAC / BattlEye / nProtect / 自研校验） | 注入行为会触发反作弊，导致崩溃或封号 |
| 无 IL2CPP metadata 加密 | 加密会增加符号还原成本，PoC 阶段应避开 |
| 无 pak / 资源加密 | 需要读取引擎内部资源结构 |

### 2.2 优先条件（有则更好）

| 条件 | 原因 |
|---|---|
| 有源码或项目文件可获取 | 便于对照调试、理解渲染管线配置 |
| 使用 Built-in 渲染管线 | 最简单，`Camera` + `targetTexture` 直接可用，无需处理 SRP 回调 |
| 使用 Mono 脚本后端 | 注入最简单，可直接加载托管 DLL、反射调用 |
| 有一定知名度 | 社区可能已有 mod 经验可参考，踩坑少 |
| 3D 场景（非纯 2D） | 多视角注入对 3D 场景才有意义，验证剔除也需要 3D 几何 |

### 2.3 排除条件

| 条件 | 原因 |
|---|---|
| 网游 / 有在线服务 | 通常有反作弊 + 联网校验 |
| IL2CPP + metadata 加密 | 符号还原成本高，PoC 阶段不值得 |
| URP / HDRP 且管线高度定制 | 需要额外处理 SRP 回调，增加 PoC 复杂度 |
| 纯 2D 游戏 | 多视角注入无意义 |

## 3. BepInEx 方案详解

### 3.1 为什么选 BepInEx

- **社区最大**：GitHub star 数、文档量、教程量均领先 MelonLoader
- **同时支持 Mono 和 IL2CPP**：BepInEx 5 支持 Mono，BepInEx 6（预览）支持 IL2CPP
- **插件模型直观**：写一个继承 `BaseUnityPlugin`（Mono）或 `BasePlugin`（IL2CPP）的类，挂 `MonoBehaviour` 每帧跑，和写 Unity 组件几乎一样
- **Harmony 运行时补丁**：可 hook 任意 C# 方法，在 PoC 阶段用于 hook 渲染回调或游戏逻辑
- **Il2CppInterop**：IL2CPP 下自动在运行时生成托管代理程序集，让你像调用普通 C# API 一样调用 IL2CPP 编译的引擎函数

### 3.2 BepInEx 版本选择

| BepInEx 版本 | 支持后端 | 状态 | 选择 |
|---|---|---|---|
| BepInEx 5 | Mono | 稳定正式版 | **目标游戏为 Mono 时选这个** |
| BepInEx 6 (bleeding edge) | Mono + IL2CPP | 预览版，可能有 bug | **目标游戏为 IL2CPP 时选这个** |

优先找 Mono 后端的游戏，用 BepInEx 5 稳定版做 PoC。

### 3.3 BepInEx 的工作机制

```
游戏启动
  │
  ├── 正常加载 UnityPlayer.dll、游戏脚本
  │
  └── BepInEx 通过 DLL 劫持 / 进程注入进入游戏进程
       │
       ├── 早期初始化（Preloader）
       │    └── 检测 Mono / IL2CPP，初始化对应后端
       │
       ├── IL2CPP 路径（如适用）
       │    └── Il2CppInterop 读取 global-metadata.dat
       │       → 生成托管代理程序集（UnityEngine.Camera.dll 等）
       │       → 你的插件代码通过代理调用引擎 API
       │
       ├── Mono 路径
       │    └── 直接加载你的 DLL，反射调用引擎 API
       │
       └── 加载插件
            └── 你的插件 DLL 放在 BepInEx/plugins/ 目录
               → 插件的 Load() 被调用
               → 你在里面创建相机、绑逻辑
```

### 3.4 插件项目结构

```
MultiCamPlugin/
├── MultiCamPlugin.csproj        ← .NET 项目文件
├── Plugin.cs                     ← 插件入口 [BepInPlugin]
├── MultiCamRunner.cs             ← 相机管理组件（MonoBehaviour）
├── CameraRig.cs                  ← 相机机位定义与运动逻辑
├── DataExporter.cs               ← 渲染结果读回与落盘
└── libs/
    ├── BepInEx.dll                ← 引用
    ├── 0Harmony.dll               ← 引用
    └── UnityEngine*.dll           ← 引用（从目标游戏的 Managed 目录复制）
```

### 3.5 插件部署方式

```
游戏根目录/
├── BepInEx/
│   ├── core/                      ← BepInEx 核心文件
│   ├── plugins/
│   │   └── MultiCamPlugin.dll     ← 你的插件，放这里
│   └── config/                    ← 配置文件
├── winhttp.dll                    ← BepInEx 的 DLL 劫持入口（或 doorstop_config.ini）
├── UnityPlayer.dll               ← 游戏引擎
└── 游戏.exe
```

BepInEx 通过在游戏目录放一个 `winhttp.dll`（DLL 劫持）或使用 Unity Doorstop 实现进程启动时自动加载。游戏启动后 BepInEx 自动运行，自动加载 `plugins/` 下的所有 DLL。

## 4. 渲染管线适配策略

### 4.1 三种管线的处理方式

| 管线 | 相机创建 | 渲染调度 | 特殊处理 |
|---|---|---|---|
| **Built-in RP** | `new GameObject` + `AddComponent<Camera>()` | 引擎自动每帧渲染 | 无，最简单 |
| **URP** | 同上 | `RenderPipelineManager` 统一调度 | 用 `beginCameraRendering` / `endCameraRendering` 回调；给相机加 `UniversalAdditionalCameraData` 配置 |
| **HDRP** | 同上 | 同 URP | 用 `HDAdditionalCameraData` 配置；自定义 pass 需更深入 |

### 4.2 PoC 策略

优先找 Built-in RP 的游戏做 PoC，跑通后再适配 URP/HDRP。确认方法：

- 查看游戏 `*_Data/` 目录下有无 `UniversalRenderPipelineAsset` 或 HDRP 资源文件
- 运行游戏后用 BepInEx 在代码里检测 `GraphicsSettings.currentRenderPipeline` 是否为 null

## 5. 数据导出方案

### 5.1 读回方式

| 方式 | API | 特点 | 适用 |
|---|---|---|---|
| 同步读回 | `RenderTexture.active` + `Texture2D.ReadPixels` | 简单，但会 stall GPU | 离线采集 |
| 异步读回 | `AsyncGPUReadback.Request` | 不阻塞主线程，回调拿 `NativeArray` | 实时采集 |

### 5.2 导出通道

| 通道 | 方法 |
|---|---|
| Color | 直接从 RenderTexture 读回 |
| Depth | `cam.depthTextureMode \|= DepthTextureMode.Depth`，从 `_CameraDepthTexture` 取，按近远平面反投影转线性 |
| 相机内参 | `cam.projectionMatrix` → 提取焦距、主点、畸变（如有） |
| 相机外参 | `cam.worldToCameraMatrix` → 提取旋转、平移 |

### 5.3 落盘格式

PoC 阶段先落 PNG + JSON（内外参），后续阶段再对齐 NeRF/3DGS 标准格式。

## 6. PoC 验收标准

阶段 1 的成功标准：

1. **附加相机能渲染出画面** — 落一张 PNG，内容是合理的游戏画面
2. **偏离主相机视角时无剔除空洞** — 将附加相机旋转 90° 或 180°，画面中不应出现空白/缺失几何
3. **相机内外参可正确读出** — `projectionMatrix` 和 `worldToCameraMatrix` 输出非零、值合理
4. **不影响游戏正常运行** — 主相机画面不受干扰，游戏不崩溃

## 7. 风险与备选

| 风险 | 影响 | 备选方案 |
|---|---|---|
| BepInEx 对某游戏不兼容 | 无法注入 | 换 MelonLoader |
| 目标游戏是 IL2CPP | 需用 BepInEx 6 预览版，可能遇 bug | 换 MelonLoader（IL2CPP 支持更成熟）或找 Mono 游戏 |
| 目标游戏是 URP/HDRP | 需额外处理 SRP 回调 | 先找 Built-in RP 游戏做 PoC |
| 目标游戏有未预期的完整性校验 | 注入后崩溃 | 换游戏，PoC 阶段不与反作弊对抗 |
