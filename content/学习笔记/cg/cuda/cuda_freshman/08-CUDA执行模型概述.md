# 08 CUDA 执行模型概述

> 从硬件层面理解 GPU 怎么跑你的代码。核心概念：SM、Warp、SIMT。
> 关联：[[学习笔记/cg/cuda/cuda_freshman/01-hello-world与线程层级.md|01 Hello World 与 CUDA 线程层级]] · [[学习笔记/cg/cuda/cuda_freshman/07-设备信息查询.md|07 设备信息查询]]

---

## 1. 神奇的数字 32 — Warp（线程束）

GPU 调度线程的最小单位不是单个线程，而是 **32 个线程一组**，叫做 **Warp（线程束）**。

这 32 个线程**必须同时执行同一条指令**。这就是 **SIMT（Single Instruction, Multiple Threads）** 模型。

### 分水果类比

```
老师（Warp 调度器）给 32 个小朋友（线程）分水果（指令）：

第 1 次分苹果（指令 A）：
  → 20 个小朋友吃（执行 A）
  → 12 个不吃（不执行 A，但也不能干别的，只能干等）
  → 等所有人走完这条指令，才能分下一种水果

第 2 次分橘子（指令 B）：
  → 刚才等的 12 个小朋友吃
  → 刚才吃的 20 个干等

第 3 次分桃子（指令 C）：
  → 32 个都吃（完美情况，效率最高）
```

一句话：**一条指令同时驱动 32 个线程，不执行的线程不能偷跑，只能等。**

## 2. 逻辑层 vs 硬件层

```
逻辑层（你写的代码）              硬件层（GPU 实际执行）
─────────────────────             ─────────────────────
Grid                             GPU 芯片
 ├── Block  ─────────────────→   SM（多处理器）
 │    ├── Thread  ──────────→     Warp（32 线程束）
 │    ├── Thread                    │
 │    └── Thread                    └── CUDA Core（执行单元）
 ├── Block
 └── Block
```

| 逻辑层（编程模型） | 硬件层（执行模型） | 对应关系 |
|---|---|---|
| Grid（网格） | 整个 GPU | 一个 kernel 启动的全部线程 |
| Block（线程块） | SM（多处理器） | Block 被分配到 SM 上执行 |
| Warp（线程束） | SM 的执行单位 | 32 个线程为一组，SM 同时执行 |
| Thread（线程） | CUDA Core | 最小的执行单元 |

关键点：
- 一个 **Block** 被分配到一个 **SM** 上，一个 SM 可以同时容纳多个 Block
- Block 内的线程被分成多个 **Warp**（每 32 个线程一个）
- SM 上的 Warp 调度器**轮流**执行 Warp——有些在执行，有些在等待，切换零开销

## 3. SM（Streaming Multiprocessor）

SM 是 GPU 的核心计算单元，可以理解为"一个小 CPU"。

### SM 内部结构

```
一个 SM 包含：
  ├── CUDA 核心（执行单元）     ← 干活的
  ├── Warp 调度器              ← 决定哪个 Warp 什么时候执行
  ├── 加载/存储单元（LSU）     ← 处理内存读写
  ├── 特殊功能单元（SFU）      ← 处理 sin/cos/sqrt 等特殊运算
  ├── 寄存器文件               ← 极快，线程私有
  ├── 共享内存 / L1 缓存       ← Block 内共享
  └── L2 缓存（所有 SM 共享）  ← 全局
```

### SM 的工作流程

1. `GigaThread` 引擎把 Block 分配到各个 SM
2. SM 把 Block 内的线程切成 Warp（每 32 个）
3. Warp 调度器从多个 Warp 中选一个执行
4. 选中的 Warp 的 32 个线程同时执行同一条指令

### SM 上的 Warp 调度

同一个 SM 上可以有不止一个常驻的 Warp：
- 有些在执行
- 有些在等待（等内存、等同步等）
- 它们之间状态转换**零开销**（硬件级切换，不像 CPU 线程切换要保存/恢复上下文）

> [!tip] 这就是 GPU 比 CPU 快的根本原因
> CPU：少量大核心，每个核心精于复杂逻辑，线程切换开销大
> GPU：大量小核心，靠 Warp 切换隐藏延迟，一个 Warp 等内存时另一个 Warp 立刻顶上

## 4. Block 的分批执行

> "虽然编程模型层面看所有线程都是并行执行的，但在微观上看，所有线程块也是分批次的在物理层面的机器上执行"

```
你写的代码：       100 个 Block 同时执行（逻辑上看）
                    ↓
硬件实际：         SM 只有 38 个（RTX 3060 Ti）
                    ↓
                   第一批 38 个 Block 上 SM 执行
                   第二批 38 个 Block 等 SM 空出来
                   第三批 24 个 Block ...
```

GPU 的 SM 数量有限，Block 数量超过 SM 容量时就要**分批排队**。

> [!warning] 这就是 CUDA 不允许 Block 间同步的原因
> 有些 Block 还在排队，根本没开始执行，没法跟别人同步。只有同一 Block 内的线程可以通过 `__syncthreads()` 同步。

## 5. Warp Divergence（分支分歧）

SIMT 模型最大的性能陷阱：**if-else 导致 Warp 分歧**。

```cpp
if (threadIdx.x < 16) {
  // A 分支：前 16 个线程执行
} else {
  // B 分支：后 16 个线程执行
}
```

执行过程：

```
时间 ──→

执行 A：  ████░░░░    前 16 个线程干活，后 16 个干等
执行 B：  ░░░░████    后 16 个线程干活，前 16 个干等

总耗时 = A + B（串行执行两个分支）
```

如果没有 if-else：

```
执行 C：  ████████    32 个线程同时干活
总耗时 = C（一次搞定）
```

> [!danger] Warp Divergence 的代价
> 同一个 Warp 内的线程走了不同的分支，分支只能**串行执行**，吞吐量减半。
> 如果 32 个线程走了 32 条不同分支，性能退化为串行。

### 如何避免

- 尽量让同一 Warp 内的线程走同一分支
- 数据预处理时按条件排序，减少分歧
- 必要时用数学运算替代分支（如用 `条件 ? a : b` 代替 `if-else`）

## 6. 架构对比（了解即可）

32 这个数字从 Fermi（2010）到 Ampere 至今未变，是 GPU 硬件的基因。

| | Fermi（2010） | Ampere（你的 3060 Ti） |
|---|---|---|
| SM 数量 | 16 | 38 |
| 每 SM CUDA 核心 | 32 | 128 |
| 每 SM 最大线程 | 1536 | 1536 |
| Warp 大小 | 32 | 32（从未变过） |
| 每 SM 最大 Warp 数 | 48 | 48 |

| Warp 是什么 | 32 个线程为一组，GPU 调度的最小单位 |
| SIMT 是什么 | 一条指令同时驱动 32 个线程 |
| Warp 内线程能否执行不同指令 | ❌ 不能，不执行的线程只能干等 |

| 一个 SM 能容纳多个 Block 吗 | ✅ 可以 |
| Block 间能否同步 | ❌ 不能，Block 可能还在排队 |
| Block 内能否同步 | ✅ 用 `__syncthreads()` |
| Warp Divergence 是什么 | 同一 Warp 内线程走不同分支，分支串行执行 |
| 如何避免 Divergence | 让同一 Warp 内线程走同一分支 |
| Warp 切换有无开销 | ❌ 零开销（硬件级切换） |
| SM 里有哪些资源 | CUDA 核心、Warp 调度器、LSU、SFU、寄存器、共享内存/L1、L2 |
