# 03 显存分配与浮点误差

> 从 `sum_arrays.cu` 出发，理解 CPU-GPU 内存模型、`cudaMalloc`/`cudaMemcpy` 的用法，以及为什么 CPU 与 GPU 的浮点计算结果可能不完全一致。

## 0. CPU-GPU 内存模型

CPU 和 GPU 是**物理隔离**的两个处理器，各自有独立的内存：

```
┌────────────────────┐          ┌────────────────────┐
│      CPU (Host)    │          │     GPU (Device)   │
│                    │          │                    │
│  a_h  (malloc)     │  ←拷贝→  │  a_d  (cudaMalloc) │
│  b_h  (malloc)     │          │  b_d  (cudaMalloc) │
│  res_h (malloc)    │          │  res_d (cudaMalloc)│
│                    │          │                    │
│  主机内存 (RAM)     │          │  设备显存 (VRAM)    │
└────────────────────┘          └────────────────────┘
```

**CPU 不能直接读写 GPU 显存，GPU 也不能直接访问主机内存。** 数据必须通过 `cudaMemcpy` 在两端之间搬运。

| | CPU 端 | GPU 端 |
|---|---|---|
| 分配 | `malloc` → `a_h` | `cudaMalloc` → `a_d` |
| 可访问者 | CPU | GPU |
| 物理位置 | 主机内存（RAM） | 设备显存（VRAM） |
| 释放 | `free(a_h)` | `cudaFree(a_d)` |

## 1. `cudaMalloc` —— 在 GPU 显存上分配

```cpp
float *a_d, *b_d, *res_d;
CHECK(cudaMalloc((float**)&a_d, nByte));
CHECK(cudaMalloc((float**)&b_d, nByte));
CHECK(cudaMalloc((float**)&res_d, nByte));
```

`cudaMalloc` 类似 CPU 的 `malloc`，但在 **GPU 显存**上分配。分配后 `a_d`、`b_d`、`res_d` 是指向显存的指针，**CPU 不能直接读写这些地址里的数据**。

### 为什么 `&a_d` 要强转 `(float**)`

`cudaMalloc` 的函数签名：

```cpp
cudaError_t cudaMalloc(void** devPtr, size_t size);
```

第一个参数是 `void**`（二级指针），因为它的设计是：通过修改你传入的指针变量来返回分配到的地址。`a_d` 是 `float*`，`&a_d` 是 `float**`，强转 `(float**)` 是为了匹配函数签名。

## 2. `cudaMemcpy` —— CPU 与 GPU 之间的数据搬运

```cpp
// 主机 → 设备
CHECK(cudaMemcpy(a_d, a_h, nByte, cudaMemcpyHostToDevice));
CHECK(cudaMemcpy(b_d, b_h, nByte, cudaMemcpyHostToDevice));

// 设备 → 主机
CHECK(cudaMemcpy(res_from_gpu_h, res_d, nByte, cudaMemcpyDeviceToHost));
```

四个参数：`(目标, 源, 字节数, 方向)`

| 方向枚举 | 含义 |
|---|---|
| `cudaMemcpyHostToDevice` | CPU → GPU |
| `cudaMemcpyDeviceToHost` | GPU → CPU |
| `cudaMemcpyDeviceToDevice` | GPU → GPU |

### 典型的 CUDA 数据流

```
CPU 生成/初始化数据
    │
    ├── cudaMemcpy (Host → Device)     ← 把输入数据搬到 GPU
    │
    ├── kernel<<<grid, block>>>()       ← GPU 并行计算
    │
    └── cudaMemcpy (Device → Host)     ← 把结果搬回 CPU
```

> [!warning] `cudaMemcpy` 是同步的
> 调用时会阻塞 CPU，直到拷贝完成。后面的代码才会继续执行。这对结果的正确性很重要——拷回结果时 kernel 一定已经执行完了。

## 3. 浮点计算误差 —— 为什么 `checkResult` 要用 `epsilon`

### `checkResult` 的实现

```cpp
void checkResult(float *hostRef, float *gpuRef, const int N)
{
  double epsilon = 1.0E-8;
  for (int i = 0; i < N; i++)
  {
    if (abs(hostRef[i] - gpuRef[i]) > epsilon)
    {
      printf("Results don't match!\n");
      return;
    }
  }
  printf("Check result success!\n");
}
```

### 误差不是拷贝产生的

`cudaMemcpy` 是**位级精确**的拷贝，一个 bit 都不会变。误差来自 **CPU 和 GPU 的浮点运算过程**。

### 核心原因：浮点数不满足结合律

数学上 `(a + b) + c = a + (b + c)`，但浮点数不行：

```
(1e20 + 1.0) - 1e20 = 0      // 1.0 被吞掉了
1e20 + (1.0 - 1e20) = 1.0    // 结果完全不同
```

只要**运算顺序不同**，结果就可能不同。而 CPU 和 GPU 经常以不同顺序计算。

### 常见误差来源

| 来源 | 说明 |
|---|---|
| **运算顺序不同** | 求和、归约等操作，CPU 串行从头加到尾，GPU 并行分块再合并，顺序不同 |
| **数学库不同** | CPU 用 `libm`，GPU 用 CUDA math library，`sin`/`exp` 等实现不同 |
| **编译器优化不同** | 可能用 FMA（融合乘加，一次运算无中间舍入）或不同指令集 |
| **精度扩展** | CPU x87 寄存器有 80 位扩展精度，GPU 严格按 32/64 位 |

### 本示例其实不会有误差

`sum_arrays.cu` 做的是 `res[i] = a[i] + b[i]`，每个元素独立计算，CPU 和 GPU 执行的运算完全一样，结果精确相等。

但 `checkResult` 用 `epsilon` 是**通用做法**——换到归约求和（reduce）等涉及运算顺序的场景，就真的会出现微小差异了。

> [!tip] 工程实践
> 永远不要用等号直接比较浮点数，而应判断差值是否在 epsilon 范围内：
> - `float` 精度：`1e-6` ~ `1e-8`
> - `double` 精度：`1e-12` ~ `1e-15`
