# 12 展开循环与并行归约

> 归约（Reduction）是 CUDA 最经典的并行算法案例。通过三种 kernel 写法的对比，理解 Warp Divergence 对性能的影响。
> 关联：[[学习笔记/cg/cuda/cuda_freshman/09-线程束执行本质与Warp-Divergence.md|09 线程束执行的本质与 Warp Divergence]] · [[学习笔记/cg/cuda/cuda_freshman/10-资源分配与延迟隐藏与占用率.md|10 资源分配、延迟隐藏与占用率]]

## 1. 什么是归约

"归约" = "归"（递归，每轮操作相同）+ "约"（减少，数据量每轮减半）。

```
输入：[3, 1, 7, 0, 4, 1, 6, 3]   ← 8 个数
第1轮：[4,   7,   5,   9]       ← 4 个结果（配对相加）
第2轮：[11,      14]             ← 2 个结果
第3轮：[25]                      ← 最终结果
```

### 两种配对方式

```
方式一：相邻配对（Neighbored）          方式二：交错配对（Interleaved）
第1轮：(0,1) (2,3) (4,5) (6,7)          第1轮：(0,4) (1,5) (2,6) (3,7)
第2轮：(0,2) (4,6)                     第2轮：(0,2) (1,3)
第3轮：(0,4)                           第3轮：(0,1)
```

## 2. reduceNeighbored — 最原始的版本

```cpp
__global__ void reduceNeighbored(int *g_idata, int *g_odata, unsigned int n)
{
    unsigned int tid = threadIdx.x;
    if (tid >= n) return;

    // 把全局指针偏移到当前 Block 的数据段
    // blockIdx.x=0 → idata = g_idata + 0
    // blockIdx.x=1 → idata = g_idata + 1024
    int *idata = g_idata + blockIdx.x * blockDim.x;

    for (int stride = 1; stride < blockDim.x; stride *= 2)
    {
        // 只有 tid 是 (2*stride) 的倍数的线程才干活
        if ((tid % (2 * stride)) == 0)
        {
            idata[tid] += idata[tid + stride];
        }
        __syncthreads();  // 等这一轮所有人都干完
    }

    // 每个 Block 的 thread 0 把结果写到输出数组
    if (tid == 0) g_odata[blockIdx.x] = idata[0];
}
```

### 逐轮执行（8 个线程，数据 [3,1,7,0,4,1,6,3]）

```
stride=1:  条件 tid%2==0 → tid=0,2,4,6 干活
  tid=0: idata[0] += idata[1]  → 3+1=4
  tid=2: idata[2] += idata[3]  → 7+0=7
  tid=4: idata[4] += idata[5]  → 4+1=5
  tid=6: idata[6] += idata[7]  → 6+3=9
  → 数据: [4,1,7,0,5,1,9,3]    ← 4 个线程干活，4 个干等

stride=2:  条件 tid%4==0 → tid=0,4 干活
  tid=0: idata[0] += idata[2]  → 4+7=11
  tid=4: idata[4] += idata[6]  → 5+9=14
  → 数据: [11,1,7,0,14,1,9,3]  ← 2 个干活，6 个干等

stride=4:  条件 tid%8==0 → tid=0 干活
  tid=0: idata[0] += idata[4]  → 11+14=25
  → 数据: [25,...]              ← 1 个干活，7 个干等
```

### 问题

每轮一半线程在干等：

```
stride=1: 4 个闲着
stride=2: 6 个闲着
stride=4: 7 个闲着
```

## 3. reduceNeighboredLess — 改善分化

```cpp
__global__ void reduceNeighboredLess(int *g_idata, int *g_odata, unsigned int n)
{
    unsigned int tid = threadIdx.x;
    int *idata = g_idata + blockIdx.x * blockDim.x;

    for (int stride = 1; stride < blockDim.x; stride *= 2)
    {
        // 关键变化：用乘法重新映射 index，而不是用取模判断
        int index = 2 * stride * tid;
        if (index < blockDim.x)
        {
            idata[index] += idata[index + stride];
        }
        __syncthreads();
    }
    if (tid == 0) g_odata[blockIdx.x] = idata[0];
}
```

### 逐轮执行（8 个线程）

```
stride=1:  index = 2*tid → tid=0,1,2,3 干活
  tid=0: index=0 → idata[0] += idata[1]   → 3+1=4
  tid=1: index=2 → idata[2] += idata[3]   → 7+0=7
  tid=2: index=4 → idata[4] += idata[5]   → 4+1=5
  tid=3: index=6 → idata[6] += idata[7]   → 6+3=9
  → tid=4,5,6,7 的 index ≥ 8 → 不执行

stride=2:  index = 4*tid → tid=0,1 干活
  tid=0: index=0 → idata[0] += idata[2]   → 4+7=11
  tid=1: index=4 → idata[4] += idata[6]   → 5+9=14

stride=4:  index = 8*tid → tid=0 干活
  tid=0: index=0 → idata[0] += idata[4]   → 11+14=25
```

### 和原始版的区别

8 个线程时看不出区别（都在同一个 Warp 里）。**放大到 64 个线程（2 个 Warp）才看得出**：

```
原始版 stride=1（条件 tid%2==0）：

Warp 0 (tid 0~31):  ✓ ✗ ✓ ✗ ✓ ✗ ... ✓ ✗   ← 16个干活16个干等 → Divergence！
Warp 1 (tid 32~63): ✓ ✗ ✓ ✗ ✓ ✗ ... ✓ ✗   ← 同样 → Divergence！

→ 2 个 Warp 都有 Divergence，都浪费时间执行 if 块

改善版 stride=1（条件 2*tid < 64）：

Warp 0 (tid 0~31):  ✓ ✓ ✓ ✓ ✓ ✓ ... ✓ ✓   ← 32个全干活 → 无 Divergence！
Warp 1 (tid 32~63): ✗ ✗ ✗ ✗ ✗ ✗ ... ✗ ✗   ← 32个全不干 → 整个 Warp 跳过，零开销！

→ Warp 0 满载执行，Warp 1 直接跳过
```

| | 原始版 | 改善版 |
|---|---|---|
| 活跃线程分布 | 交错分散到每个 Warp | 集中打包到部分 Warp |
| 每个 Warp 内 | 混合（有干有等） | 要么全干，要么全不干 |
| Divergence | 每个 Warp 都有 | 没有 |
| 不干活的 Warp | 没有，每个 Warp 都得跑 if | 有，直接跳过，零开销 |

> [!tip] 核心区别
> 原始版把活儿均匀摊到每个 Warp，导致每个 Warp 都有 Divergence；改善版把活儿集中打包给部分 Warp，让其他 Warp 整个跳过，不浪费时间。两个版本计算结果完全一样，只是线程编号方式不同。

## 4. reduceInterleaved — 交错配对

```cpp
__global__ void reduceInterleaved(int *g_idata, int *g_odata, unsigned int n)
{
    unsigned int tid = threadIdx.x;
    int *idata = g_idata + blockIdx.x * blockDim.x;

    // 从 blockDim.x/2 开始，逐步减半
    for (int stride = blockDim.x / 2; stride > 0; stride >>= 1)
    {
        if (tid < stride)
        {
            idata[tid] += idata[tid + stride];
        }
        __syncthreads();
    }
    if (tid == 0) g_odata[blockIdx.x] = idata[0];
}
```

### 逐轮执行（8 个线程，数据 [3,1,7,0,4,1,6,3]）

```
stride=4: tid<4 → tid=0,1,2,3 干活
  tid=0: idata[0] += idata[4]  → 3+4=7
  tid=1: idata[1] += idata[5]  → 1+1=2
  tid=2: idata[2] += idata[6]  → 7+6=13
  tid=3: idata[3] += idata[7]  → 0+3=3
  → [7,2,13,3,4,1,6,3]

stride=2: tid<2 → tid=0,1 干活
  tid=0: idata[0] += idata[2]  → 7+13=20
  tid=1: idata[1] += idata[3]  → 2+3=5
  → [20,5,13,3,...]

stride=1: tid<1 → tid=0 干活
  tid=0: idata[0] += idata[1]  → 20+5=25
  → [25,...]
```

跨度从大往小走（4→2→1），且干活的线程总是从 tid=0 开始连续排列 → **天然无 Divergence**。

## 5. 为什么需要 `__syncthreads()`

```cpp
idata[tid] += idata[tid + stride];  // 写 idata[tid]
// 下一轮别人要读 idata[tid]
__syncthreads();  // 必须等所有人写完，下一轮才能读
```

如果没有 `__syncthreads()`：

```
tid=0 已经进入 stride=2 那轮，要读 idata[2]
tid=2 还在 stride=1 那轮，还没写完 idata[2]
→ tid=0 读到旧数据 → 结果错误
```

## 6. 整体流程

```
大数组 (1600万元素)
  │
  ├── Block 0: 处理 [0 ~ 1023]     → 归约 → 1 个结果
  ├── Block 1: 处理 [1024 ~ 2047]  → 归约 → 1 个结果
  ├── Block 2: 处理 [2048 ~ 3071]  → 归约 → 1 个结果
  ├── ...
  └── Block N: 处理 [...]          → 归约 → 1 个结果
                                        ↓
              CPU 把所有 Block 的结果加起来 → 总和
```

每个 Block 独立归约出自己的局部和，最后 CPU 把所有局部和相加。因为 Block 之间不能同步，所以最后一步只能在 CPU 上做。

## 📌 速查表

| 问 | 答案要点 |
|---|---|
| 归约是什么 | 每轮配对相加，数据量减半，直到剩一个结果 |
| 两种配对方式 | 相邻配对（Neighbored）和交错配对（Interleaved） |
| reduceNeighbored 的问题 | `tid % (2*stride)` 导致活跃线程交替分布，每个 Warp 都有 Divergence |
| reduceNeighboredLess 的改进 | `index = 2*stride*tid` 让活跃线程连续排列，整 Warp 跳过或全干 |
| reduceInterleaved 的特点 | 跨度从大到小（4→2→1），干活的线程从 tid=0 连续排列 |
| 为什么需要 `__syncthreads()` | 确保这一轮写完，下一轮才能读 |
| Block 间能否同步 | ❌ 不能，最后求和在 CPU 上做 |
| 原始版 vs 改善版的区别 | 活跃线程从"交错分散"变成"集中打包"，消除 Divergence |
| 三个版本结果是否一样 | ✅ 一样，只是性能不同 |
