# 14 动态并行

> 在 kernel 内部启动 kernel（GPU 递归调用 GPU），运行时动态决定启动配置。
> 关联：[[学习笔记/cg/cuda/cuda_freshman/08-CUDA执行模型概述.md|08 CUDA 执行模型概述]] · [[学习笔记/cg/cuda/cuda_freshman/01-hello-world与线程层级.md|01 Hello World 与 CUDA 线程层级]]

---

## 1. 什么是动态并行

之前所有的 kernel 都是 **CPU 调用**的。动态并行就是 **GPU 内部调用 kernel**——kernel 里再启动 kernel。

```
CPU 调用（之前）：
  CPU ──→ kernel<<<grid, block>>>()
              ↓
           GPU 执行

动态并行（现在）：
  CPU ──→ parentKernel<<<grid, block>>>()
              ↓
           GPU 执行 parentKernel
              ↓
           parentKernel 内部调用 childKernel<<<grid, block>>>()
              ↓
           GPU 执行 childKernel
              ↓
           childKernel 结束 → parentKernel 继续
```

## 2. 父子网格关系

```
父网格 (Parent Grid)
  ├── 父线程块 0
  │     ├── 父线程 0 ──→ 启动子网格 A
  │     ├── 父线程 1
  │     └── 父线程 2
  └── 父线程块 1
        └── 父线程 0 ──→ 启动子网格 B
```

### 三条规则

1. 子网格必须在父线程、父线程块、父网格结束之前结束
2. 所有子网格完成后，父网格才会结束
3. 同一父线程块中所有线程创建的子网格都完成后，父线程块才算完成

> [!warning] 隐式同步
> 父线程块的所有线程即使执行完毕，也要等它启动的所有子网格完成后才算完成。虽然没写同步指令，但 GPU 保证子网格先完成。

## 3. 嵌套 Hello World 代码

```cpp
__global__ void nesthelloworld(int iSize, int iDepth)
{
    unsigned int tid = threadIdx.x;
    printf("depth : %d blockIdx: %d,threadIdx: %d\n", iDepth, blockIdx.x, threadIdx.x);

    // 终止条件：线程数减到 1 时停止递归
    if (iSize == 1)
        return;

    // 下一层的线程数减半
    int nthread = (iSize >> 1);

    // 只有 tid==0 的线程启动子网格（每个 Block 只启动一个子网格）
    if (tid == 0 && nthread > 0)
    {
        nesthelloworld<<<1, nthread>>>(nthread, ++iDepth);
        printf("-----------> nested execution depth: %d\n", iDepth);
    }
}
```

### 参数说明

| 参数 | 含义 |
|---|---|
| `iSize` | 当前这一层要处理的线程数 |
| `iDepth` | 递归深度（从 0 开始） |
| `nthread = iSize >> 1` | 下一层线程数减半（右移一位 = 除以 2） |

### 启动方式

```cpp
int size = 64;
int block_x = 2;
dim3 block(block_x, 1);
dim3 grid((size - 1) / block.x + 1, 1);  // 32 个 Block
nesthelloworld<<<32, 2>>>(64, 0);
```

## 4. 递归树全流程

以 **Block 0** 为例（其他 Block 同理）：

```
depth=0: Block 0, 64 个线程
  → tid=0 启动子网格: <<<1, 32>>>(32, 1)
  → tid=0~63 都打印 "depth: 0"

  depth=1: Block 0, 32 个线程
    → tid=0 启动子网格: <<<1, 16>>>(16, 2)
    → tid=0~31 都打印 "depth: 1"

    depth=2: Block 0, 16 个线程
      → tid=0 启动子网格: <<<1, 8>>>(8, 3)

      depth=3: 8 个线程
        → <<<1, 4>>>(4, 4)

        depth=4: 4 个线程
          → <<<1, 2>>>(2, 5)

          depth=5: 2 个线程
            → <<<1, 1>>>(1, 6)

            depth=6: 1 个线程
              → iSize==1, return（终止）
```

每个 Block 递归 7 层（64→32→16→8→4→2→1），32 个 Block 总共启动 32×6=192 个子网格。

## 5. 同步规则

### 显式同步 vs 隐式同步

**显式同步**：父线程主动调用 `cudaDeviceSynchronize()` 等待子网格完成。

```cpp
nesthelloworld<<<1, nthread>>>(nthread, ++iDepth);
cudaDeviceSynchronize();  // 显式等待子网格完成才继续
```

**隐式同步**：父线程没调用同步，但父线程块在结束前，必须等所有子网格完成。

```cpp
nesthelloworld<<<1, nthread>>>(nthread, ++iDepth);
// 没写同步，但父线程块结束前会自动等子网格
```

### 为什么需要隐式同步

```
父线程块 Block 0:
  tid=0: 启动子网格 A  ──→  父线程执行完了... 等等！
  tid=1: 启动子网格 B  ──→  父线程执行完了...

  如果不等子网格就结束 → 子网格还在跑，父网格已经销毁 → 崩溃

  所以：父线程块的所有线程即使执行完，也要等子网格完成
```

### 对比 CPU 端的隐式同步

```
CPU 端：
  kernel<<<>>>()          ← 异步，CPU 不等
  cudaMemcpy(D2H)         ← 隐式同步，CPU 在这里等 GPU
  return 0                 ← 如果上面没有 cudaMemcpy，CPU 直接退出
                             GPU 可能还在跑 → 程序结束，GPU 被中断

GPU 端（动态并行）：
  childKernel<<<>>>()      ← 异步，父线程不等
  // 父线程块结束
  // 但隐式同步保证：等所有子网格完成 → 父线程块才真正结束
```

### 同步规则总表

| 规则 | 说明 |
|---|---|
| 子网格必须在父网格结束前结束 | 父网格隐式等待所有子网格完成 |
| 同一线程块内的子网格可以同步 | 同一父线程块启动的子网格 |
| 不同线程块的子网格不能同步 | 不同 Block 启动的子网格互相独立 |

> [!info] 线程块内的同步要求
> 如果多个线程都启动子网格，需要用 `__syncthreads()` 确保所有线程都到了启动子网格的位置，否则执行顺序不可控。

## 6. 内存模型

### 三层内存可见性

```
┌─────────────────────────────────────────────┐
│  全局内存 (Global Memory)                    │
│  常量内存 (Constant Memory)                  │
│  ┌──────────────┐    ┌──────────────┐      │
│  │  父网格       │    │  子网格       │      │
│  │              │    │              │      │
│  │ ┌─────────┐  │    │ ┌─────────┐ │      │
│  │ │共享内存  │  │    │ │共享内存  │ │      │  ← 各自私有
│  │ │(Block级)│  │    │ │(Block级)│ │      │
│  │ └─────────┘  │    │ └─────────┘ │      │
│  │ ┌─────────┐  │    │ ┌─────────┐ │      │
│  │ │局部内存 │ │    │ │局部内存  │ │      │  ← 各自私有
│  │ │(线程级)│ │    │ │(线程级) │ │      │
│  │ └─────────┘ │    │ └─────────┘ │      │
│  └──────────────┘    └──────────────┘      │
└─────────────────────────────────────────────┘
     ↑ 全局/常量内存父子共享
```

### 逐条解释

**① 父网格和子网格共享全局和常量内存**

```cpp
// 父网格写了全局内存
data[idx] = 100.0f;

// 子网格能读到（但只在子网格启动时才能保证看到）
childKernel<<<>>>(data);
// 子网格内：float v = data[idx];  ← 能读到 100.0
```

**② 父网格子网格有不同的局部内存**

局部内存（Local Memory）是线程私有的，每个线程的局部内存互相不可见。父线程的局部内存子线程看不到，反之亦然。

**③ 弱一致性**

父网格和子网格可以同时读写同一块全局内存——GPU 允许并发访问。但"弱一致性"意味着：
- 不保证父写完子才读
- 不保证子写完父立刻能看到
- 如果需要顺序保证，必须用同步

**④ 内存一致性的两个时刻**

只有在这两个时刻，父网格和子网格看到的内存内容是一致的：

```
时间 ──→

父网格:    [写入 data]
                    │
                    ▼ 子网格启动
                    │ ← 时刻1：子网格启动时，看到父网格之前的写入
                    │
子网格:              [读写 data]
                    │
                    ▼ 子网格结束
                    │ ← 时刻2：子网格结束时，父网格能看到子网格的写入
                    │
父网格:    [读取 data]  ← 能看到子网格的修改
```

在这两个时刻之外（比如子网格正在跑的时候），父网格读全局内存不保证能看到子网格的最新写入。

**⑤ 共享内存和局部内存是私有的**

- 共享内存 → Block 级私有（父 Block 和子 Block 各自独立，互不可见）
- 局部内存 → 线程级私有（父线程和子线程各自独立，互不可见）

**⑥ 局部内存对线程私有，对外不可见**

局部内存虽然物理上在全局显存里，但逻辑上只有该线程能访问，其他线程（包括同 Block 的）看不到。

### 总结对比

| 内存类型 | 父子共享？ | 一致性保证 |
|---|---|---|
| 全局内存 | 共享 | 子网格启动时 + 结束时 |
| 常量内存 | 共享 | 子网格启动时 |
| 共享内存 | 各自私有 | — |
| 局部内存 | 各自私有 | — |

## 7. 动态并行的利与弊

| 优点 | 缺点 |
|---|---|
| 运行时动态决定启动多少线程，适应负载 | 增加代码复杂度 |
| 减少主机-设备数据传输（不用来回拷数据） | 有启动开销，嵌套递归可能比循环慢 |
| 让复杂的递归算法更自然地表达 | 支持的设备有最低算力要求 |

> [!tip] 什么时候用动态并行
> 递归如果能转成循环就转成循环（如归约）。动态并行适合需要运行时动态决策的场景，如自适应细分、不规则的递归数据结构。
