# 322. 零钱兑换

题目：[LeetCode 322](https://leetcode.cn/problems/coin-change/description/)

源码：[322.零钱兑换.cpp](https://github.com/awaken-psy/leetcode/blob/main/hot100/动态规划/322.零钱兑换.cpp)

## 题面

给定硬币面额数组 `coins` 和目标金额 `amount`，每种硬币可以无限次使用。求凑出目标金额所需的最少硬币数，无法凑出则返回 `-1`。

- `coins = [1,2,5]`，`amount = 11` → `3`，即 `5+5+1`。
- `coins = [2]`，`amount = 3` → `-1`。
- `coins = [1]`，`amount = 0` → `0`。

范围：`1 <= coins.length <= 12`，`1 <= coins[i] <= 2³¹ - 1`，`0 <= amount <= 10000`。

## 核心思路

**`dp[i]`：凑出金额 `i` 所需的最少硬币数。** 和「完全平方数」一样，枚举最后使用的那枚硬币，设它的面额为 `coin`：

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
条件：coin <= i，且金额 i - coin 能够凑出
```

初始化 `dp[0] = 0`，其他状态设为 `INT_MAX`，表示不可达。金额从小到大计算，前面的状态可以已经使用过同种硬币，因此允许重复选取。

最终 `dp[amount]` 仍为 `INT_MAX` 时返回 `-1`，否则返回它的值。

### 与完全平方数的关键区别：不保证有解

完全平方数中始终可以用若干个 1 凑出目标；硬币字典里可能没有 1，例如 `[2]` 无法凑出 3。

所以转移前必须检查 `dp[i - coin] != INT_MAX`：不仅要排除不可达状态，也要避免计算 `INT_MAX + 1` 导致有符号整数溢出。`INT_MAX` 来自头文件 `<climits>`。

**也不能总是先选最大面额。** `[1,3,4]` 凑 6，贪心会选 `4+1+1`，而最优是 `3+3`，只需 2 枚。

## C++ 题解

```cpp
#include <algorithm>
#include <climits>
#include <vector>

class Solution {
public:
    int coinChange(std::vector<int>& coins, int amount) {
        int n = coins.size();
        std::vector<int> dp(amount + 1, INT_MAX);
        dp[0] = 0;

        for (int i = 1; i <= amount; ++i) {
            for (int j = 0; j < n; ++j) {
                // 硬币不能超过当前金额，剩余金额也必须可达。
                if (coins[j] <= i && dp[i - coins[j]] != INT_MAX) {
                    dp[i] = std::min(dp[i], dp[i - coins[j]] + 1);
                }
            }
        }
        return dp[amount] == INT_MAX ? -1 : dp[amount];
    }
};
```

**复杂度：时间 `O(amount × n)`，额外空间 `O(amount)`。** `n` 为硬币面额的数量。
