## 1.磁盘
### 1.1 磁盘结构

#### 1.1.1 物理结构

![](<Attachments/Pasted image 20261106115622.png>)

| 原文                                | 翻译              | 作用               |
| --------------------------------- | --------------- | ---------------- |
| Platters                          | 盘片              | 保存数据的圆盘          |
| Spindle                           | 主轴              | 带动盘片旋转           |
| Arm                               | 磁臂              | 带动末端的读写磁头移动      |
| Actuator                          | 执行器，也可理解为磁臂驱动机构 | 控制磁臂的位置          |
| SCSI connector                    | SCSI 接口         | 与计算机连接、传输命令和数据   |
| Electronics                       | 电子电路，包括处理器和存储器  | 控制硬盘工作           |

#### 1.1.2 几何结构

![](<Attachments/Pasted image 20261106120016.png>)
1. 磁盘由若干个盘片（platter）组成，每个盘片有两个盘面（surface）。
2. 每个盘面包含许多同心圆环，称为磁道（track）。
3. 每条磁道包含若干扇区（sector），扇区之间由间隙（gap）分隔。

![709](<Attachments/Pasted image 20261106120106.png>)
- 上下对齐的磁道组成一个柱面
- 多个磁头安装在联动的磁臂组件上。当磁臂移动到某个径向位置时，各个磁头就位于同一柱面的不同磁道上。

### 1.2 磁盘容量

| 原文                        | 翻译   | 含义                 |
| ------------------------- | ---- | ------------------ |
| Recording density，bits/in | 记录密度 | 沿磁道长度方向，1 英寸能放多少位  |
| Track density，tracks/in   | 磁道密度 | 沿半径方向，1 英寸能排列多少条磁道 |
| Areal density，bits/in²    | 面密度  | 记录密度与磁道密度的乘积       |

#### 1.2.1 记录区
![](<Attachments/Pasted image 20261106120718.png>)

相邻的一批磁道归为一组，称为记录区（recording zones），形状是一个完整环带。

1. 同一个记录区内，每条磁道具有相同的扇区数
2. 不同记录区，每条磁道的扇区数不同。
3. 外侧记录区每条磁道的扇区数，比内侧记录区更多，因此外圈的顺序数据传输率可以更高。
4. 因此，计算容量时，使用**平均每磁道扇区数**。

$$
\text{容量}=\text{每扇区字节数}\times\text{平均每磁道扇区数}\times\text{每盘面磁道数}\times\text{每盘片盘面数}\times\text{每个硬盘盘片数}
$$
#### 1.2.2 分区记录的深层理解

- 磁头记录一位数据，需要为它分配一段时间，频率由记录时钟规定，可以调整。
$$
\boxed{\text{一位的物理长度}=\text{线速度}\times\text{每位记录时间}}
$$
- 同一记录区内：记录频率保持不变，位长度与周长按相同比例增加，所以每道扇区数不增加。
- 跨入外侧记录区：硬盘提高记录频率

### 1.3 磁盘operation
![635](<Attachments/Pasted image 20261107042305.png>) ![375](<Attachments/Pasted image 20261107042319.png>)
1. 盘面以固定的转速旋转。
2. 读写磁头连接在磁臂末端，依靠一层薄薄的空气垫，悬浮在盘面上方。
3. 磁臂通过径向移动，可以把磁头定位到任意磁道上方（多个盘面的磁头是一起的）。

- 多个磁头同步移动，**不能据此把读写带宽直接乘以磁头数量**
- 读取一个小扇区所花的时间，通常远小于机械定位时间。

### 1.4 磁盘访问时间
![797](<Attachments/Pasted image 20261107050405.png>)
$$
\boxed{
T_{\text{red}}
=
T_{\text{seek}}
+
T_{\text{rotation}}
+
T_{\text{transfer}}
}
$$

- 虽然寻道过程中盘片也在转，但公式里的旋转延迟，是**寻道完成之后还需要等待的时间**。
- 访问时间主要由寻道时间和旋转延迟决定。
- 平均访问时间（简化模型，实际还可能包含排队等开销）

$
\boxed{
T_{\text{access}}
=
T_{\text{avg seek}}
+
T_{\text{avg rotation}}
+
T_{\text{avg transfer}}
}
$$

### 1.5 逻辑磁盘块

- 现代磁盘为复杂的扇区几何结构提供了一个更简单的抽象视图：把可用扇区看成一串固定大小为 $b$ 的逻辑块。
- 逻辑块与实际物理扇区之间的映射，由称为**磁盘控制器**的硬件维护。
- 控制器把逻辑块请求转换成：（盘面，磁道，扇区）
- 这种方式允许控制器为各个记录区保留备用柱面
	- 例如1000个block，只提供980个逻辑块，20个备用，防止坏块。

### 1.6 读取磁盘扇区
![823](<Attachments/Pasted image 20261107060820.png>)

1. CPU 通过向磁盘控制器关联的端口，也就是某个地址，写入命令、逻辑块号和目标内存地址，发起磁盘读取
	- ![](<Attachments/Pasted image 20261107061316.png>)
2. 磁盘控制器读取扇区，并执行直接内存访问(direct memory access)，即 DMA，将数据传输到主存。
	- ![663](<Attachments/Pasted image 20261107061415.png>)
3. DMA 传输完成时，磁盘控制器通过中断通知 CPU。在图示模型中，就是向 CPU 的一个专门中断引脚发出信号。
	- ![894](<Attachments/Pasted image 20261107061539.png>)

- 这个流程允许 CPU 在设备处理请求期间执行其他工作，再通过完成通知处理结果。

### 1.7 固态硬盘(SSD)
![](<Attachments/Pasted image 20261107061817.png>)
- SSD 内部有闪存转换层，负责把外部逻辑地址映射到内部闪存位置。
- 页大小：512 B - 4 KB；每块包含 32 - 128 页。
- 数据以页为单位读写，所属块被擦除之后，其中的页才能被写入。
- 一个块经历约 100,000 次重复写入后会磨损。

| 名称        | 作用             | 示例             |
| --------- | -------------- | -------------- |
| 逻辑块       | 主机向设备发请求时使用的单位 | 512 B          |
| 闪存页 Page  | 闪存读写、编程的单位     | 4 KiB          |
| 闪存块 Block | 闪存擦除的单位，包含多页   | 64 页，即 256 KiB |

#### 1.7.1 SSD 的性能特征

| 指标       |   读取（示例） |       写入 |
| -------- | -------: | -------: |
| 顺序访问吞吐量  | 550 MB/s | 470 MB/s |
| 随机访问吞吐量  | 365 MB/s | 303 MB/s |
| 平均顺序访问时间 |    50 μs |    60 μs |

- 随机写入会慢一些：
	- 擦除一个块需要较长时间，约 1 ms。
	- 修改一个块中的某一页，需要将其他页复制到新块。
- SSD 没有磁臂，消除了机械寻道和旋转等待，但仍有控制器、闪存读写、地址映射等工作。连续请求更有利于合并、组织和并行处理这些工作。

#### 1.7.2 如何修改一页

假设某个旧块保存：
~~~text
旧块 X：[甲][乙旧][丙][丁]
~~~

现在要修改“乙”：
1. 找到 Y 块里的一个空闲页，把“乙新”写进去。
2. 更新 FTL 映射，并把“乙旧”标为失效。
3. 以后需要回收旧块 X 时，把仍有效的甲、丙、丁迁移出去。
4. 擦除整个旧块 X，让它重新成为可用空间。

更新之后：
~~~text
旧块 X：[甲][乙旧，失效][丙][丁]
新块 Y：[乙新][空][空][空]
~~~

#### 1.7.3 SSD vs 机械硬盘

- 优点：没有运动部件，因此速度更快、功耗更低，也更耐受机械冲击。
- 缺点：存在磨损耗尽的可能，可以通过 FTL 中的“磨损均衡逻辑”缓解。
	- FTL 可以改变逻辑地址与物理位置的对应关系，把写入分散到不同物理块，让磨损更均匀。
- 价格：SSD 约为 HDD 的约 3.1 - 3.6 倍。

## 2.局部性

- 不能只指望所有存储设备都追上 CPU 的速度，程序的访问却通常有规律：短时间内，常常反复访问一部分数据和指令，也常访问彼此邻近的位置。
	- 空间局部性（Spatial locality）：地址彼此邻近的内容，往往会在相近的时间内被引用。
	- 时间局部性（Temporal locality）：最近被引用过的内容，很可能在不久之后再次被引用。

~~~c
sum = 0;
for (i = 0; i < n; i++)
    sum += a[i];
return sum;
~~~

| 引用对象      | 局部性类型 | 原因                    |
| --------- | ----- | --------------------- |
| 数据：数组元素   | 空间局部性 | a[0]、a[1]、a[2]……的地址连续 |
| 数据：变量 sum | 时间局部性 | 同一个变量反复被使用            |
| 指令：顺序执行   | 空间局部性 | 顺序执行的指令通常位于邻近地址       |
| 指令：循环执行   | 时间局部性 | 同一段循环指令被多次使用          |

- 编译器优化后，sum 很可能一直保存在寄存器中，所以不能据此推断每次迭代都会重新访问主存。

## 3.存储层次结构

### 3.1 软件和硬件的互补性质

1. 快速存储技术的每字节成本更高、容量更小，并且需要更多电力，也会产生更多热量。
2. CPU 与主存之间的速度差距在扩大。
3. 编写良好的程序通常具有良好的局部性。

- 硬件：高速存储昂贵、容量有限，因此需要与容量更大、单位成本更低的存储共同使用。
- 软件：一个程序即使使用很大的数据空间，在一段较短时间内，也经常集中访问其中一部分数据和指令。
- 把两者结合起来，就可以让较快的小容量存储保存近期活跃内容的副本，让较慢的大容量存储提供更大的数据空间。

| 所在层次 | 主要特点            | 承担的作用        |
| ---- | --------------- | ------------ |
| 较上层  | 更快、容量较小、每字节成本较高 | 保存近期活跃的数据与指令 |
| 较下层  | 更慢、容量较大、每字节成本较低 | 提供更大的存储空间    |

### 3.2 缓存（cache）

- 缓存（Cache）：一种容量较小、速度较快的存储设备，用来暂存较大、较慢设备中一部分数据。
- 缓存是一个角色，某个较快的位置，只要暂存较慢位置的一部分内容，就可以承担缓存的作用。后面的例子还包括文件缓存、浏览器缓存等。
- 平均访问时间：
$$
\text{平均访问时间}=\text{命中时间}+\text{不命中率}\times\text{额外不命中代价}
$$
#### 3.2.1 缓存不命中

1. 程序需要块 b 中的数据。
2. 块 b 不在缓存中：不命中，Miss。
3. 从下层内存取回块 b，并把块 b 存入缓存。
4. 放置策略决定 b 放在哪里；替换策略决定哪个已有块被驱逐，即 victim，牺牲块。

| 策略    | 回答的问题               |
| ----- | ------------------- |
| 放置策略  | 新块允许放在哪些位置？         |
| 替换策略  | 允许的位置被占满时，换掉哪一个已有块？ |

#### 3.2.2 三类缓存不命中

- 冷不命中(Cold miss)：缓存初始为空时，会发生冷不命中。
- 冲突不命中(Conflict miss)：即使缓存总容量足够，多个数据对象映射到相同位置，也会发生冲突不命中。
- 容量不命中(Capacity miss)：活跃缓存块的集合，也称工作集，超过缓存容量时，会发生容量不命中。

| 类型    | 主要原因            | 思考方向          |
| ----- | --------------- | ------------- |
| 冷不命中  | 某块还没有被带入过       | 首次访问的代价       |
| 冲突不命中 | 可用位置受限，多个块争同一位置 | 放置规则、相联度与地址布局 |
| 容量不命中 | 活跃工作集超过容量       | 缓存容量与工作集大小    |

#### 3.2.3 缓存结构

| 缓存类型 | 缓存什么 | 存放位置 | 延迟（周期） | 管理者 |
|---|---|---|---:|---|
| 寄存器 | 4–8 字节的字 | CPU 核心 | 0 | 编译器 |
| TLB | 地址翻译结果 | 片上 TLB | 0 | 硬件 MMU |
| L1 缓存 | 64 字节块 | 片上 L1 | 4 | 硬件 |
| L2 缓存 | 64 字节块 | 片上 L2 | 10 | 硬件 |
| 虚拟内存 | 4 KB 页 | 主存 | 100 | 硬件与操作系统 |
| 缓冲区缓存 Buffer cache | 文件的部分内容 | 主存 | 100 | 操作系统 |
| 磁盘缓存 Disk cache | 磁盘扇区 | 磁盘控制器 | 100,000 | 磁盘固件 |
| 网络文件缓冲缓存 | 文件的部分内容 | 本地磁盘 | 10,000,000 | NFS 客户端 |
| 浏览器缓存 | Web 页面 | 本地磁盘 | 10,000,000 | 浏览器 |
| Web 缓存 | Web 页面 | 远程服务器磁盘 | 1,000,000,000 | Web 代理服务器 |

#### 3.3.2 读取DRAM
![](<Attachments/Pasted image 20261107143937.png>)
![](<Attachments/Pasted image 20261107144116.png>)

- 步骤 1：行地址选通信号 RAS，选择第 2 行。把第 2 行从 DRAM 阵列复制到行缓冲器。
- 步骤 2：列地址选通信号 CAS，选择第 1 列。把超单元（2,1）从缓冲器送到数据线，最终返回 CPU。

#### 3.3.3 内存模块
![](<Attachments/Pasted image 20261107144722.png>)
- 一个 64 MB 内存模块，由 8 片 8M×8 的 DRAM 芯片组成。
- 地址指定行 i、列 j；每片芯片输出对应超单元（i,j）的 8 位，
- 同一组行列地址送到 8 片芯片，各片同时选中自己的（i,j），分别提供整个 64 位数据中的 8 位，组合成一个 64 位字。

#### 3.3.4 改进型DRAM

- SDRAM(同步 DRAM)：
	- 使用常规时钟信号，而不是异步控制，按时钟节拍工作，可以更有组织地安排命令和连续传输。
	- 可以复用已经选定的行地址，例如 RAS、CAS、CAS、CAS，先选行，再多次选列。
- DDR SDRAM(双倍数据率同步 DRAM)：
	- 使用上升沿和下降沿传送数据。
	- 不同代际具有不同大小的内部预取结构：DDR 为 2 位，DDR2 为 4 位，DDR3 为 8 位。
		- 预取：把一次读取需要的一批数据，从 DRAM 内核并行取到内部缓冲，再由数据引脚分多次送出去。
		- 以DDR3为例，一次内部预取8n位，n 表示芯片对外的数据位宽（以n=8为例，芯片有 8 条数据线）
			- DDR3 采用 8n 预取，因此一次内部准备 64 位，每个时钟边沿一起传送 8 位，4个时钟周期发送完毕
