# 第一章 引论

> 编译原理总览：编译是什么、分几步、每步进出什么、跟解释有何不同。
> 上游：00-总览 · 关联：[[学习笔记/计算机基础/编译原理/02-高级语言及其语法描述.md|第二章 高级语言及其语法描述]] · [[学习笔记/计算机基础/编译原理/03-词法分析.md|第三章 词法分析]]

## 0. 一句话定位

**编译程序** = 把某种语言（源语言）的程序翻译成**逻辑等价**的另一种语言（目标语言）程序的**转换系统**。

> [!tip] 一句话记死编译 vs 解释
> **编译产出"程序"，解释产出"结果"。** 类比：编译是**全文翻译**（翻完再读），解释是**同声传译**（边翻边说）。

---

## 1. 编译 vs 解释（高频考点）

|  | 功能 | 工作结果 | 实现技术上 | 代表语言 |
|---|---|---|---|---|
| **编译程序** | 源程序的**转换系统** | 源程序的**目标代码** | 把中间代码**转换成**目标程序 | Pascal / Fortran / C |
| **解释程序** | 源程序的**执行系统** | 源程序的**执行结果** | **执行**中间代码 | Basic / Prolog |

- 解释：逐句分析执行，**不产生目标程序**；优点易查错，缺点效率低。
- 编译：整个程序翻译后再执行；优点只需分析翻译一次，缺点运行时错误要查整个程序。

> [!question] 编译结果一定是机器代码吗？Java 算编译还是解释？
> 不一定。编译结果可以是**中间代码文件**（如 `.class`），只要机器（含虚拟机）能运行即可。
> **Java 是半编译半解释**：源码 → 编译成字节码 → JVM 解释执行。初衷是**跨平台**而非效率。

## 2. 编译五阶段 —— 每阶段的输入/输出/规则/工具（最爱考）

> [!abstract] 英译类比（记忆抓手）
> 识别单词 → 分析语法 → 初步翻译 → 译文修饰 → 写出译文，正对应：
> **词法 → 语法 → 语义+中间代码 → 优化 → 目标代码**

| 阶段 | 输入 | 输出 | 依循规则 | 描述工具 / 方法 |
|---|---|---|---|---|
| ① **词法分析**（扫描程序） | 字符流 | **单词符号 / TOKEN** | 词法规则 | **正规式、有限自动机**（DFA / NFA / 状态图） |
| ② **语法分析**（识别程序） | 单词符号 | **语法树** | 语法规则 | **上下文无关文法**；递归下降 / LR / 算符优先 |
| ③ **语义分析 + 中间代码生成** | 语法树（句子） | **中间代码序列** | 语义规则 | 语法制导翻译、DAG；**四元式 / 三元式 / 逆波兰** |
| ④ **优化** | 中间代码 | 更高效的中间代码 | **等价变换**规则 | 公共子表达式提取、循环优化、删除无用代码 |
| ⑤ **目标代码生成** | 中间代码（或优化后） | **目标代码** | 硬件结构 / 指令含义 | 寄存器分配 |

> [!info] 语义分析的两大任务
> 1. **静态语义检查**：类型审查、变量是否定义、算符是否符合规范；
> 2. 翻译成**中间代码**（为了后续优化与跨平台）。

### 四元式

形式：`(算符, 运算对象1, 运算对象2, 结果)`；**用不到的槽位填 `-`**。

> [!info] 符号约定（先对上号）
> - `id1`/`id2`/`id3` 是名字在**符号表里的内部编号**：id1=sum、id2=first、id3=count。
> - `t1`/`t2`/`t3` 是**临时变量**，存中间结果。

**例** `sum := first + count * 10`（设 sum/first/count 都是 real，10 是整型常量）：

```text
(1) (inttoreal, 10,  -,   t1)   // 整型 10 → 实数 t1=10.0（一元操作，第二槽填 -）
(2) (*,         id3, t1,  t2)   // count * 10.0 → t2
(3) (+,         id2, t2,  t3)   // first + t2 → t3
(4) (:=,        t3,  -,   id1)  // sum := t3（赋值只需一个源，第二槽填 -）
```

> [!question] inttoreal 这步哪来的？
> **语义分析**的类型检查。`count` 是 real、`10` 是 int，`count*10` 类型不一致 → 编译器自动插入 `inttoreal` 把 10 转成实数（隐式类型转换），对应 slide 19–20 的 inttoreal 语义处理节点。
> 运算顺序仍是**先乘后加、最后赋值**，等价于三地址码：`t1=(real)10; t2=count*t1; t3=first+t2; sum=t3`。

> [!warning] 目标代码三种形式（别记混）
> | 形式 | 后续处理 |
> |---|---|
> | **汇编指令代码** | 需要**汇编** |
> | **绝对指令代码** | 可**直接运行** |
> | **可重新定位指令代码** | 需要**连接** |

## 3. 一遍 vs 多遍

**遍（Pass）**：对源程序或其中间结果**从头到尾扫描一次**并做相关处理的过程。每遍从外存读入前一遍的中间结果，完成后把结果写回外存。

|  | 内存 | 时间 |
|---|---|---|
| **多遍编译** | 少占 | 多耗 |
| **一遍编译** | 多占 | 少耗 |

> [!tip] 一遍编译里谁是核心
> **语法分析器处于核心地位**，词法分析常作为它的子程序被按需调用。

> [!danger] "遍" ≠ "阶段"（极易混淆）
> - **遍**是**物理**概念（一次完整的扫描周期）；
> - **阶段**是**逻辑**概念（编译的功能划分）。
> - 关系：**一个阶段可分多遍，一遍也可包含多个阶段**。比如一遍编译就把五个逻辑阶段合在一遍里做完。

## 4. 编译程序结构（补充必考点）

### 贯穿全程的两项工作

- **表格管理**：其中**符号表最重要**——记录源程序中名字（标识符）的类型、作用域、存储分配信息。
- **出错处理**：
  - **语法错误**：在词法 / 语法分析阶段查出（如括号不配对、保留字拼错）；
  - **语义错误**：部分编译时查出（标识符未说明就用、形实参数不一致），部分**运行时**才查出（下标越界、运算溢出）。

> [!abstract] 好编译程序的三个要求
> **全**（最大限度发现错误）· **准**（准确指出性质和地点）· **局部化**（把错误影响限制在尽可能小的范围）。

### 前端 / 后端

| | 包含 | 关注 |
|---|---|---|
| **前端** | 词法 + 语法 + 语义 + 中间代码生成 + 机器无关优化 | 主要与**源语言**有关 |
| **后端** | 目标代码生成 + 机器相关优化 | 主要与**目标机**有关 |

> [!question] 为什么分成前端后端？
> **复用**：前端换目标机不用改（跨平台），后端换源语言不用改（跨语言）；也便于移植和团队分工。

### 编译程序的生成技术

自编译 · 交叉编译 · **自展** · 移植 · 自动生成（LEX / YACC）。

> [!tip] 自展 = 滚雪球
> 先定核心语言 L0，用汇编实现其编译程序 T0；把 L0 扩充为 L1，**用 L0 写 L1 的编译程序 T1**（自编译）；再扩充到 L2……层层扩展直到目标语言。每一层都用上一层语言来写本层编译程序。

## ✅ 自测题（先自己想，再展开答案）

> [!question]- Q1. 编译程序和解释程序在「工作结果」和「实现技术」上有何区别？各举一种代表语言。
> - **工作结果**：编译→源程序的**目标代码**；解释→源程序的**执行结果**。
> - **实现技术**：编译→把中间代码**转换成**目标程序；解释→**执行**中间代码。
> - 语言：编译如 **C / Pascal / Fortran**；解释如 **Basic / Prolog**。

> [!question]- Q2. 写出编译的五个阶段；并写出词法分析、语法分析、语义分析与中间代码生成三者的输入和输出。
> 五阶段：**词法分析 → 语法分析 → 语义分析与中间代码生成 → 优化 → 目标代码生成**。
> - 词法：输入**字符流**，输出**单词符号 (TOKEN)**；
> - 语法：输入**单词符号**，输出**语法树**；
> - 语义分析与中间代码生成：输入**语法树（句子）**，输出**中间代码序列**。

> [!question]- Q3. 词法分析、语法分析分别依循什么规则？用什么工具/文法描述？
> - **词法分析**依循**词法规则**，用**正规式 + 有限自动机**（DFA/NFA/状态图）描述；
> - **语法分析**依循**语法规则**，用**上下文无关文法**描述，方法有递归下降、LR、算符优先。

> [!question]- Q4. 写出四元式的一般形式，并写出 `a := b + c * d` 的四元式序列。
> 一般形式：`(算符, 运算对象1, 运算对象2, 结果)`。
>
> ```text
> (1) (*,  c,  d,  t1)   // 先算 c*d
> (2) (+,  b,  t1, t2)   // 再算 b+t1
> (3) (:=, t2, -,  a)    // 赋给 a（赋值无第二运算对象，填 -）
> ```

> [!question]- Q5. 目标代码有哪三种形式？各自需要什么后续处理才能运行？
> - **汇编指令代码** → 需要**汇编**；
> - **绝对指令代码** → 可**直接运行**；
> - **可重新定位指令代码** → 需要**连接**。

> [!question]- Q6. 什么是"遍"？一遍与多遍编译在时间、空间上如何权衡？"遍"和"阶段"有何区别？
> **遍**：对源程序或其中间结果**从头到尾扫描一次**并做相关处理的过程。
> - 一遍：**多占内存、少耗时间**；多遍：**少占内存、多耗时间**。
> - **遍**是**物理**概念（一次扫描周期），**阶段**是**逻辑**概念（功能划分）。**一个阶段可分多遍，一遍也可含多个阶段**。

> [!question]- Q7. 编译程序的前端和后端分别包含哪些工作？为什么要把编译程序分成前端后端？
> - **前端**：词法 + 语法 + 语义 + 中间代码生成 + 机器无关优化（主要与**源语言**有关）；
> - **后端**：目标代码生成 + 机器相关优化（主要与**目标机**有关）。
> - 分开的目的：**复用**——前端换目标机不改（跨平台），后端换源语言不改（跨语言），且利于移植与分工。
