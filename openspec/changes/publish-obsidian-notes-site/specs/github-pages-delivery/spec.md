## Purpose

把本地筛选后的笔记内容转换为可预览、可重复构建和可部署的静态网站。交付流程连接作者的日常写作与 GitHub Pages，明确本地源笔记、网站仓库和线上版本之间的边界，并为更新失败提供可核对的状态。

## ADDED Requirements

### Requirement: 本地操作连接外部笔记库与网站工程

交付流程 SHALL 接受明确的笔记库路径，支持作者完成导出、校验与本地预览。导出与构建的所有写入 SHALL 位于网站工程的生成文件范围，源笔记与附件的字节内容 SHALL 在操作前后保持一致。

#### Scenario: 从现有笔记库生成预览
- **WHEN** 作者指定 `D:\Obsidian repository\awaken`，在网站工程中运行导出及预览
- **THEN** 本地预览呈现筛选后的公开内容，源笔记及附件的字节内容与操作前一致

### Requirement: 网站仓库承载可重复构建的公开输入

网站仓库 SHALL 保存网站源文件、依赖锁文件、筛选后的内容及构建所需的公开元数据。CI SHALL 从这些输入构建完整静态产物，并验证构建输入与公开资源清单一致。

#### Scenario: 在干净环境构建
- **WHEN** CI 检出网站仓库并安装锁定依赖
- **THEN** 它能够构建与提交内容匹配的页面、索引和资源

#### Scenario: 生成目录混入额外文件
- **WHEN** 网站内容目录存在公开资源清单之外的笔记或附件
- **THEN** 校验失败并阻止此次部署

### Requirement: GitHub Pages 地址与资源路径一致

网站 SHALL 支持配置最终站点地址，并正确生成 GitHub Pages 账户首页及项目子路径中的页面地址、资源地址和内部导航。部署 SHALL 使用 GitHub Actions 完成构建、产物上传及 Pages 发布。

#### Scenario: 部署到账户首页
- **WHEN** 目标仓库为 `<owner>.github.io`，站点地址配置为 `https://<owner>.github.io`
- **THEN** 首页、笔记直达地址、搜索结果、图片和样式从该根路径正常加载

#### Scenario: 部署到项目子路径
- **WHEN** 目标站点地址配置为 `https://<owner>.github.io/<repo>`
- **THEN** 所有站内页面、导航与资源引用使用对应的项目基础路径

### Requirement: 发布受构建校验结果约束

系统 SHALL 在部署前校验公开内容范围、必要本地资源、搜索索引及站内地址。校验或构建失败 SHALL 终止该次发布并保留当前成功部署版本。发布完成 SHALL 提供部署状态与实际网站地址供作者核对。

#### Scenario: 构建或资源校验失败
- **WHEN** 提交的内容出现缺失附件、路径冲突或构建错误
- **THEN** 工作流报告失败，当前成功部署版本继续可访问

#### Scenario: 发布成功
- **WHEN** 构建及全部发布前校验通过，Pages 部署完成
- **THEN** 作者能获得成功状态和网站地址，并通过该地址检查首页、公开笔记与资源
