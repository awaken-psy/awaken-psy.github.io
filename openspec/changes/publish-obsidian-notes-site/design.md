## Context

动机及能力范围见 [proposal.md](proposal.md)。网站工程当前只有 OpenSpec 规划文件，外部笔记库包含 768 篇 Markdown。学习笔记共 462 篇，覆盖图形学、算法、计算机基础与 AI。语法扫描发现 233 篇使用双链、213 篇使用公式块、99 篇使用提示块、49 篇使用 Mermaid，另有 Markdown 图片、图片双链、共享附件及本地文件 URI。

作者已确认深色技术风、对外分享为主并兼顾自行检索，以及站名 `awaken` 和介绍“倘若重新穿越时光河流”。公开规则以 `selective-note-publishing` 规格为准。

## Goals / Non-Goals

### Goals

- 通过一个本地导出入口连接既有笔记库与公开网站工程，集中计算文件夹规则、单篇例外、链接和资源范围。
- 将公开内容集作为页面、搜索、导航和部署的共同输入，支持完整重建、失败恢复及可重复验证。
- 尽量复用 Quartz 的解析、页面生成与搜索能力，将定制集中在导出规则、首页组件和样式。

### Non-Goals

当前公开范围的验收边界覆盖本次导出的内容、当前构建产物及最新成功部署。历史 Git 提交、读者已下载副本和外部缓存的处理需要单独确定操作范围。作者通过本地 Obsidian 与 GitHub 网站仓库完成内容维护。

## Decisions

### 1. 固定 Quartz 5 的可重复版本

采用 Quartz 作为静态生成器，以官方 `v5` 默认分支当前的 `8be3806431d33b9edaafcfc34a9520333399bf1e` 提交作为首次实现基线，该提交的包版本为 `5.0.0`。使用 Node.js 24、npm 锁文件和 Quartz 插件锁文件固定构建输入。安装后先用代表性笔记完成语法、搜索和 Pages 路径验证，再添加定制页面。

核对时官方文档已面向 Quartz 5，GitHub 的 `releases/latest` 仍指向较早的 v4 发布。版本选择以已核对的源提交为准。评估发布标签入口时发现其版本信息与当前默认分支有差异，固定源提交能够明确复现所用 API 和插件接口。[官方源码包信息](https://github.com/jackyzha0/quartz/blob/8be3806431d33b9edaafcfc34a9520333399bf1e/package.json)

### 2. 外部笔记库经本地导出进入网站工程

内容来源通过命令参数或本地环境变量提供，当前路径为 `D:\Obsidian repository\awaken`。网站工程使用 `D:\project\awaken`。规划的导出入口为 `scripts/export-notes.mjs`，公开生成内容集中在 `content/`，首页和关于等作者维护页面放在独立的 `site-pages/`，集中配置放在网站工程中。

导出把作者维护页面、筛选后的笔记与所需资源合成为完整 `content/`。原笔记的相对目录得到保留。首页、关于与专题生成路径使用明确的保留名称，遇到目标路径、大小写折叠或编码规范化冲突时返回错误。

评估过从整库直接构建的方式，Quartz 对非 Markdown 附件的输出范围较宽。导出阶段先建立可公开输入，能让网站仓库和 CI 使用同一内容边界。[Quartz 公开范围说明](https://quartz.jzhao.xyz/features/private-pages)

### 3. 一处计算公开规则

使用 YAML 解析器读取 frontmatter，`publish` 只接受布尔值。显式值优先，缺省时检查相对根目录的完整路径段，首段为 `学习笔记` 时公开，其余目录隐藏。`publish` 是此工作流的公开状态入口，Quartz 的默认草稿过滤需要配置为与最终公开集一致。

完整索引在本地记录源路径、标题、别名及公开状态，随后按公开状态生成发布集。索引覆盖全库便于识别指向隐藏笔记的链接。公开清单只写入已导出路径、内容摘要及公开页面所需的日期信息。

评估过在 462 篇学习笔记中逐篇补充 `publish: true`，文件夹继承能直接利用现有目录组织，使日常设置集中于例外笔记。

### 4. 用解析后的结构处理引用

复用 Quartz 所依赖的 Markdown AST 与 Obsidian 语法解析逻辑，统一处理内联链接、引用式链接、双链、章节、块引用和嵌入。链接按明确相对路径、笔记库相对路径、唯一文件名及唯一别名依次解析，歧义在本地报错。公开目标转换为确定的站内目标并保留定位信息。代码围栏和行内代码按代码内容处理。

隐藏目标的普通链接转为纯文本。作者显式写出的标签保留，自动目标标题统一替换为“未公开笔记”。隐藏笔记的整篇、章节及块嵌入同样显示占位文本。公开嵌入交由 Quartz 呈现，循环引用采用有限的普通链接回退。

缺失的普通笔记目标转为纯文本并记录本地告警。必要图片或嵌入内容缺失会阻止导出。`file://`、`obsidian://` 与 Windows 本机文件链接转为保留标签的纯文本，链接目标写入本地诊断。实际抽样发现的本机源码链接可通过这条规则呈现为可读文件名。

原始 HTML 通过 HTML AST 检查本地链接和资源属性，SVG 及 HTML 附件继续收集必要的本地依赖。文本附件中的笔记链接和嵌入应用同一公开规则。资源读取前对规范化实际路径做根目录边界检查，依赖遍历使用已访问集合。常规 HTTP、HTTPS 等外部链接沿用作者原有地址。

评估过仅用文本正则替换的方式，代码示例、引用式链接、中文编码和嵌套内容需要结构信息，因此采用现有解析器进行处理。

### 5. 附件采用引用闭包，输出采用完整替换

从公开笔记的有效引用开始收集图片、SVG、PDF、HTML 等本地附件，继续遍历资源的必要本地依赖。普通笔记链接仅建立导航，内容嵌入按目标公开状态处理。位于任意目录的普通附件以公开引用关系决定是否导出，共享资源按实际路径去重。

每次导出持有输出锁，在工程内临时目录生成完整内容和公开清单。读取源文件时记录摘要，发布替换前复核本轮依赖的文件、索引所需元数据及目录枚举结果。临时内容校验成功后替换旧生成目录，替换失败恢复上一目录。本地诊断、缓存与锁文件集中在被 Git 忽略的工程工作目录中。

CI 对生成目录与公开清单进行精确比对，检查额外文件、资源摘要和显式隐藏属性。全库隐藏目标审计在持有源库的本地导出阶段完成。合成笔记库中的隐藏内容标记用于回归验证公开文件、索引和最终产物。

评估过只增量复制变动文件，完整替换更容易覆盖“公开改隐藏”、删除和失去引用的附件清理。当前附件体积约 24.5 MB，完整重建适合初版规模。

### 6. 首页分享入口与笔记检索共享公开元数据

首页使用 `awaken` 与完整原句“倘若重新穿越时光河流”。依次呈现介绍、四类笔记入口、专题、精选和最近更新。图形学分类映射 `学习笔记/cg/`，其他三类映射现有同名目录及 `学习笔记/ai/`。专题由可配置目录映射生成，初始入口采用 CUDA、LearnOpenGL 和 GAMES202，目录内存在公开笔记时展示。

精选由配置中的源相对路径列表控制，最多六篇，初始允许空列表。最近更新显示五篇，使用规格规定的日期优先级。导出时将用于排序的有效源日期记录到公开元数据，防止 CI 检出时间改变排序。单篇公开例外进入目录与搜索，首页主要分类仍围绕四个学习方向组织。

笔记标题按 frontmatter、首个一级标题、文件名的顺序提取。保留现有别名与标签供链接和检索使用。搜索采用 Quartz 的中文全文检索入口，验收包括“线程层级”及 `cudaDeviceReset`。[Quartz 搜索说明](https://quartz.jzhao.xyz/features/full-text-search)

首页将分享入口置于主要位置，文章页采用桌面分类导航、正文和章节目录，手机端将辅助目录收进可操作菜单。评估过将全库文件树直接作为首页，专题与分类入口更贴合对外分享的主用途，文件树承担文章页的连续浏览。

### 7. 深色视觉采用集中主题变量

初始色值采用页面 `#0D1117`、面板 `#161B22`、正文 `#E6EDF3`、强调色 `#58A6FF`。这些数值是实现建议，作者已确认的是深色技术风。中文正文使用清晰的系统字体栈，代码使用等宽字体栈。分类入口与笔记列表复用少量组件，响应式布局分别验证 360px、768px 和 1440px。

交互状态通过文字、图标和可见焦点共同表达，正文对比度达到规格门槛。宽代码和表格在自身区域滚动，图表按内容区域缩放。评估过逐页面独立配色，集中主题变量便于统一调整阅读层级和对比度。

### 8. 本地筛选，CI 构建，GitHub Pages 交付

日常流程为运行本地导出、检查预览、提交筛选后的变化，再由 GitHub Actions 执行依赖安装、输入清单校验、静态构建、资源与索引校验、Pages 产物上传和部署。工作流只需要网站仓库提供的公开输入。部署任务与前置校验保持依赖关系，同一 Pages 环境串行部署。

优先配置账户首页 `https://<owner>.github.io`，目标仓库为 `<owner>.github.io`。通过统一站点地址参数同时支持项目子路径，用根路径和非空基础路径进行链接回归。实际 GitHub 用户名与目标仓库作为部署输入。[GitHub Pages 站点类型](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

评估过在远程 CI 直接读取完整笔记库，本地筛选能减少远程构建的数据访问范围，并让作者在提交前检查生成结果。Pages 构建和部署参照 Quartz 官方流程，在固定版本上核对工作流配置。[Quartz 托管说明](https://quartz.jzhao.xyz/hosting)

### 9. 四篇公式问题在导出副本中定向修正

实施核对发现四篇笔记存在公式分隔符与列表缩进问题，作者明确授权修正网站导出副本。通过 `site.content-fixes.mjs` 为四个公开源路径提供局部转换，导出报告记录应用情况，源文件摘要仍以原始字节校验。引用之外的 Markdown 采用原始文字与位置替换，避免整篇序列化改变公式、缩进或代码。公式修正用原有 KaTeX 渲染器与对应源片段验证。

目标仓库经连接账户核对后确认为 `awaken-psy/awaken-psy.github.io`，当前默认分支为 `master`，发布工作流跟随该分支配置。

## Risks / Trade-offs

- 既有短名称、别名或规范化路径存在歧义。通过本地全库索引和显式错误定位需要修正的引用。
- 隐藏笔记的链接和嵌入可能进入搜索或其他元数据。以筛选后的 AST 和内容集生成全部公开派生数据，并用独有标记验证最终产物。
- 公开文章引用共享目录中的附件。资源边界按实际公开引用关系确定，作者可从本地导出摘要核对将要公开的资源。
- 历史公开版本可能继续存在于 Git 历史与外部缓存。验收与撤回操作明确以新发布成功后的当前版本为边界。
- Quartz 文档、GitHub Release 和插件接口可能处于不同版本。固定已核对的核心提交与插件锁文件，在样例验收通过后构建定制页面。

## Migration Plan

1. 在网站工程引入固定的 Quartz 基线，建立与之匹配的工具链和插件锁文件，完成代表性笔记的最小构建。
2. 使用合成笔记库验证目录默认、单篇覆盖、链接、附件和撤回，再对实际源库执行本地导出及渲染核对。
3. 实现首页、分类专题、搜索和深色阅读布局，检查三个视口及根路径、项目基础路径两组构建。
4. 配置作者的 GitHub 用户名、目标仓库及最终站点地址，提交已核对的公开输入，观察 Pages 成功状态并检查实际地址。
5. 发布失败时检查工作流错误并修复后重试。需要回退时选择符合当前公开规则的既有代码版本，重新导出当前允许公开的内容后部署。
